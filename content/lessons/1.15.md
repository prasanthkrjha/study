# Greedy Algorithms

A greedy algorithm makes the locally optimal choice at every step — the choice that looks best right now — without ever reconsidering or backtracking. When it works, it produces the globally optimal solution with remarkable simplicity: no DP table, no recursion tree, just a single pass through the input (often after sorting). When it doesn't work, it confidently produces a wrong answer, which is why "can I use greedy here?" is a question that deserves a proof, not just intuition.

The reason greedy works for some problems and fails for others comes down to one structural property: **the greedy choice must be safe**, meaning that making the locally optimal choice now never closes off a globally optimal solution. If you can always swap a non-greedy choice for the greedy one without worsening the solution (this is the "exchange argument"), then greedy is provably optimal. If you can find even one counter-example where the greedy choice forces a suboptimal outcome, you need dynamic programming or backtracking instead.

Understanding when greedy applies — and being able to articulate why in an interview — is more valuable than memorizing specific greedy algorithms. The activity selection problem (sort by end time, take greedily) is the canonical teaching example: it has a clean exchange argument proof, and that same proof structure recurs across dozens of interval and scheduling problems. The difference between a candidate who says "I think sorting by end time works" and one who can say "sorting by end time is optimal because any other first choice can be swapped for the earliest-ending interval without reducing the count" is the difference between guessing and knowing.

## Theory & Fundamentals

### What makes a problem greedy-solvable?

Two properties must hold:
1. **Greedy choice property:** There exists a globally optimal solution that makes the greedy choice at the first step. Equivalently, the greedy choice can always be incorporated into an optimal solution.
2. **Optimal substructure:** After making the greedy choice, the remaining problem has the same structure, and its optimal solution combines with the greedy choice to form the global optimum.

Both DP and greedy exploit optimal substructure. The difference: DP considers all sub-choices and picks the best; greedy commits to one choice without exploring alternatives. Greedy is more efficient (O(n log n) or O(n) vs polynomial DP) but only correct when the greedy choice property holds.

### The exchange argument proof technique

The exchange argument is the standard way to prove a greedy strategy correct:
1. Assume there is an optimal solution O that does **not** follow the greedy rule at some step.
2. Identify where O first diverges from the greedy solution G.
3. "Exchange" the non-greedy choice in O for the greedy choice.
4. Show that the modified O' is at least as good as O (not worse).
5. Conclude: since any optimal solution can be converted to the greedy solution without losing quality, the greedy solution is also optimal.

For activity selection: if O's first selected interval is not the earliest-finishing one, swap it for the earliest-finishing interval. Since it finishes no later, every subsequent interval in O remains compatible. O' is equally valid, no smaller. Therefore, always picking the earliest-finishing interval is safe.

### Greedy vs. DP decision guide

| Signal | Algorithm |
|---|---|
| One locally optimal choice that's always safe | Greedy |
| Choices interact — one choice affects future options non-monotonically | DP |
| Need all valid configurations | Backtracking |
| Problem: maximize non-overlapping intervals | Greedy (sort by end) |
| Problem: 0/1 knapsack | DP (greedy fails — see below) |
| Problem: coin change (standard denominations, e.g. US coins) | Greedy sometimes works |
| Problem: coin change (arbitrary denominations) | DP always works |

### Classic greedy failure: 0/1 knapsack

Items: weights [3, 4, 5], values [4, 5, 6], capacity 7.
Greedy (best value/weight ratio first): ratio = [1.33, 1.25, 1.2] → pick weight 3 (value 4), then weight 4 (value 5) → total value 9.
Optimal: pick weight 3 + weight 4 = weight 7, value 9. Hmm — same here, but with weights [3, 4, 5], values [3, 4, 10], capacity 7: greedy picks weight 5 (ratio 2.0, value 10), done — total 10. Optimal: weight 3+4 = 7, value 7. Actually 10 wins. Let us use [2,3,4] weights and [3,4,5] values, cap 5: greedy ratio [1.5, 1.33, 1.25] → picks weight 2 (value 3), then weight 3 (value 4) → total 7. Optimal: weight 2+3 is 5, value 7. Same. A clean example: weights [1, 3, 4, 5], values [1, 4, 5, 7], capacity 7. Greedy (by ratio): [1, 1.33, 1.25, 1.4] → picks 5 (val 7), then tries 3 (fits, val 4) → total 11. Optimal: 3+4=7, val 9, OR 3+5 doesn't fit OR... actually 5+1=6 (val 8), plus fits 1 more weight 1 → total val 9. Wait: 5(7) + 1(1) + 1(1) only if multiple units. For 0/1 knapsack weights=[1,3,4,5], vals=[1,4,5,7], cap=7: greedy picks 5 (val 7), then can add 1 (val 1) → total 8. Optimal: pick 3+4=7 (vals 4+5=9). Greedy gives 8, optimal is 9. Greedy fails.

## Core Patterns / Techniques

### Pattern 1: Activity selection / interval scheduling

```js
// Maximum number of non-overlapping intervals
// Sort by end time — greedy choice: always pick earliest-finishing valid interval
function activitySelection(activities) {
  activities.sort((a, b) => a.end - b.end); // key: sort by END, not start

  let count = 0;
  let lastEnd = -Infinity;

  for (const { start, end } of activities) {
    if (start >= lastEnd) { // compatible: starts after the last selected interval ends
      count++;
      lastEnd = end;
    }
    // else: overlaps — skip (greedy removal)
  }
  return count;
}
```

### Pattern 2: Fractional knapsack (greedy works; 0/1 knapsack it does not)

```js
// Fractional knapsack: you can take fractions of items
// Greedy: sort by value/weight ratio descending
function fractionalKnapsack(items, capacity) {
  items.sort((a, b) => b.value / b.weight - a.value / a.weight); // best ratio first

  let totalValue = 0;
  let remaining = capacity;

  for (const { weight, value } of items) {
    if (remaining <= 0) break;
    const take = Math.min(weight, remaining); // take all or fill capacity
    totalValue += (take / weight) * value;
    remaining -= take;
  }
  return totalValue;
}
// Greedy works here because fractions are allowed — you never "waste" capacity
// by committing to a full item that later prevents a better combination.
```

### Pattern 3: Jump game (can you reach the end?)

```js
// Greedy: track the furthest index reachable so far
function canJump(nums) {
  let maxReach = 0;
  for (let i = 0; i < nums.length; i++) {
    if (i > maxReach) return false; // stuck: can't reach index i
    maxReach = Math.max(maxReach, i + nums[i]);
  }
  return true;
}
```

### Pattern 4: Gas station (circular greedy)

```js
// Can complete a circular route? If so, from which starting station?
// Key insight: if total gas >= total cost, a solution always exists,
// and the answer is the station after the last point where cumulative sum goes negative.
function canCompleteCircuit(gas, cost) {
  let totalSurplus = 0, tank = 0, start = 0;
  for (let i = 0; i < gas.length; i++) {
    const net = gas[i] - cost[i];
    tank += net;
    totalSurplus += net;
    if (tank < 0) {       // can't reach next station from current start
      start = i + 1;      // try starting from the next station
      tank = 0;           // reset tank
    }
  }
  return totalSurplus >= 0 ? start : -1;
}
```

## Code Examples

### Example 1: Minimum number of platforms / rooms (greedy sweep)

```js
/**
 * Given arrival and departure times of trains, find the minimum number
 * of platforms required so no train has to wait.
 *
 * Greedy: create separate +1 (arrival) and -1 (departure) events,
 * sort by time, sweep to find the peak simultaneous count.
 *
 * Equivalent to: minimum meeting rooms needed.
 * Time: O(n log n), Space: O(n)
 */
function minPlatforms(arrivals, departures) {
  const n = arrivals.length;
  const events = [];

  for (let i = 0; i < n; i++) {
    events.push([arrivals[i], 1]);    // train arrives: +1 platform needed
    events.push([departures[i], -1]); // train departs: -1 platform freed
  }

  // Sort by time; on tie, process departures before arrivals
  // (a departing train frees the platform before the arriving train needs it)
  events.sort((a, b) => a[0] - b[0] || a[1] - b[1]);

  let platforms = 0;
  let maxPlatforms = 0;

  for (const [, delta] of events) {
    platforms += delta;
    maxPlatforms = Math.max(maxPlatforms, platforms);
  }

  return maxPlatforms;
}

console.log(minPlatforms(
  [900, 940, 950, 1100, 1500, 1800],
  [910, 1200, 1120, 1130, 1900, 2000]
)); // 3
```

### Example 2: Assign cookies (classic greedy matching)

```js
/**
 * You want to maximize the number of content children.
 * Each child has a greed factor g[i] (minimum cookie size needed).
 * Each cookie has a size s[j]. Assign at most one cookie per child.
 *
 * Greedy: sort both arrays. Use the smallest cookie that satisfies
 * the least-greedy remaining child. This is optimal: giving a larger
 * cookie to a less-greedy child wastes capacity.
 *
 * Time: O(n log n + m log m), Space: O(1)
 */
function findContentChildren(greed, sizes) {
  greed.sort((a, b) => a - b);   // least greedy first
  sizes.sort((a, b) => a - b);   // smallest cookies first

  let child = 0;
  let cookie = 0;

  while (child < greed.length && cookie < sizes.length) {
    if (sizes[cookie] >= greed[child]) {
      child++; // cookie satisfies this child — move to next child
    }
    cookie++; // always move to next cookie (used or too small)
  }

  return child; // number of children satisfied
}

console.log(findContentChildren([1, 2, 3], [1, 1])); // 1
console.log(findContentChildren([1, 2], [1, 2, 3])); // 2
```

## Best Practices

- **Prove greedy correctness before implementing.** Ask: "If I make this local choice, can I always get an equally good or better global solution?" If you can sketch the exchange argument, implement with confidence. If you can find a counter-example, switch to DP.
- **Sorting is almost always the first step.** Greedy algorithms typically need input in a specific order to make locally optimal choices. Identify the right sort key (by end time? by ratio? by start time?) before everything else.
- **Greedy and DP share optimal substructure.** The distinction is whether the greedy choice property also holds. When in doubt, check small examples: if a greedy approach gives the right answer on 3-5 hand-crafted examples including edge cases, it's likely correct.
- **Greedy on coins only works for certain denominations.** US coins (1¢, 5¢, 10¢, 25¢) have the greedy property; arbitrary denominations like {1, 3, 4} do not (greedy gives 3 coins for amount 6 using 4+1+1; optimal is 2 coins using 3+3). Always verify or use DP.
- **Counter-example first, algorithm second.** Before coding, try to break your greedy idea with a small example. If you can't break it after 3-4 tries, the exchange argument likely holds. If you can break it, you've saved the time of implementing the wrong algorithm.
- **Be explicit about ties in sorting.** When two items have the same sort key (e.g., same end time), the tie-breaking rule can matter. Document your tie-breaking and verify it against edge cases.
- **Greedy is not always O(n log n).** Some greedy algorithms (like the two-pointer approach on sorted arrays) are O(n) after the sort. Identify whether sorting dominates or whether a linear pass after sorting is the bottleneck.

## Common Interview Questions

**Q1: How do you know if a greedy algorithm is correct?**

A: Apply the exchange argument: assume an optimal solution doesn't make the greedy choice at some step, and show you can swap in the greedy choice without making the solution worse. If that swap is always valid, greedy is provably optimal. Alternatively, look for a counter-example — if you can find one, greedy is wrong.

**Q2: Why does sorting by end time (not start time) produce the maximum set of non-overlapping intervals?**

A: Sorting by end time implements the exchange argument: the earliest-finishing valid interval, when used as the first choice, never blocks more future choices than any other valid first choice. Any alternative first choice finishes at least as late, which can only restrict future options — never improve them.

**Q3: Why does greedy fail for 0/1 knapsack but succeed for fractional knapsack?**

A: In fractional knapsack, you can always take part of an item, so the "best ratio first" greedy never wastes capacity — you fill the bag exactly. In 0/1 knapsack, committing to a heavy item may prevent a better combination of lighter items. The choices interact: taking item A affects whether B and C fit together, and that interaction cannot be captured by a local ratio comparison.

**Q4: What is the time complexity of the activity selection algorithm?**

A: O(n log n) dominated by sorting. The subsequent linear scan is O(n). If the input is pre-sorted by end time, the algorithm is O(n).

**Q5: Describe a greedy approach to the "jump game II" problem (minimum jumps to reach end).**

A: At each position, track the furthest you can reach with the current number of jumps (current range end). When you exit the current range, you must make another jump — increment the jump count and extend the range to the furthest reachable position seen so far. This is O(n) with no sorting.

**Q6: When does the coin change problem have a greedy solution?**

A: When the denomination set has the "canonical" property — each denomination is a multiple of smaller ones (e.g., US coins: 25 = 5×5, 10 = 2×5). Arbitrary denominations break this: {1, 3, 4} with target 6 — greedy gives 4+1+1=3 coins, but 3+3=2 coins is optimal.

**Q7: What is the greedy approach to the "task scheduler" problem?**

A: Always execute the most frequent remaining task. Track frequencies, not task identities. After each execution cycle of length (n+1) (cooling period + 1), reduce the executed task's frequency and process the next most frequent. The total time = max(tasks.length, cycles × (n+1)).

**Q8: How does the "gas station" problem guarantee that if a solution exists, the greedy start works?**

A: If total gas ≥ total cost, a solution exists (sufficiency). The greedy key: whenever the tank goes negative starting from the current start, those stations (and the current start) cannot be part of any valid starting position. So reset the start to the next station and the tank to 0. The last such reset's "next station" is the answer.

## Practice Exercises

**Exercise 1 — Assign Cookies (Easy)**
Given children's greed factors and cookie sizes (one cookie per child), maximize the number of content children. A child is content if the assigned cookie size ≥ their greed factor.
Hint: Sort both arrays. The smallest sufficient cookie for the least-greedy child is optimal — using a larger cookie there wastes it.

**Exercise 2 — Lemonade Change (Easy)**
At a lemonade stand, each lemonade costs $5. Customers pay with $5, $10, or $20 bills. Determine if you can give correct change to every customer.
Hint: Greedy: always give change using the largest denomination possible (prefer $10 over two $5s when making $15 change). Track your cash inventory.

**Exercise 3 — Jump Game II (Medium)**
Given an array of non-negative integers where `nums[i]` is the maximum jump from index i, find the minimum number of jumps to reach the last index.
Hint: Greedy with range tracking. At each step, track the furthest reachable index within the current jump count. When you pass the current range boundary, increment jump count and extend the range.

**Exercise 4 — Partition Labels (Medium)**
A string is divided into as many parts as possible so that each letter appears in at most one part. Return a list of the sizes of these parts.
Hint: First pass: record the last index where each character appears. Second pass: greedily extend the current partition's end to the last occurrence of any character seen so far. When you reach the end, record the partition size.

**Exercise 5 — Reorganize String (Medium)**
Given a string, rearrange its characters so no two adjacent characters are the same. Return any valid rearrangement, or "" if impossible.
Hint: A rearrangement is possible if the most frequent character appears at most ⌈n/2⌉ times. Greedy: always place the most frequent remaining character next (if different from the previous). Use a max-heap of (frequency, character) pairs.

## Key Takeaways

- Greedy algorithms make the locally optimal choice at each step without reconsideration — correct only when the greedy choice property holds.
- The exchange argument is the formal proof technique: show that swapping any non-greedy choice for the greedy choice never worsens the solution.
- Sorting by end time is optimal for interval scheduling (activity selection); sorting by value/weight ratio is optimal for fractional (but not 0/1) knapsack.
- Greedy fails when choices interact — when committing to one option can foreclose a better combination of others. That interaction is exactly what DP handles.
- The gas station, jump game, and partition labels problems all have O(n) greedy solutions after recognizing the right invariant to maintain.
- Coin change with arbitrary denominations requires DP, not greedy — memorize this distinction for interviews.
- Always try to find a counter-example before implementing a greedy solution. If you can't find one after several tries, the exchange argument likely holds.
- Greedy's strength is simplicity and speed: O(n log n) or O(n) versus O(n²) or O(n×W) DP when greedy is valid.
