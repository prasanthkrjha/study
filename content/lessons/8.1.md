# LLM Fundamentals & Prompt Engineering

Large language models are the infrastructure layer on which every AI product in this module is built. Understanding how they work — at the level of a transformer architecture, tokenization, and context window mechanics — is not academic background; it is the knowledge that explains why certain prompting strategies work, why context length matters for RAG system design, and why some tasks are inherently hard for LLMs regardless of how well you prompt them.

Prompt engineering is the practice of designing model inputs to reliably elicit the outputs your application needs. It is not guessing and checking — it is systematic design with measurable output. A prompt is code: it should be versioned, tested against representative inputs, and evaluated for regressions when changed. The difference between a junior engineer who "writes prompts" and a senior AI engineer who "designs prompt systems" is exactly this: the latter treats prompts as artifacts subject to the same rigor as any other production component.

This unit establishes both the theoretical foundation (why do transformers work, what is tokenization doing) and the practical techniques (system prompts, few-shot examples, chain-of-thought, structured outputs) that you will apply in every subsequent unit in this module.

## Theory & Fundamentals

**Transformer architecture in brief**: A Transformer processes a sequence of tokens using self-attention — a mechanism that allows every position in the sequence to directly attend to (compute a weighted combination of) every other position. This enables capturing long-range dependencies that RNNs struggle with. The key components: token embeddings (each token is mapped to a dense vector), positional encodings (since attention is position-invariant, position information is added explicitly), multiple layers of multi-head self-attention + feed-forward networks, and a final linear layer projecting to vocabulary logits.

**Autoregressive generation**: During text generation, an LLM produces one token at a time. At each step it takes all previously generated tokens (the context) as input, computes a probability distribution over the vocabulary, and samples the next token. This process repeats until a stop condition is met. The implication: generation cost scales linearly with the number of output tokens, and the model "reads" the entire context (input + all previously generated tokens) on every generation step — this is why context length directly affects latency and cost.

**Tokenization**: Text is converted to tokens before being processed. A token is typically a word fragment (subword) — common words map to a single token; rare words are split into multiple tokens. English text averages roughly 1.3 tokens per word. Implications for prompt engineering: counting words does not tell you how many tokens you are using; non-English text is often more token-expensive (more subword splits); code has its own tokenization patterns (indentation, symbols).

**Context window**: The maximum number of tokens (input + output) the model can process in a single call. Everything outside the context window is invisible to the model. For RAG systems, this constrains how much retrieved context you can include. For agents with long tool-call histories, context management (summarization, truncation, external memory) becomes a real engineering problem.

**Temperature and sampling**: Temperature controls randomness in token selection. At temperature 0, the model always picks the highest-probability token (deterministic, maximally consistent). At higher temperatures, lower-probability tokens are sampled more often (more creative, more varied). For structured-output tasks (JSON extraction, classification) use low temperature; for creative generation use higher temperature.

## Core Concepts / Techniques

**Zero-shot prompting**:
```python
# No examples — relies entirely on the model's pretraining knowledge
zero_shot_prompt = """Classify the sentiment of this customer review as POSITIVE, NEGATIVE, or NEUTRAL.
Return ONLY the classification word, nothing else.

Review: "The shipping was fast but the product quality disappointed me."
Sentiment:"""
```

**Few-shot prompting**:
```python
# Provide 3 labeled examples before the real input
few_shot_prompt = """Classify sentiment as POSITIVE, NEGATIVE, or NEUTRAL.

Review: "Amazing product, works exactly as described." -> POSITIVE
Review: "Broke after two days. Very disappointed." -> NEGATIVE
Review: "It is okay, nothing special." -> NEUTRAL
Review: "Fast delivery, but the color was slightly different than pictured." ->"""
# The model continues from the pattern established by the examples
```

**Chain-of-thought (CoT)**:
```python
cot_prompt = """You are a math tutor. Solve the problem step by step before giving the final answer.

Problem: A store bought 240 items at $8 each and sold 180 of them at $15 each.
The remaining items were sold at 50% off the selling price. What was the total profit?

Let's think step by step:"""
# Generating intermediate reasoning tokens gives the model more compute per problem
```

**System prompt design**:
```python
system_prompt = """You are a customer support assistant for TechCorp, a B2B SaaS company.

Rules:
- Answer only questions about TechCorp products and services.
- If a question is outside scope, politely redirect to support@techcorp.com.
- Never speculate about competitor products.
- Always respond in the same language as the user's question.
- Format responses in clear, numbered steps when describing a process.

Context: The user's account tier is {account_tier}."""

# System prompt sets behavior; user prompt is the specific request
# This separation means guardrails are defined once, not repeated per message
```

**Structured output / JSON mode**:
```python
structured_prompt = """Extract the entities from the text below.

Return a JSON object with this exact schema:
{
  "person_name": string or null,
  "company": string or null,
  "date": string in YYYY-MM-DD format or null,
  "amount_usd": number or null
}

Text: "On March 15 2025, Sarah Chen from Meridian Capital invested $2.5 million."

Return ONLY the JSON object, no explanation:"""
```

## Code Examples

```python
"""
Production-grade prompt engineering patterns:
system/user separation, few-shot, CoT, structured output,
and a minimal prompt versioning system.
"""
from anthropic import Anthropic
import json
import hashlib
from datetime import datetime

client = Anthropic()

# ─── 1. Reusable prompt builder ───────────────────────────────────────────────
def build_classifier_prompt(examples: list[dict], text: str) -> str:
    """Build a few-shot classification prompt from labeled examples."""
    lines = ["Classify the intent of customer messages.\n"]
    lines.append("Examples:")
    for ex in examples:
        lines.append(f'Message: "{ex["text"]}" -> {ex["label"]}')
    lines.append(f'\nMessage: "{text}" ->')
    return "\n".join(lines)

examples = [
    {"text": "How do I reset my password?",         "label": "ACCOUNT_HELP"},
    {"text": "I was charged twice this month.",      "label": "BILLING"},
    {"text": "When will my order arrive?",           "label": "ORDER_STATUS"},
    {"text": "I want to cancel my subscription.",   "label": "CANCELLATION"},
]

test_messages = [
    "My credit card was billed incorrectly last week.",
    "Can you help me recover my account?",
    "I need to stop my plan immediately.",
]

for msg in test_messages:
    prompt = build_classifier_prompt(examples, msg)
    response = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=10,
        temperature=0,          # deterministic — classification task
        messages=[{"role": "user", "content": prompt}],
    )
    label = response.content[0].text.strip()
    print(f"Input: {msg!r}\nLabel: {label}\n")

# ─── 2. Structured JSON extraction ────────────────────────────────────────────
EXTRACTION_SYSTEM = """You are a data extraction assistant.
Extract structured information from text.
Return ONLY valid JSON matching the requested schema, no commentary."""

def extract_entities(text: str) -> dict:
    schema = '{"name": string|null, "date": "YYYY-MM-DD"|null, "amount": number|null}'
    user_msg = f"Schema: {schema}\n\nText: {text}\n\nJSON:"
    response = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=200,
        temperature=0,
        system=EXTRACTION_SYSTEM,
        messages=[{"role": "user", "content": user_msg}],
    )
    raw = response.content[0].text.strip()
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        # Sanitize: find first { and last }
        start, end = raw.find("{"), raw.rfind("}") + 1
        return json.loads(raw[start:end]) if start != -1 else {}

result = extract_entities(
    "On January 3 2025, Dr. Amelia Torres signed a contract worth $450,000."
)
print("Extracted:", result)

# ─── 3. Chain-of-thought for multi-step reasoning ─────────────────────────────
def solve_with_cot(problem: str) -> dict:
    """Returns both the reasoning chain and the final answer."""
    response = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=800,
        system="You are a careful reasoning assistant. Think step by step.",
        messages=[{
            "role": "user",
            "content": f"{problem}\n\nReason through this step by step, then state the final answer clearly on the last line starting with 'Final answer:'",
        }],
    )
    full_text = response.content[0].text
    parts = full_text.rsplit("Final answer:", 1)
    return {
        "reasoning": parts[0].strip(),
        "answer":    parts[1].strip() if len(parts) > 1 else "Not found",
    }

result = solve_with_cot(
    "A train travels from A to B at 80 km/h. The return trip is at 60 km/h. "
    "What is the average speed for the whole journey?"
)
print("Reasoning:", result["reasoning"][:200], "...")
print("Answer:", result["answer"])

# ─── 4. Prompt versioning ─────────────────────────────────────────────────────
class PromptVersion:
    """Track prompt text with a hash for reproducibility."""
    def __init__(self, name: str, template: str):
        self.name      = name
        self.template  = template
        self.hash      = hashlib.md5(template.encode()).hexdigest()[:8]
        self.created   = datetime.utcnow().isoformat()

    def render(self, **kwargs) -> str:
        return self.template.format(**kwargs)

    def __repr__(self):
        return f"PromptVersion({self.name!r}, hash={self.hash})"

# Log which version produced which output
v1 = PromptVersion(
    "sentiment_classifier_v1",
    "Classify the sentiment of this text as POSITIVE, NEGATIVE, or NEUTRAL:\n\n{text}\n\nSentiment:"
)
print(v1)
```

## Best Practices

- **Version control your prompts.** A prompt change is equivalent to a code change — it should be tracked in git with a commit message explaining why it was changed, not silently updated in a database or environment variable.
- **Test prompts against edge cases before deploying.** Create a representative test suite of 15-20 inputs covering normal cases, edge cases, and adversarial inputs. Re-run this suite every time you modify a prompt.
- **Separate behavior (system prompt) from content (user prompt).** Guardrails, persona, and output format belong in the system prompt, set once. The user prompt should carry only the task-specific input.
- **Use temperature 0 for deterministic tasks.** Classification, extraction, and any task where consistency matters more than creativity should use the lowest available temperature.
- **Request JSON in the schema, not just "in JSON format."** Including the exact field names and types in the prompt dramatically reduces invalid JSON output. Use JSON mode (where available) as an additional enforcement layer.
- **Chain-of-thought is not always the answer.** CoT adds latency and cost proportional to the reasoning chain length. Use it only when the task genuinely requires multi-step reasoning; simple classification tasks do not benefit.
- **Measure prompt performance quantitatively.** Define what "good" output looks like (a rubric, expected values, format checks) and compute a score. Gut-feel evaluation does not scale and does not catch subtle regressions.

## Common Interview Questions

**Q: What is a transformer and what makes it different from earlier sequence models?**
A: A Transformer processes entire sequences in parallel using self-attention, where each position directly attends to every other position with learned weights. Earlier RNNs processed sequences step-by-step with a compressed hidden state, struggling to retain information over long sequences and unable to be trained in parallel. Transformers removed these bottlenecks, enabling training on vastly more data and modeling much longer dependencies.

**Q: What is tokenization and why does it matter for prompt engineering?**
A: Tokenization converts text into integer token IDs that the model processes. Most LLMs use subword tokenization (BPE or WordPiece): common words are single tokens; rare words and non-English text are split into fragments. It matters because: the model's context limit is in tokens (not words or characters), costs are per-token, and some characters/languages are significantly more expensive than English prose.

**Q: What is the difference between zero-shot and few-shot prompting?**
A: Zero-shot provides no examples — the model relies on pretraining to understand the task. Few-shot includes labeled input/output examples before the real query, establishing the expected format and reasoning style. Few-shot typically improves consistency and output format adherence at the cost of a longer (more expensive) prompt. Use few-shot when zero-shot output is inconsistent or the required format is unusual.

**Q: What is chain-of-thought prompting and when does it help?**
A: CoT asks the model to generate intermediate reasoning steps before producing a final answer. It improves accuracy on multi-step tasks (math, logic, multi-hop reasoning) because generating the reasoning tokens gives the model additional "compute" — more forward passes — to work through the problem. It does not meaningfully help simple classification or retrieval tasks.

**Q: What is temperature in an LLM and how do you choose it?**
A: Temperature scales the logit distribution before sampling — low temperature makes the distribution sharper (favors high-probability tokens, more consistent), high temperature makes it flatter (more randomness and creativity). Use temperature 0 for extraction, classification, and structured output tasks where consistency is critical. Use higher values (0.7-1.0) for creative writing or brainstorming.

**Q: What is a context window and what are its practical implications?**
A: The context window is the maximum number of tokens (input + output combined) the model can process in one call. Practical implications: retrieved chunks in RAG must fit within budget; agent tool-call histories grow over time and must be managed; very long documents require chunking before processing; output length is constrained by what remains after input.

**Q: How do you prevent prompt injection?**
A: Prompt injection occurs when user-supplied text contains instructions that override or bypass the system prompt. Mitigations: structurally separate user content from instructions (e.g., XML tags like `<user_input>...</user_input>`), validate and sanitize user input before including it in prompts, keep sensitive instructions in the system prompt where they have higher precedence, and use output validation to detect unexpected behavior patterns.

Count the number of unique outputs at each temperature. Plot a bar chart of output diversity vs. temperature. Draw conclusions about when each temperature setting is appropriate.

## Key Takeaways

- Transformers process sequences in parallel via self-attention, enabling better long-range dependency capture and parallel training compared to RNNs.
- Tokens, not words or characters, are the unit of computation — context limits, costs, and latency are all measured in tokens.
- System prompts set persistent behavior and constraints; user prompts carry task-specific input. This separation is what makes reusable AI components possible.
- Few-shot prompting improves format consistency and task adherence by showing examples; chain-of-thought improves accuracy on multi-step reasoning by generating intermediate steps.
- Temperature controls output randomness — use 0 for deterministic structured tasks, higher values for creative tasks.
- Prompts are production artifacts: version control them, test them against edge cases, and measure their performance quantitatively.
- Context windows constrain RAG chunk budgets, agent memory, and output length — managing context is a real engineering problem, not just a prompt consideration.
- Structured output (JSON schema in the prompt + JSON mode) is far more reliable for programmatic output than asking for "JSON format."
