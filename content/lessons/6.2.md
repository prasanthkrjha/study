# Data Analysis & Visualization

Exploratory Data Analysis (EDA) is the step between raw data and model training where you build genuine understanding of a dataset — its shape, its distributions, its anomalies, and the relationships between features. Skipping EDA and going straight to modeling is one of the most common mistakes made by engineers moving into ML: models quietly trained on dirty or misunderstood data produce results that look plausible but are subtly or catastrophically wrong.

Python's visualization ecosystem centers on matplotlib (the foundational layer), seaborn (statistical visualizations with better defaults built on matplotlib), and pandas' own `.plot()` API. Understanding which tool to reach for — and when a table is more informative than a chart — separates analysts who can communicate findings from those who produce visual noise.

This unit covers the full EDA loop: loading and profiling data, detecting data quality issues, computing and visualizing distributions and correlations, and generating the kind of analysis that informs modeling decisions in Module 7. The skills here are also what you reach for first when debugging a model that is underperforming.

## Theory & Fundamentals

**Why EDA before modeling**: A model trained on data with a significant class imbalance, unexpected outliers, or a leaky feature will silently learn the wrong thing. EDA surfaces these problems before they become expensive model failures. Concretely: if a feature's distribution is wildly different between training and test sets, or if a "predictive" feature is actually computed from the target (leakage), no amount of hyperparameter tuning fixes the problem.

**matplotlib architecture**: matplotlib has two interfaces. The stateful pyplot API (`plt.plot(...)`, `plt.xlabel(...)`) is convenient for quick exploratory plots. The object-oriented API (`fig, ax = plt.subplots(); ax.plot(...)`) is necessary for multi-panel figures, fine-grained control, and embedded plots in production reports. The object-oriented API should be the default for anything more complex than a single quick chart.

**seaborn's statistical orientation**: seaborn functions expect "tidy" data — each row is one observation, each column is one variable. Its key value is that it automatically handles grouping and aggregation in a single call: `seaborn.boxplot(data=df, x="category", y="value")` computes and renders a box-and-whisker distribution per category without any manual groupby. This makes it significantly faster for the iterative look-at-the-data loop of EDA than building the same chart from scratch with matplotlib.

**Distributions and summary statistics**: The mean tells you the center of a distribution; the standard deviation tells you the spread. But both are sensitive to outliers. The median (50th percentile) and IQR (interquartile range, 75th minus 25th percentile) are robust equivalents. When mean and median diverge significantly, you have a skewed distribution — which often warrants a log transform before feeding the feature to a linear model. Understanding this informs feature engineering decisions in Module 7.

**Correlation vs. causation**: A high correlation between two features means they move together linearly, not that one causes the other. Correlation matrices are useful for spotting multicollinearity (features that are nearly redundant, which can destabilize linear models) and for a first-pass feature relevance scan. They do not replace domain knowledge about what actually drives the target variable.

## Core Concepts / Techniques

**Profiling a DataFrame**:
```python
import pandas as pd
import numpy as np

df = pd.read_csv("data.csv")

# Shape, types, non-null counts
print(df.shape)
print(df.dtypes)
print(df.isnull().sum())

# Numeric summary: mean, std, quartiles
print(df.describe())

# Value counts for categorical columns
print(df["status"].value_counts(normalize=True))  # relative frequencies
```

**matplotlib basics — object-oriented style**:
```python
import matplotlib.pyplot as plt

fig, axes = plt.subplots(1, 2, figsize=(12, 4))

# Left panel: histogram
axes[0].hist(df["revenue"], bins=50, edgecolor="black")
axes[0].set_title("Revenue Distribution")
axes[0].set_xlabel("Revenue ($)")
axes[0].set_ylabel("Count")

# Right panel: scatter
axes[1].scatter(df["age"], df["revenue"], alpha=0.3, s=10)
axes[1].set_title("Age vs Revenue")
axes[1].set_xlabel("Age")
axes[1].set_ylabel("Revenue ($)")

fig.tight_layout()
plt.savefig("eda_overview.png", dpi=150)
plt.show()
```

**seaborn for statistical plots**:
```python
import seaborn as sns

# Distribution by category
fig, axes = plt.subplots(1, 3, figsize=(15, 4))

sns.histplot(df["revenue"], kde=True, ax=axes[0])          # distribution with KDE
sns.boxplot(data=df, x="segment", y="revenue", ax=axes[1]) # distribution per group
sns.heatmap(df.corr(numeric_only=True), annot=True,         # correlation matrix
            cmap="coolwarm", center=0, ax=axes[2])

plt.tight_layout()
plt.show()
```

## Code Examples

```python
"""
Full EDA workflow on a sales dataset.
Covers: profiling, cleaning, univariate and bivariate analysis,
correlation, and saving a visual report.
"""
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns

# ─── 1. Load & Profile ──────────────────────────────────────────────────────
df = pd.read_csv("sales.csv", parse_dates=["order_date"])

print("Shape:", df.shape)
print("\nNull counts:\n", df.isnull().sum())
print("\nDtype summary:\n", df.dtypes)
print("\nNumeric summary:\n", df.describe())

# ─── 2. Clean ────────────────────────────────────────────────────────────────
df = df.drop_duplicates(subset=["order_id"])
df = df.dropna(subset=["user_id", "revenue"])
df["discount_pct"] = df["discount_pct"].fillna(0.0)
df["region"] = df["region"].str.strip().str.title()

# Clip extreme outliers at the 99th percentile (keep 99% of data intact)
cap = df["revenue"].quantile(0.99)
df["revenue_capped"] = df["revenue"].clip(upper=cap)

# Log-transform for right-skewed revenue (common in financial data)
df["log_revenue"] = np.log1p(df["revenue_capped"])

# ─── 3. Univariate Analysis ──────────────────────────────────────────────────
fig, axes = plt.subplots(2, 2, figsize=(12, 8))
fig.suptitle("Univariate Distributions", fontsize=14)

# Revenue (original) — shows right skew
sns.histplot(df["revenue"], bins=80, kde=False, ax=axes[0, 0])
axes[0, 0].set_title("Revenue (raw)")

# Revenue (log-transformed) — approximately normal after log
sns.histplot(df["log_revenue"], bins=60, kde=True, ax=axes[0, 1])
axes[0, 1].set_title("Log(1 + Revenue)")

# Categorical: order volume by region
region_counts = df["region"].value_counts()
axes[1, 0].barh(region_counts.index, region_counts.values)
axes[1, 0].set_title("Orders by Region")

# Temporal: monthly order volume
monthly = df.set_index("order_date").resample("ME")["order_id"].count()
axes[1, 1].plot(monthly.index, monthly.values)
axes[1, 1].set_title("Monthly Order Volume")
axes[1, 1].tick_params(axis="x", rotation=45)

fig.tight_layout()
plt.savefig("univariate.png", dpi=150)
plt.show()

# ─── 4. Bivariate & Multivariate Analysis ────────────────────────────────────
fig, axes = plt.subplots(1, 3, figsize=(15, 4))

# Box plot: revenue distribution per segment
sns.boxplot(data=df, x="segment", y="log_revenue",
            order=df.groupby("segment")["log_revenue"].median()
                    .sort_values(ascending=False).index,
            ax=axes[0])
axes[0].set_title("Log Revenue by Segment")
axes[0].tick_params(axis="x", rotation=30)

# Scatter with color by segment
segments = df["segment"].unique()
palette = sns.color_palette("tab10", len(segments))
for seg, color in zip(segments, palette):
    sub = df[df["segment"] == seg]
    axes[1].scatter(sub["discount_pct"], sub["log_revenue"],
                    alpha=0.3, s=8, color=color, label=seg)
axes[1].set_title("Discount % vs Log Revenue")
axes[1].set_xlabel("Discount %")
axes[1].set_ylabel("Log Revenue")
axes[1].legend(markerscale=2, fontsize=8)

# Correlation heatmap
numeric_cols = ["revenue_capped", "log_revenue", "discount_pct",
                "quantity", "days_to_ship"]
corr = df[numeric_cols].corr()
sns.heatmap(corr, annot=True, fmt=".2f", cmap="coolwarm",
            center=0, vmin=-1, vmax=1, ax=axes[2])
axes[2].set_title("Correlation Matrix")

fig.tight_layout()
plt.savefig("bivariate.png", dpi=150)
plt.show()

# ─── 5. Quick Insights Table ─────────────────────────────────────────────────
summary = (
    df.groupby("segment")
      .agg(
          n_orders=("order_id", "count"),
          median_revenue=("revenue_capped", "median"),
          avg_discount=("discount_pct", "mean"),
          return_rate=("returned", "mean"),
      )
      .round(2)
      .sort_values("median_revenue", ascending=False)
)
print("\nSegment Summary:\n", summary.to_string())
```

## Best Practices

- **Always look at the data before computing statistics.** A bimodal distribution or a cluster of outliers is visible in a histogram immediately; summary statistics (mean, std) hide it. Plot first, compute second.
- **Log-transform right-skewed numeric features** (revenue, population, counts) before passing them to linear models or plotting correlations — skewed data violates the linearity assumptions many models and correlation metrics depend on.
- **Use `value_counts(normalize=True)` on every categorical column** early in EDA to spot class imbalance, rare categories, and encoding inconsistencies (e.g. "US", "u.s.", "United States" as three separate values).
- **Clip outliers, do not blindly drop them.** Outliers are often real data points that a model should handle. Clipping at the 99th percentile preserves the rank and relative ordering without letting a handful of extreme values distort a model's loss function.
- **Check distributions separately for train and test splits.** Distribution shift (where the test set has a different distribution than training) is one of the most common causes of a model that performs well in training but poorly in production.
- **Annotate your plots** with titles, axis labels, and data source information before sharing. An unlabeled chart is uninterpretable to anyone except the person who made it an hour ago.
- **Save a summary statistics table alongside charts.** Numbers communicate precision; charts communicate shape. A colleague reading your EDA report needs both.

## Common Interview Questions

**Q: What is EDA and why do you do it before modeling?**
A: EDA (Exploratory Data Analysis) is the process of profiling a dataset to understand its distributions, missing values, outliers, and feature relationships before training a model. It surfaces data quality issues and informs feature engineering decisions. Skipping it leads to models trained on dirty or misunderstood data, where bugs are invisible until the model is in production.

**Q: What is a correlation matrix and what are its limitations?**
A: A correlation matrix shows the pairwise Pearson correlation coefficient between numeric columns, ranging -1 (perfect negative linear relationship) to +1 (perfect positive). Its limitations: it only captures linear relationships (misses nonlinear associations), is sensitive to outliers, and measures correlation not causation. Two features can be highly correlated due to a hidden confounding variable.

**Q: What is the difference between mean and median, and when does the distinction matter?**
A: The mean is the arithmetic average, pulled by outliers. The median is the middle value — robust to outliers and skew. For right-skewed distributions (income, revenue, user activity), the mean is significantly higher than the median and is misleading as a "typical" value. In ML feature engineering, skewed features often benefit from median-based imputation and log-transformation.

**Q: What is a KDE plot and what does it show?**
A: KDE (Kernel Density Estimation) is a smoothed continuous estimate of a variable's probability distribution. Unlike a histogram (which depends on arbitrary bin widths), a KDE curve gives a continuous shape. It is useful for comparing the distribution shapes of two groups on the same axes without the visual noise of overlapping bars.

**Q: What is data leakage and how do you detect it during EDA?**
A: Data leakage occurs when information from the target variable or the future is encoded in a feature, making the model appear more accurate in evaluation than it would be in production. EDA detects it by examining features that have suspiciously high correlation with the target, or by checking whether a feature's value could logically be known before the target is determined.

**Q: How do you visualize the relationship between a categorical and a continuous variable?**
A: A box plot shows the median, IQR, and outliers per category. A violin plot adds the full distribution shape. A strip or swarm plot shows individual data points. For large datasets, a box plot with notches (indicating the confidence interval around the median) is usually the most information-dense option.

**Q: What is multicollinearity and why does it matter?**
A: Multicollinearity is when two or more features are highly correlated with each other. It matters for linear models because it makes individual coefficient estimates unstable and large in magnitude — the model cannot reliably attribute predictive power to one feature vs. the other. It is visible in a correlation matrix as cells with absolute value close to 1 between feature pairs (not features and the target).

## Key Takeaways

- EDA is not optional housekeeping — it is the primary mechanism for catching data quality problems before they become invisible model bugs.
- matplotlib's object-oriented API (fig/axes) is the right default for anything beyond a one-off exploratory chart.
- seaborn excels at statistical visualizations per group (box plots, violin plots, pair plots) and should be the first choice for bivariate analysis.
- Log-transforming right-skewed features is one of the highest-leverage preprocessing steps for linear models and for making distributions visually interpretable.
- Correlation measures linear association only; always verify high-correlation findings with a scatter plot to distinguish linear from nonlinear relationships.
- Clip rather than drop outliers unless you have domain-specific evidence that they are measurement errors.
- Always check for class imbalance in the target variable — training a classifier on a 99/1 split without addressing the imbalance produces a model that predicts the majority class for everything and still looks 99% accurate.
- Save EDA outputs (charts and summary tables) as versioned artifacts alongside your code — they are the audit trail that explains why you made the feature engineering decisions you did.
