# Advanced Graphs

Once basic BFS and DFS are in hand, a second tier of graph problems requires algorithms with names: Dijkstra's for weighted shortest paths, Union-Find for dynamic connectivity, Kruskal's and Prim's for minimum spanning trees, and topological sort for dependency ordering. Each of these answers a question that plain BFS or DFS cannot — either because edges have weights, or because the question is about global structure rather than local reachability.

Understanding when to reach for which algorithm is as important as knowing how to implement it. The trigger phrases are distinct: "shortest path in a weighted graph" → Dijkstra; "detect if adding an edge creates a cycle" or "find the number of connected groups" → Union-Find; "connect all nodes at minimum cost" → MST (Kruskal's or Prim's); "order tasks given prerequisites" → topological sort. Misidentifying the problem type and applying the wrong algorithm is a common interview failure mode.

These algorithms also compose. Kruskal's MST algorithm uses Union-Find internally. Dijkstra uses a min-heap (priority queue). Topological sort using Kahn's algorithm is a modified BFS. Seeing the composition helps you understand why each piece has its particular time complexity, and helps you reconstruct algorithms from first principles when memory fails under pressure.

## Theory & Fundamentals

### Union-Find (Disjoint Set Union)

Union-Find maintains a collection of disjoint sets and supports two operations:
- `find(x)`: returns the canonical representative (root) of x's set.
- `union(x, y)`: merges the sets containing x and y.

Both operations are nearly O(1) amortized with two optimizations:
1. **Path compression** (in `find`): make every node on the path point directly to the root, flattening the tree.
2. **Union by rank**: always attach the shorter tree under the root of the taller tree.

Together these give O(α(n)) per operation, where α is the inverse Ackermann function — effectively constant for all practical n.

### Dijkstra's algorithm

Dijkstra finds the shortest distances from a single source to all other nodes in a graph with **non-negative** edge weights. The algorithm:
1. Start with distance 0 for the source, infinity for all others.
2. Use a min-heap (priority queue) keyed by current known distance.
3. At each step, extract the node with the smallest known distance.
4. For each neighbor, if the path through the current node is shorter than the known path to that neighbor, update and push to the heap.
5. Stop when the heap is empty (or when the target is extracted, if only one destination is needed).

Correctness relies on non-negative edges: once a node is extracted as the minimum, its distance is finalized (no future path can be shorter, since all edge weights are ≥ 0).

**Bellman-Ford** handles negative edge weights (and detects negative cycles) in O(VE), far slower than Dijkstra's O((V + E) log V). For interview purposes, assume Dijkstra unless the problem specifies negative weights.

### Minimum Spanning Tree

An MST of a connected, weighted, undirected graph spans all vertices with the minimum total edge weight and contains no cycles. Key properties:
- An MST always has exactly V-1 edges (where V = number of vertices).
- If all edge weights are distinct, the MST is unique.
- **Cut property:** for any partition of the graph into two sets, the minimum-weight edge crossing the cut belongs to every MST.

**Kruskal's:** Sort edges by weight, add each edge if it doesn't form a cycle (checked via Union-Find). O(E log E).
**Prim's:** Grow the MST from one node outward; always add the cheapest edge connecting an MST node to a non-MST node. Uses a min-heap. O((V + E) log V).

Kruskal's is simpler to implement in interviews. Prim's performs better on dense graphs.

### Topological sort

A topological ordering of a DAG (directed acyclic graph) is a linear ordering of vertices such that for every directed edge (u → v), u appears before v. It is only possible for DAGs — cycles prevent any linear ordering.

**Kahn's algorithm (BFS-based):**
1. Compute in-degree (number of incoming edges) for every node.
2. Seed a queue with all nodes of in-degree 0.
3. Process each node from the queue: append to result, decrement in-degree of all neighbors; enqueue any neighbor whose in-degree drops to 0.
4. If the result contains all nodes, the graph is a DAG. If not, there was a cycle.

**DFS-based (finish time):**
Run DFS; when a node is fully explored (all children processed), prepend it to the result. The result, reversed, is the topological order.

## Core Patterns / Techniques

### Pattern 1: Union-Find

```js
class UnionFind {
  constructor(n) {
    this.parent = Array.from({ length: n }, (_, i) => i); // each node is its own root
    this.rank = new Array(n).fill(0);
    this.components = n; // track number of distinct sets
  }

  find(x) {
    // Path compression: directly connect to root
    if (this.parent[x] !== x) {
      this.parent[x] = this.find(this.parent[x]);
    }
    return this.parent[x];
  }

  union(a, b) {
    const rootA = this.find(a);
    const rootB = this.find(b);
    if (rootA === rootB) return false; // already same component — adding edge would create cycle

    // Union by rank: attach smaller tree under larger
    if (this.rank[rootA] < this.rank[rootB]) {
      this.parent[rootA] = rootB;
    } else if (this.rank[rootA] > this.rank[rootB]) {
      this.parent[rootB] = rootA;
    } else {
      this.parent[rootB] = rootA;
      this.rank[rootA]++;
    }
    this.components--;
    return true;
  }

  connected(a, b) {
    return this.find(a) === this.find(b);
  }
}
```

### Pattern 2: Dijkstra's shortest path

```js
function dijkstra(graph, source, n) {
  // graph: adjacency list, graph[u] = [[v, weight], ...]
  const dist = new Array(n).fill(Infinity);
  dist[source] = 0;

  // Min-heap: [distance, node] — simulate with sorted array for simplicity
  const heap = [[0, source]];

  while (heap.length) {
    heap.sort((a, b) => a[0] - b[0]);         // use a real MinHeap in production
    const [d, u] = heap.shift();

    if (d > dist[u]) continue;                // stale entry — skip it

    for (const [v, weight] of (graph[u] ?? [])) {
      const newDist = dist[u] + weight;
      if (newDist < dist[v]) {
        dist[v] = newDist;
        heap.push([newDist, v]);
      }
    }
  }

  return dist;
}
```

### Pattern 3: Kruskal's MST

```js
function kruskalMST(n, edges) {
  // edges: [[weight, u, v], ...]
  edges.sort((a, b) => a[0] - b[0]); // sort by weight ascending
  const uf = new UnionFind(n);
  const mstEdges = [];
  let totalWeight = 0;

  for (const [weight, u, v] of edges) {
    if (uf.union(u, v)) {          // returns true if u and v were in different components
      mstEdges.push([u, v, weight]);
      totalWeight += weight;
      if (mstEdges.length === n - 1) break; // MST is complete
    }
  }

  return { mstEdges, totalWeight };
}
```

### Pattern 4: Topological sort (Kahn's algorithm)

```js
function topoSort(numNodes, edges) {
  // edges: [prerequisite, course] — prerequisite must come before course
  const graph = Array.from({ length: numNodes }, () => []);
  const inDegree = new Array(numNodes).fill(0);

  for (const [pre, course] of edges) {
    graph[pre].push(course);
    inDegree[course]++;
  }

  // Start with all nodes that have no prerequisites
  const queue = [];
  for (let i = 0; i < numNodes; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  const order = [];
  while (queue.length) {
    const node = queue.shift();
    order.push(node);
    for (const neighbor of graph[node]) {
      inDegree[neighbor]--;
      if (inDegree[neighbor] === 0) queue.push(neighbor);
    }
  }

  return order.length === numNodes ? order : []; // empty = cycle detected
}
```

## Code Examples

### Example 1: Network delay time (Dijkstra's)

```js
/**
 * Given n nodes, directed weighted edges, and a source k,
 * find the time for a signal to reach all nodes from k.
 * Return -1 if some node is unreachable.
 *
 * This is single-source shortest path on a directed weighted graph.
 * Time: O((V + E) log V) with a proper min-heap
 */
function networkDelayTime(times, n, k) {
  // Build adjacency list: graph[u] = [[v, weight], ...]
  const graph = Array.from({ length: n + 1 }, () => []);
  for (const [u, v, w] of times) {
    graph[u].push([v, w]);
  }

  const dist = new Array(n + 1).fill(Infinity);
  dist[k] = 0;

  // Heap simulation [distance, node]
  const heap = [[0, k]];

  while (heap.length) {
    heap.sort((a, b) => a[0] - b[0]);
    const [d, u] = heap.shift();

    if (d > dist[u]) continue; // stale — a shorter path was already found

    for (const [v, w] of graph[u]) {
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        heap.push([dist[v], v]);
      }
    }
  }

  // Find the maximum distance to any node (the signal must reach all of them)
  let maxDist = 0;
  for (let i = 1; i <= n; i++) {
    if (dist[i] === Infinity) return -1; // unreachable node
    maxDist = Math.max(maxDist, dist[i]);
  }
  return maxDist;
}

// times = [[2,1,1],[2,3,1],[3,4,1]], n=4, k=2 → 2
console.log(networkDelayTime([[2,1,1],[2,3,1],[3,4,1]], 4, 2));
```

### Example 2: Course schedule II (topological sort)

```js
/**
 * Return an ordering in which to take numCourses courses, given prerequisites.
 * Return [] if no valid ordering exists (cycle).
 *
 * Models courses as a DAG; topological sort gives a valid completion order.
 * Time: O(V + E) — Kahn's algorithm is a modified BFS
 */
function findOrder(numCourses, prerequisites) {
  const graph = Array.from({ length: numCourses }, () => []);
  const inDegree = new Array(numCourses).fill(0);

  // Build directed graph: prerequisite -> course
  for (const [course, pre] of prerequisites) {
    graph[pre].push(course);
    inDegree[course]++;
  }

  // Seed: courses with no prerequisites
  const queue = [];
  for (let i = 0; i < numCourses; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  const result = [];

  while (queue.length) {
    const course = queue.shift();
    result.push(course);

    // "Complete" this course: reduce in-degrees of dependent courses
    for (const next of graph[course]) {
      inDegree[next]--;
      if (inDegree[next] === 0) queue.push(next); // all prerequisites satisfied
    }
  }

  // If we processed all courses, no cycle exists
  return result.length === numCourses ? result : [];
}

console.log(findOrder(4, [[1,0],[2,0],[3,1],[3,2]]));
// One valid order: [0, 1, 2, 3] or [0, 2, 1, 3]
```

## Best Practices

- **Skip stale entries in Dijkstra by checking `d > dist[u]`.** The lazy deletion pattern avoids removing entries from the heap (which is expensive) — instead, just ignore outdated entries when they are popped.
- **Dijkstra's correctness depends on non-negative edge weights.** If the problem mentions negative weights, you must use Bellman-Ford. Applying Dijkstra to a graph with negative edges produces wrong answers.
- **Union-Find's `union` returning false signals a cycle.** This is how Kruskal's detects and avoids adding edges that would create cycles in the MST.
- **Track component count in UnionFind.** Decrement on each successful `union`. This gives O(1) access to the number of remaining components at any point.
- **Kahn's cycle detection is a free bonus.** If the topological order contains fewer nodes than the graph has, a cycle exists. You don't need a separate cycle-detection pass.
- **Prefer Kruskal's over Prim's in interviews.** The Union-Find + sorted-edges approach is easier to code correctly under pressure. Prim's requires a min-heap over edges with lazy deletion, adding implementation complexity.
- **For shortest path with uniform edge weights, use BFS, not Dijkstra.** BFS is O(V + E) vs. Dijkstra's O((V + E) log V). Only reach for Dijkstra when edges have distinct non-negative weights.

## Common Interview Questions

**Q1: What does Dijkstra's algorithm do, and what is its key limitation?**

A: Dijkstra computes single-source shortest paths in a weighted graph. Its key limitation is that it requires **non-negative edge weights**. With non-negative weights, once a node is extracted from the min-heap, its distance is final. A negative edge could allow a path discovered later to beat an already-finalized distance.

**Q2: What is the time complexity of Dijkstra's with a binary min-heap?**

A: O((V + E) log V). Each node is extracted from the heap once (O(V log V)), and each edge is relaxed once (O(E log V) for heap insertions). With a Fibonacci heap it improves to O(E + V log V), but that's never needed in interviews.

**Q3: What are the two optimizations that make Union-Find nearly O(1) per operation?**

A: Path compression and union by rank. Path compression flattens the tree during `find` so subsequent lookups are faster. Union by rank (or union by size) ensures the tree stays shallow by always merging the smaller tree into the larger. Together they give amortized O(α(n)) per operation.

**Q4: When would you use Union-Find versus DFS/BFS for connected components?**

A: Use Union-Find when edges are added incrementally (online) and you need to answer "are A and B connected?" after each addition. Use BFS/DFS when you have the entire graph upfront and want to enumerate or process each component. Union-Find is not naturally suited for directed graphs or finding the actual path.

**Q5: What is the difference between Prim's and Kruskal's MST algorithms?**

A: Kruskal's processes edges globally, sorted by weight, and uses Union-Find to reject cycle-forming edges. Prim's grows a single connected component by always adding the cheapest edge connecting the current MST to a new node (like Dijkstra's). Both produce an MST. Kruskal's is simpler to implement; Prim's is preferable for dense graphs.

**Q6: What condition must a graph satisfy for topological sort to be defined?**

A: The graph must be a DAG (directed acyclic graph). Any cycle makes topological sorting impossible — if A depends on B and B depends on A, neither can come first. Kahn's algorithm detects cycles as a side effect: if the result contains fewer than V nodes, a cycle exists.

**Q7: In the course schedule problem, how do you detect an impossible ordering (cycle)?**

A: Run Kahn's algorithm. If the resulting order's length equals numCourses, all courses can be completed. If it's shorter, the remaining courses (those never reached in-degree 0) form a cycle — they mutually depend on each other and can never be started.

**Q8: How does Dijkstra differ from BFS for finding shortest paths?**

A: BFS works on unweighted graphs (or uniform weights), exploring nodes level by level (by hop count). Dijkstra works on weighted graphs, using a min-heap to always explore the globally cheapest unvisited node next. If all edge weights are 1, Dijkstra degenerates to BFS.

## Practice Exercises

**Exercise 1 — Number of Provinces (Medium)**
Given an n×n adjacency matrix where `isConnected[i][j] = 1` means city i and city j are directly connected, find the number of provinces (connected components).
Hint: Apply Union-Find — union every pair (i, j) where `isConnected[i][j] === 1`. The number of distinct roots remaining is the answer. Alternatively, use DFS/BFS per component.

**Exercise 2 — Cheapest Flights Within K Stops (Medium)**
Given n cities, flights `[from, to, price]`, source src, destination dst, and at most k stops, find the cheapest price. Return -1 if impossible.
Hint: Modified Dijkstra or Bellman-Ford with k+1 relaxation rounds. The state is `[cost, city, stopsRemaining]`. Do not mark cities as globally visited — the same city can be revisited with more stops remaining.

**Exercise 3 — Min Cost to Connect All Points (Medium)**
Given an array of points `[xi, yi]`, find the minimum cost to connect all points. The cost of connecting two points is the Manhattan distance `|xi - xj| + |yi - yj|`.
Hint: Model as a complete graph (all pairs are edges). Apply Kruskal's or Prim's. For Prim's, instead of storing all edges upfront, compute distances on the fly as you grow the MST.

**Exercise 4 — Alien Dictionary (Hard)**
Given a list of words sorted according to an alien language's alphabet, determine the order of characters in the alphabet. If no valid order exists, return "".
Hint: Compare adjacent words to extract ordering constraints (edges). Run topological sort. If adjacent words have the same prefix but the shorter word comes after the longer one, immediately return "" (impossible).

**Exercise 5 — Reconstruct Itinerary (Hard)**
Given a list of airline tickets `[from, to]`, reconstruct the itinerary starting from "JFK". Use all tickets exactly once. If multiple valid itineraries exist, return the one with the smallest lexicographic order.
Hint: This is Eulerian path (using every edge exactly once) on a directed graph. Use Hierholzer's algorithm: DFS greedily taking the lexicographically smallest neighbor, and prepend each node to the path after its neighbors are exhausted.

## Key Takeaways

- Union-Find provides nearly O(1) connectivity queries and merges, enabling O(E log E) cycle detection as edges are added one at a time.
- Dijkstra's requires a min-heap and non-negative weights; it finds shortest paths from one source to all others in O((V + E) log V).
- Kruskal's MST = sort edges + Union-Find cycle check. Prim's MST = Dijkstra-style expansion. Both produce the same tree; Kruskal's is simpler in interviews.
- Topological sort is only defined for DAGs; Kahn's BFS-based algorithm detects cycles for free.
- The stale-entry skip (`if (d > dist[u]) continue`) is essential in Dijkstra when using a lazy-deletion heap.
- The "cut property" of MSTs explains why greedy edge selection (cheapest crossing edge) is correct.
- Composition matters: Kruskal's uses Union-Find; Dijkstra uses a min-heap; topological sort is a modified BFS. Seeing these compositions helps reconstruct algorithms from first principles.
- For uniform-weight shortest paths, BFS is O(V + E) and always preferable to Dijkstra.
