# Sliding Window

The sliding window technique is the specialized tool for problems about **contiguous subarrays or substrings**. Instead of re-computing from scratch for each possible window, you maintain a running state (a sum, a character frequency map, a count) and update it incrementally as the window edges move. A fixed-size window slides like a conveyor belt; a variable-size window expands and contracts based on validity.

The pattern's power comes from amortization: even when the inner shrink-loop appears to make the algorithm look quadratic, each element is added to the window exactly once and removed from the window exactly once across the entire run. That gives O(n) total work — the same guarantee that makes amortized analysis so important in complexity reasoning.

Sliding window is closely related to two pointers — both use two indices that move forward. The distinction is intent: two pointers typically look for a specific pair or partition; sliding window focuses on the best (longest, shortest, maximum, minimum) contiguous window satisfying a constraint. In practice, the implementation is often identical.

## Theory & Fundamentals

### The Amortization Argument

The key insight that makes variable-size sliding window O(n) is that both pointers only move forward. `right` advances through the array once: n steps total. `left` also only ever moves forward, and can advance at most n times across the entire run (it can never go backward). Total moves: at most 2n → O(n), regardless of the inner while loop.

```
right → → → → → → → → → → → → → (n moves total)
left          → → → → → → →      (at most n moves total across all iterations)
```

This argument breaks if `left` can ever move backward. It never does in a valid sliding window implementation — that invariant is what you must protect.

### Window State

The window state is what you track between the two pointers. Common states:

| Problem type | Window state |
|---|---|
| Max/min subarray sum | Running sum (integer) |
| Longest unique substring | Set of characters in window |
| Min window with all chars | Frequency map + "satisfied" counter |
| Max k-distinct chars | Frequency map + distinct count |
| Fixed-size max | Running sum, subtract outgoing element |

The state must be **updatable in O(1)** when the window expands or shrinks by one element. If updating the state requires re-scanning the window, the algorithm degrades to O(n²).

### Fixed vs. Variable Windows

**Fixed-size window**: size `k` is given. Slide right by one at each step, adding `arr[right]` and removing `arr[right - k]`. State update is always O(1).

**Variable-size window**: two sub-patterns:
1. **Expand until invalid, then shrink** — for "longest window satisfying condition." Expand `right` freely; shrink `left` when condition breaks.
2. **Expand until valid, then shrink to optimize** — for "shortest window satisfying condition." Expand until the window is valid; shrink `left` as long as validity holds, recording the smallest valid window.

## Core Patterns / Techniques

### Pattern 1: Fixed-Size Window Maximum

```js
// Maximum sum of any subarray of length k
function maxSumSubarray(nums, k) {
  // Build the first window
  let windowSum = 0;
  for (let i = 0; i < k; i++) windowSum += nums[i];

  let best = windowSum;

  // Slide the window: add new right element, subtract old left element
  for (let right = k; right < nums.length; right++) {
    windowSum += nums[right] - nums[right - k]; // O(1) update
    best = Math.max(best, windowSum);
  }
  return best;
}
// Time: O(n)  Space: O(1)
```

### Pattern 2: Longest Window Without Repeats (Expand-Shrink)

```js
// Longest substring without repeating characters
function lengthOfLongestSubstring(s) {
  const inWindow = new Set();
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    // Shrink from left until the new character can be added
    while (inWindow.has(s[right])) {
      inWindow.delete(s[left]);
      left++;
    }
    inWindow.add(s[right]);
    best = Math.max(best, right - left + 1);
  }
  return best;
}
// Time: O(n) — each char added once, removed once
// Space: O(k) where k = alphabet size (at most 128 for ASCII)
```

### Pattern 3: Shortest Valid Window (Contract After Valid)

```js
// Minimum size subarray with sum >= target
function minSubarrayLen(target, nums) {
  let left = 0;
  let windowSum = 0;
  let best = Infinity;

  for (let right = 0; right < nums.length; right++) {
    windowSum += nums[right]; // expand right

    // Once valid, contract left as far as possible while still valid
    while (windowSum >= target) {
      best = Math.min(best, right - left + 1);
      windowSum -= nums[left];
      left++;
    }
  }
  return best === Infinity ? 0 : best;
}
// Time: O(n)  Space: O(1)
```

### Pattern 4: At-Most-K Distinct Characters

```js
// Longest substring with at most k distinct characters
function longestSubstringKDistinct(s, k) {
  const freq = new Map();
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    // Add new character to window
    freq.set(s[right], (freq.get(s[right]) ?? 0) + 1);

    // Shrink if we exceed k distinct characters
    while (freq.size > k) {
      const leftCh = s[left];
      freq.set(leftCh, freq.get(leftCh) - 1);
      if (freq.get(leftCh) === 0) freq.delete(leftCh);
      left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}
// Time: O(n)  Space: O(k)
```

### Pattern 5: Exact Count via "At Most K" Trick

Some problems ask for an "exactly k" count. The trick: `count(exactly k) = count(at most k) - count(at most k-1)`.

```js
// Number of subarrays with exactly k odd numbers
function numberOfSubarraysExactlyK(nums, k) {
  const atMost = (limit) => {
    let left = 0, count = 0, odds = 0;
    for (let right = 0; right < nums.length; right++) {
      if (nums[right] % 2 !== 0) odds++;
      while (odds > limit) {
        if (nums[left] % 2 !== 0) odds--;
        left++;
      }
      count += right - left + 1; // all subarrays ending at right that satisfy
    }
    return count;
  };
  return atMost(k) - atMost(k - 1);
}
// Time: O(n)  Space: O(1)
```

## Code Examples

### Example 1: Minimum Window Substring

```js
/**
 * Given strings s and t, find the minimum window in s that contains
 * all characters of t. Return "" if none exists.
 *
 * Strategy: expand right until all chars in t are covered, then
 * contract left to find the minimum valid window. Repeat.
 *
 * Time: O(|s| + |t|)   Space: O(|t|)
 */
function minWindow(s, t) {
  if (!s || !t) return '';

  // Frequency of each character we need
  const need = new Map();
  for (const ch of t) need.set(ch, (need.get(ch) ?? 0) + 1);

  const window = new Map();
  let have = 0;                // how many chars are satisfied (count >= need)
  const required = need.size;  // total distinct chars to satisfy

  let left = 0;
  let bestLeft = 0, bestLen = Infinity;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    window.set(ch, (window.get(ch) ?? 0) + 1);

    // Did we just satisfy a requirement?
    if (need.has(ch) && window.get(ch) === need.get(ch)) {
      have++;
    }

    // All requirements met — try to shrink the window
    while (have === required) {
      if (right - left + 1 < bestLen) {
        bestLeft = left;
        bestLen = right - left + 1;
      }

      const leftCh = s[left];
      window.set(leftCh, window.get(leftCh) - 1);
      if (need.has(leftCh) && window.get(leftCh) < need.get(leftCh)) {
        have--;
      }
      left++;
    }
  }

  return bestLen === Infinity ? '' : s.slice(bestLeft, bestLeft + bestLen);
}

console.log(minWindow('ADOBECODEBANC', 'ABC')); // 'BANC'
console.log(minWindow('a', 'a'));               // 'a'
console.log(minWindow('a', 'b'));               // ''
```

### Example 2: Sliding Window Maximum with Deque

```js
/**
 * Given an array and window size k, return the maximum in each window.
 * Brute force: O(n·k). Optimal: O(n) using a monotonic deque.
 *
 * Deque stores indices in decreasing order of their values.
 * Front of deque always holds the index of the window's maximum.
 *
 * Time: O(n)   Space: O(k)
 */
function maxSlidingWindow(nums, k) {
  const deque = []; // stores indices; nums[deque[0]] is always the window max
  const result = [];

  for (let right = 0; right < nums.length; right++) {
    // Remove indices that are outside the window
    while (deque.length && deque[0] < right - k + 1) {
      deque.shift();
    }

    // Maintain decreasing order: remove smaller elements from the back
    // (they can never be the maximum of any future window)
    while (deque.length && nums[deque[deque.length - 1]] < nums[right]) {
      deque.pop();
    }

    deque.push(right);

    // Window is full: record the maximum
    if (right >= k - 1) {
      result.push(nums[deque[0]]);
    }
  }
  return result;
}

console.log(maxSlidingWindow([1,3,-1,-3,5,3,6,7], 3)); // [3,3,5,5,6,7]
console.log(maxSlidingWindow([1], 1));                  // [1]
```

## Best Practices

- **Both pointers must only move forward** — if your `left` pointer ever needs to move backward, your window state is wrong and the O(n) guarantee breaks.
- **Use a frequency map with a "satisfied" counter** instead of re-scanning the map to check validity — incrementing/decrementing `have` in O(1) is what keeps the inner loop amortized.
- **Track window size as `right - left + 1`** — this is always the length of the current window, and it's the value you compare or record.
- **For fixed-size windows, subtract the outgoing element** — `windowSum += nums[right] - nums[right - k]` is more efficient than rebuilding the sum each time.
- **For "exactly k" problems, use the at-most-k subtraction trick** — trying to implement "exactly k" directly is harder and usually requires additional state.
- **Initialize `best` to `Infinity` for minimum problems and `-Infinity` (or 0) for maximum problems** — avoids edge cases with empty or single-element arrays.
- **Handle empty string/array edge cases at the top** — guard against `s.length === 0` or `k > nums.length` before entering the main logic.

## Common Interview Questions

**Q1: What is the time complexity of the sliding window approach for "longest substring without repeating characters"?**
A: O(n). Each character is added to the window (via `right`) exactly once and removed (via `left`) at most once, so total operations are O(2n) = O(n).

**Q2: How does sliding window differ from the brute-force approach for substring problems?**
A: Brute force checks every possible window from scratch, costing O(n·k) or O(n²). Sliding window maintains incremental state (a running sum, a frequency map) that can be updated in O(1) when the window shifts, giving O(n) total.

**Q3: When should you use a fixed-size vs. variable-size sliding window?**
A: Fixed-size when the window size `k` is given explicitly in the problem. Variable-size when you're optimizing (longest, shortest, maximum, minimum) over all valid window sizes.

**Q4: How do you detect the end of a "valid" window state?**
A: Define a validity predicate and a counter/variable that tracks it in O(1). For "all characters of t covered," use `have === required`. For "sum >= target," use `windowSum >= target`. Update this counter when you add or remove an element.

**Q5: Can sliding window handle negative numbers in sum problems?**
A: Not directly for variable-size windows. The "shrink while valid" logic assumes that making the window smaller reduces the sum (monotonicity). With negative numbers, shrinking might not reduce the sum. In those cases, use Kadane's algorithm or prefix sums instead.

**Q6: What is the "at most K minus at most K-1" trick?**
A: For problems asking for subarrays with exactly k occurrences of something, it's easier to count "at most k" windows using sliding window, then subtract "at most k-1" windows. The difference gives "exactly k."

**Q7: Explain the monotonic deque used in "Sliding Window Maximum."**
A: A deque maintains indices in decreasing order of their values. When a new element enters, all smaller elements at the back are removed (they can never be the max of any future window since they are older and smaller). This ensures the front always holds the current window's maximum index.

**Q8: How would you find the number of subarrays with average >= threshold?**
A: Subtract `threshold` from every element (so you need average >= 0, i.e., sum >= 0 for any subarray). Then count subarrays with non-negative sum — which can be done with prefix sums or a modified sliding window approach.

## Practice Exercises

**Exercise 1 — Fixed Window Average (Beginner)**
Given an array of integers and a window size `k`, find the maximum average of any contiguous subarray of length exactly `k`. Implement the O(n) sliding window approach and verify it produces the same answer as a brute-force O(n·k) approach on the same input.
Hint: Maintain a running window sum. Update by adding the new right element and subtracting the element that just left the window (`nums[right - k]`).

**Exercise 2 — Longest Subarray of 1s After Deletion (Beginner-Intermediate)**
Given a binary array (containing only 0s and 1s), find the maximum length of a contiguous subarray of 1s after deleting exactly one element. Think of this as: at most one 0 allowed in the window. What is the window validity condition?
Hint: Track the count of zeros in the window. The window is valid as long as zeros ≤ 1. After finding the longest window, subtract 1 from its length (for the deleted element).

**Exercise 3 — Permutation in String (Intermediate)**
Given strings `s1` and `s2`, return `true` if any permutation of `s1` is a substring of `s2`. This is a fixed-size sliding window with character frequency matching. How do you efficiently check if the window matches `s1`'s frequency without comparing the full frequency map each time?
Hint: Maintain a "matched" counter tracking how many of the 26 letter frequencies match between the window and `s1`. Increment/decrement when a character's window count equals (or breaks away from) its required count.

**Exercise 4 — Fruit Into Baskets (Intermediate)**
You have an array of fruit types. You can carry two baskets, each holding only one type of fruit. Starting from any position, collect the maximum number of fruits in contiguous positions using only two types. This is "longest subarray with at most 2 distinct values." Extend your solution to k distinct values.
Hint: Use a frequency map where `freq.size` tracks distinct types. Shrink the window when `freq.size > k`.

**Exercise 5 — Substring with Concatenation of All Words (Advanced)**
Given a string `s` and an array `words` where all words have the same length, find all starting indices of substrings in `s` that are a concatenation of all words (in any order, each used once). The window size is fixed (`words.length * wordLen`) but you must match whole words within it.
Hint: Use a sliding window of size `k * wordLen`. Slide by one word at a time. Maintain a map of word counts currently in the window, and compare to the required word count map.

## Key Takeaways

- Sliding window achieves O(n) for contiguous subarray/substring problems by updating window state incrementally rather than recomputing from scratch.
- The O(n) guarantee comes from amortization: both `left` and `right` only move forward, so total pointer moves are at most 2n.
- Fixed windows slide by dropping the outgoing element and adding the incoming one in O(1).
- Variable windows expand until a condition breaks (longest problems) or is met (shortest problems), then contract from the left.
- Valid state must be trackable in O(1) on each pointer move — use counters, not re-scans.
- The "at most k" minus "at most k-1" trick converts "exactly k" problems into two easier "at most" problems.
- Sliding window cannot directly handle negative-number sum constraints — use prefix sums or Kadane's algorithm for those.
- Recognize the pattern by keywords: "subarray," "substring," "contiguous," "window," "longest," "shortest."
