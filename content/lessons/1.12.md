# Intervals

An interval `[start, end]` represents a contiguous range — a time window, a line segment, a memory block, or any bounded span. Interview problems involving intervals typically ask you to merge overlapping spans, count simultaneous conflicts, find gaps, or schedule the maximum number of non-overlapping activities. These all share a foundational insight: once you impose an ordering, the relationships between adjacent intervals become trivially checkable with a single condition.

The overwhelming majority of interval problems begin with one move: **sort by start time**. After sorting, you know that any interval you have not yet processed starts at or after the current interval. This turns an O(n²) pairwise comparison problem into a single linear pass where you only need to compare the current interval against the most recent "committed" interval — never any earlier one.

The one major exception is interval scheduling (maximize non-overlapping intervals), where you sort by **end time** instead of start time. The distinction matters: sorting by end time is provably optimal for greedy selection because it always picks the interval that leaves the most future room. Knowing when to sort by start vs. end, and why, is the key conceptual divide in this topic.

## Theory & Fundamentals

### Overlap condition

Two intervals `[a, b]` and `[c, d]` overlap if and only if `a <= d && c <= b`. Equivalently, they do **not** overlap when `b < c || d < a` (one ends before the other begins). In code, checking the "not overlapping" condition is often cleaner:

```js
function overlaps(a, b) {
  // Returns true if intervals a and b share any point
  return a[0] <= b[1] && b[0] <= a[1];
}
```

This single condition underlies every interval problem. The variations are:
- Strict vs. inclusive: `a[0] < b[1]` (touching endpoints don't count as overlap)
- What you do when overlap is detected: merge, count conflict, find gap, etc.

### Three core problems and their approaches

| Problem | Sort by | Goal | Key operation |
|---|---|---|---|
| Merge intervals | Start time | Combine overlapping spans | Extend `last[1] = max(last[1], end)` when overlap |
| Count meeting rooms needed | Start time | Max simultaneous occupancy | Track active interval count with a min-heap of end times |
| Max non-overlapping (scheduling) | End time | Select maximum count | Greedy: take interval if it starts ≥ last end |

### Why sorting by end time is optimal for scheduling

Suppose an optimal solution selects some first interval that is not the earliest-finishing. Swap it for the earliest-finishing interval. Since the earliest-finishing interval ends no later, every subsequent interval that was compatible with the original first choice is also compatible with the swap. The count cannot decrease. Therefore, always picking the earliest-finishing valid interval is at least as good as any other strategy — it is greedy-optimal.

### Insert interval

Insert a new interval into a sorted, non-overlapping list. Scan linearly:
1. While current intervals end before the new interval starts: add to output unchanged.
2. While current intervals overlap the new interval: merge (expand new interval's bounds).
3. After merges: add the final merged interval, then the rest of the list unchanged.
Total time: O(n), since the list is already sorted.

## Core Patterns / Techniques

### Pattern 1: Merge overlapping intervals

```js
function merge(intervals) {
  if (!intervals.length) return [];
  intervals.sort((a, b) => a[0] - b[0]); // sort by start time

  const merged = [intervals[0]];
  for (let i = 1; i < intervals.length; i++) {
    const last = merged[merged.length - 1];
    const [start, end] = intervals[i];

    if (start <= last[1]) {
      // Overlaps with last merged interval — extend the end
      last[1] = Math.max(last[1], end);
    } else {
      // No overlap — start a new group
      merged.push([start, end]);
    }
  }
  return merged;
}
// merge([[1,3],[2,6],[8,10],[15,18]]) → [[1,6],[8,10],[15,18]]
```

### Pattern 2: Interval scheduling (maximum non-overlapping)

```js
function maxNonOverlapping(intervals) {
  intervals.sort((a, b) => a[1] - b[1]); // sort by END time (key difference)
  let count = 0;
  let lastEnd = -Infinity;

  for (const [start, end] of intervals) {
    if (start >= lastEnd) { // compatible with last selected interval
      count++;
      lastEnd = end;
    }
  }
  return count;
}
```

### Pattern 3: Minimum meeting rooms (minimum resources for all intervals)

```js
// Uses a min-heap of end times of currently active intervals
function minMeetingRooms(intervals) {
  intervals.sort((a, b) => a[0] - b[0]); // sort by start

  // Simulate a min-heap with a sorted array (sufficient for interview)
  const endTimes = []; // tracks when each "room" becomes free

  for (const [start, end] of intervals) {
    if (endTimes.length && endTimes[0] <= start) {
      // Reuse the earliest-freeing room
      endTimes.shift(); // in a real heap: pop()
    }
    endTimes.push(end);
    endTimes.sort((a, b) => a - b); // in a real heap: push() maintains order
  }

  return endTimes.length; // number of rooms in use at peak
}
```

### Pattern 4: Insert a new interval

```js
function insert(intervals, newInterval) {
  const result = [];
  let i = 0;
  const n = intervals.length;

  // Phase 1: add all intervals that end before new interval starts
  while (i < n && intervals[i][1] < newInterval[0]) {
    result.push(intervals[i++]);
  }

  // Phase 2: merge all overlapping intervals into newInterval
  while (i < n && intervals[i][0] <= newInterval[1]) {
    newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
    newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
    i++;
  }
  result.push(newInterval);

  // Phase 3: add remaining non-overlapping intervals
  while (i < n) result.push(intervals[i++]);

  return result;
}
```

## Code Examples

### Example 1: Meeting rooms II — minimum simultaneous rooms needed

```js
/**
 * Given an array of meeting time intervals [start, end],
 * find the minimum number of conference rooms required.
 *
 * Key insight: instead of tracking which specific room each meeting uses,
 * track only when each "in-use" room becomes free (end times).
 * At each new meeting's start, if any room is free (its end <= new start),
 * reuse it; otherwise open a new room.
 *
 * Time: O(n log n) — sorting + heap operations
 * Space: O(n) — heap of end times
 */
function minMeetingRoomsHeap(intervals) {
  if (!intervals.length) return 0;

  intervals.sort((a, b) => a[0] - b[0]); // process meetings in start-time order

  // Min-heap of end times (here simulated; use a real heap class in production)
  class MinHeap {
    constructor() { this.h = []; }
    push(v) {
      this.h.push(v);
      this.h.sort((a, b) => a - b); // O(k log k) — acceptable for illustration
    }
    pop() { return this.h.shift(); }
    peek() { return this.h[0]; }
    size() { return this.h.length; }
  }

  const heap = new MinHeap();

  for (const [start, end] of intervals) {
    if (heap.size() > 0 && heap.peek() <= start) {
      heap.pop(); // reclaim the earliest-ending room
    }
    heap.push(end); // allocate this meeting's room, record when it ends
  }

  return heap.size(); // rooms still occupied = total rooms needed
}

const meetings = [[0,30],[5,10],[15,20]];
console.log(minMeetingRoomsHeap(meetings)); // 2
```

### Example 2: Non-overlapping intervals — minimum removals to eliminate all overlaps

```js
/**
 * Given an array of intervals, find the minimum number to remove
 * so that the remaining intervals are non-overlapping.
 *
 * Observation: minimizing removals = maximizing the non-overlapping set we keep.
 * This is exactly the interval scheduling maximization problem.
 * Answer = total intervals - max non-overlapping count.
 *
 * Time: O(n log n) — sorting dominates
 * Space: O(1)
 */
function eraseOverlapIntervals(intervals) {
  if (!intervals.length) return 0;

  // Sort by end time — greedy scheduling
  intervals.sort((a, b) => a[1] - b[1]);

  let keep = 0;       // count of intervals we keep
  let lastEnd = -Infinity;

  for (const [start, end] of intervals) {
    if (start >= lastEnd) {
      keep++;          // this interval is compatible — keep it
      lastEnd = end;   // update the boundary for future comparisons
    }
    // else: this interval overlaps — skip it (count as removed)
  }

  return intervals.length - keep; // total minus what we kept
}

console.log(eraseOverlapIntervals([[1,2],[2,3],[3,4],[1,3]])); // 1
console.log(eraseOverlapIntervals([[1,2],[1,2],[1,2]]));       // 2
console.log(eraseOverlapIntervals([[1,2],[2,3]]));             // 0
```

## Best Practices

- **Sort first — always.** For merge and insert problems, sort by start time. For scheduling (maximize non-overlapping), sort by end time. Getting the sort key wrong produces an incorrect algorithm.
- **Use strict vs. non-strict comparison deliberately.** `start < lastEnd` detects overlapping intervals; `start <= lastEnd` also treats touching endpoints as overlap. Understand which interpretation the problem demands before writing the condition.
- **Track only what you need.** Merge problems only need the most recent merged interval's end. Scheduling problems only need the last selected interval's end. Rooms problems need all current end times (a heap). Match data structure to what you actually need to compare.
- **For "insert interval", process in three distinct phases.** Intervals strictly before, intervals overlapping, intervals strictly after. Interleaving these phases is a common source of off-by-one bugs.
- **The minimum meeting rooms count equals the maximum simultaneous overlap.** You can also solve it with a timeline sweep: create +1 events at each start and -1 at each end, sort by time, sweep accumulating the running count.
- **Verify edge cases:** zero intervals, all intervals overlapping into one, all intervals disjoint, intervals that touch at a single point.
- **Closed vs. half-open intervals matter.** `[1,3]` and `[3,5]` overlap (touching) under closed semantics but not under half-open `[1,3)` and `[3,5)` semantics. Clarify with the interviewer which convention the problem uses.

## Common Interview Questions

**Q1: Why do we sort by end time for the scheduling problem but start time for merge intervals?**

A: For merge, we want to process intervals in the order they begin so we can extend a running merged window. For scheduling (maximize count), we sort by end time because it implements the greedy proof: an earlier-ending interval leaves the most future room, guaranteeing the greedy selection is optimal.

**Q2: What is the time and space complexity of the merge intervals algorithm?**

A: O(n log n) time (dominated by sorting) and O(n) space for the output. The linear scan after sorting is O(n), but sorting costs O(n log n). If the input is pre-sorted, the algorithm is O(n).

**Q3: How do you find the minimum number of meeting rooms required?**

A: Sort by start time. Maintain a min-heap of the end times of currently running meetings. For each new meeting, if the earliest-ending current meeting ends before this one starts, reuse that room (pop from heap); otherwise allocate a new room. Push the new meeting's end time. The heap size at the end is the answer. O(n log n).

**Q4: What is the overlap condition, and how does it simplify to a single expression?**

A: Two intervals `[a, b]` and `[c, d]` overlap when `a <= d && c <= b`. This covers all overlap configurations (partial, containment, identical). They don't overlap when `b < c` (first ends before second starts) or `d < a` (second ends before first starts) — DeMorgan gives `!(b < c || d < a)` = `b >= c && d >= a`.

**Q5: How would you find all "free time" windows between a set of intervals?**

A: Merge all intervals into non-overlapping spans. Then iterate through the merged list; the gap between `merged[i][1]` and `merged[i+1][0]` is a free window. This is O(n log n) for sorting plus O(n) for scanning.

**Q6: Can you solve the "insert interval" problem without sorting?**

A: Yes — if the input intervals are already sorted and non-overlapping (as is typically stated). Scan once: collect intervals that end before the new one starts, merge all overlapping intervals into the new interval, then append the rest. O(n) — no sort needed.

**Q7: What is the connection between "minimum number of removals" and "maximum scheduling"?**

A: They are complements. Minimum removals to make intervals non-overlapping = total intervals minus the maximum number of non-overlapping intervals you can keep. The greedy scheduling algorithm directly gives the maximum to keep.

**Q8: How do you detect if a person can attend all their meetings?**

A: Sort by start time. Check if any adjacent pair of meetings overlaps: if `intervals[i][0] < intervals[i-1][1]`, an overlap exists and the person cannot attend both. Return false if any overlap found, true otherwise. O(n log n).

## Practice Exercises

**Exercise 1 — Merge Intervals (Easy)**
Given an array of intervals where `intervals[i] = [start, end]`, merge all overlapping intervals and return the merged result. Example: `[[1,3],[2,6],[8,10],[15,18]]` → `[[1,6],[8,10],[15,18]]`.
Hint: Sort by start time. Compare each interval's start against the most recently merged interval's end.

**Exercise 2 — Meeting Rooms (Easy)**
Given an array of meeting time intervals `[start, end]`, determine if a single person can attend all meetings (i.e., no two meetings overlap).
Hint: Sort by start time and check each adjacent pair. O(n log n) total.

**Exercise 3 — Employee Free Time (Medium)**
Given a schedule of working hours for several employees (each employee has a list of non-overlapping intervals sorted by start time), return the list of intervals representing free time common to all employees.
Hint: Flatten all intervals into one list, sort by start, merge, then find gaps. Alternatively, use a heap to merge k sorted lists.

**Exercise 4 — Data Stream — Summary Ranges (Medium)**
Given a sorted integer array with no duplicates, return the shortest list of ranges that cover all numbers. A range `[a, b]` is written as `"a->b"` if a ≠ b, or `"a"` if a = b.
Hint: This is an interval merging problem on consecutive integers. Extend the current range while the next number is exactly one more; otherwise start a new range.

**Exercise 5 — Minimum Number of Arrows to Burst Balloons (Medium)**
Balloons are represented as intervals `[xstart, xend]`. An arrow shot at x bursts every balloon whose range includes x. Find the minimum number of arrows needed to burst all balloons.
Hint: This is structurally identical to the maximum non-overlapping intervals problem. Sort by end time and greedily fire each arrow at the end of the current earliest-finishing balloon.

## Key Takeaways

- Sort by **start time** for merge and insert problems; sort by **end time** for scheduling (maximize non-overlapping) problems. The choice of sort key is the crux of the algorithm.
- The overlap condition `a[0] <= b[1] && b[0] <= a[1]` is universal — memorize it.
- Merge intervals maintains one invariant: only compare each interval against the last merged result, never earlier ones.
- The greedy scheduling proof (sort by end, take greedily) is an exchange argument: the earliest-finishing valid interval never hurts future choices.
- Minimum meeting rooms = maximum simultaneous overlapping intervals = size of the end-time min-heap at peak.
- Minimum removals to make non-overlapping = total − maximum non-overlapping (they are complements).
- Insert interval is a three-phase scan: before, overlapping, after. Pre-sorted input makes this O(n).
- Always verify edge cases: empty input, all overlapping, all disjoint, touching endpoints.
