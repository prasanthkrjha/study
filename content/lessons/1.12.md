# Intervals

Interval problems ("merge overlapping meetings," "can you attend all meetings," "insert a new interval") almost always start with the same move: **sort by start time**. Once sorted, overlap detection becomes a simple linear scan.

## Merge intervals

```js
function mergeIntervals(intervals) {
  if (!intervals.length) return [];
  intervals.sort((a, b) => a[0] - b[0]);
  const merged = [intervals[0]];
  for (let i = 1; i < intervals.length; i++) {
    const last = merged[merged.length - 1];
    const [start, end] = intervals[i];
    if (start <= last[1]) {
      last[1] = Math.max(last[1], end); // overlaps — extend
    } else {
      merged.push([start, end]); // no overlap — new group
    }
  }
  return merged;
}
```

The overlap check `start <= last[1]` is the whole trick: because the array is sorted by start time, you only ever need to compare against the **most recently merged** interval, never the whole history.

## Interval scheduling (maximize non-overlapping intervals)

This is a greedy problem in disguise: sort by **end time** instead of start time, and greedily take an interval whenever it doesn't overlap the last one you took. Sorting by end time (not start time) is what makes the greedy choice provably optimal — it always leaves the most room for future intervals.

```js
function maxNonOverlapping(intervals) {
  intervals.sort((a, b) => a[1] - b[1]);
  let count = 0, lastEnd = -Infinity;
  for (const [start, end] of intervals) {
    if (start >= lastEnd) { count++; lastEnd = end; }
  }
  return count;
}
```

## Overlap detection

Two intervals `[a, b]` and `[c, d]` overlap exactly when `a <= d && c <= b`. This single condition underlies "meeting rooms," "insert interval," and "employee free time" problems — the variation is usually in what you do once you know two intervals overlap (merge them, count a conflict, or find the gap between them).

## Recognizing the pattern

Any problem describing ranges, meetings, or time windows — and asking you to merge, count conflicts, or schedule optimally — wants: sort first (by start or end depending on the goal), then a single linear pass comparing each interval only to the most recent one you've committed to.
