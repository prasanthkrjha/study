# Technical Conceptual Q&A

This unit is a rapid-reference for the conceptual questions that recur across full-stack and AI interviews — the goal is being able to answer each crisply in 30-60 seconds, then go deeper if asked.

## Full-stack conceptual

**React internals**
- *Reconciliation*: React compares the new element tree to the previous one (diffing) and computes the minimal set of real DOM mutations needed, rather than re-rendering the whole DOM on every state change.
- *Hooks rules*: hooks must be called in the same order on every render (never inside conditionals/loops) because React tracks hook state by call order, not by name.
- *Closures*: a common bug source — a callback or effect captures the value of a variable **at the time it was created**, not its latest value, unless that variable is in the dependency array or accessed via a ref/functional update.

**Node.js event loop** — Node is single-threaded for JS execution but non-blocking for I/O: expensive I/O operations (file reads, network calls) are delegated to the system/libuv thread pool, and their callbacks are queued to run on the main thread once the current synchronous code finishes. This is why one slow synchronous computation blocks *everything* (there's only one JS thread), but many concurrent I/O operations don't block each other.

**REST API design** — resources as nouns (`/users/42`, not `/getUser`), HTTP verbs carry the action (GET/POST/PUT/PATCH/DELETE), status codes communicate outcome precisely (200 vs 201 vs 204 vs 400 vs 404 vs 500), and idempotency matters (GET/PUT/DELETE should be safely repeatable; POST typically isn't).

**Caching strategies** — client-side (browser cache, `Cache-Control` headers), CDN-level (static assets, Unit 5.3), server-side (in-memory or Redis, Unit 2.3), and database-level (query caching, materialized views) — each solves a different layer of "don't redo expensive work."

**JWT vs. sessions** — a session stores state server-side (a session ID cookie references server-held data), needing lookup on every request but easy to revoke instantly. A JWT is self-contained and stateless (the token itself holds the claims, signed to prevent tampering) — no server lookup needed, but harder to revoke before expiry since the server isn't tracking active tokens.

**CORS** — a browser security mechanism that blocks a webpage from making requests to a different origin (domain/port/protocol) unless the server explicitly allows it via response headers (`Access-Control-Allow-Origin`). It's enforced by the browser, not the server — which is why CORS errors only show up in browser-based clients, never in server-to-server or `curl` requests.

## AI/LLM conceptual

**How RAG works end-to-end** — chunk documents, embed chunks and store them (vector database), embed the incoming query, retrieve the most similar chunks, include them in the prompt as grounding context, generate an answer constrained to that context. (Full detail: Unit 8.3.)

**Chunking trade-offs** — too large dilutes relevance per chunk; too small loses surrounding context. (Unit 8.3.)

**Vector vs. keyword search** — dense/semantic (embeddings) catches paraphrases and meaning but can miss exact terms; sparse/keyword (BM25) catches exact terms but misses paraphrases. Production systems often combine both. (Unit 8.2/8.3.)

**Hallucination mitigation** — grounding prompts explicitly in retrieved context, instructing the model to say "I don't know" when context is insufficient, and evaluation harnesses that check answers against source material. (Unit 8.9.)

**Agent architecture patterns** — the ReAct loop (reason → act → observe, Unit 8.6), single-agent vs. multi-agent (one model handling everything vs. multiple specialized agents coordinating), and where MCP fits as the tool-interoperability layer (Unit 8.8).

**Fine-tuning vs. RAG vs. prompting** — prompting changes behavior with zero training cost but is limited by context window and doesn't add new knowledge; RAG adds retrievable knowledge without retraining; fine-tuning changes the model's actual behavior/style but costs the most and doesn't update easily. (Unit 8.9.)
