# Stack

A stack is a last-in, first-out (LIFO) data structure with two core operations: `push` (add to top) and `pop` (remove from top), both O(1). In JavaScript, a plain array serves as a stack using `.push()` and `.pop()`. The LIFO property makes stacks the natural tool for problems involving **nesting, matching, and "what was the most recent unresolved thing?"**

Stacks appear in two distinct families of problems. The first is literal nesting: bracket matching, call stacks, HTML tag validation — problems where every closing element must match the most recently opened element still waiting. The second family is the **monotonic stack**, where you discard elements that violate a sorted order to efficiently find the next greater or smaller element. These two families have different setups but the same underlying LIFO logic.

Learning to recognize when a stack is appropriate is more valuable than memorizing specific stack algorithms. The mental trigger: if the answer for the current element depends on a previous element that hasn't been "resolved" yet — and specifically, it depends on the **most recently unresolved** element — you need a stack.

## Theory & Fundamentals

### The LIFO Property and Why It Matters

Consider parentheses `((()))`. The innermost pair must be closed first. That's LIFO: the last opened must be the first closed. A stack captures this naturally: push open brackets, check (and pop) on close brackets.

In contrast, if the problem cared about the oldest unresolved item, you would need a queue (FIFO). Most nesting and matching problems care about the **most recent** unresolved item — hence the stack.

### Monotonic Stack — The Key Concept

A monotonic stack maintains elements in strictly increasing or strictly decreasing order from bottom to top. When a new element violates the order, you pop until the order is restored, then push the new element.

**Monotonic decreasing stack** (top is smallest): used to find the next greater element. When you see a larger value, it "resolves" everything smaller than it still on the stack.

**Monotonic increasing stack** (top is largest): used to find the next smaller element.

```
Array: [4, 3, 2, 5, 1]
Processing 4: stack = [4]
Processing 3: 3 < 4, push: stack = [4, 3]
Processing 2: 2 < 3, push: stack = [4, 3, 2]
Processing 5: 5 > 2,3,4 → pop 2 (next greater = 5), pop 3 (NGE=5), pop 4 (NGE=5)
              stack = [5]
Processing 1: 1 < 5, push: stack = [5, 1]
End: remaining elements [5, 1] have no next greater → -1
```

The O(n) complexity proof: each element is pushed exactly once and popped exactly once → total operations are O(2n) = O(n), regardless of how many pops happen in the inner while loop.

### Stack vs. Recursion

Every recursive function implicitly uses a call stack. Any recursive algorithm can be reimplemented iteratively using an explicit stack. Iterative stack implementations avoid stack overflow for large inputs (deep recursion in JavaScript throws "Maximum call stack size exceeded") and often use less memory.

## Core Patterns / Techniques

### Pattern 1: Bracket Matching

```js
// Valid Parentheses: check if bracket sequence is properly nested
function isValid(s) {
  const matchFor = { ')': '(', ']': '[', '}': '{' };
  const stack = [];

  for (const ch of s) {
    if (!matchFor[ch]) {
      // Opening bracket — push it
      stack.push(ch);
    } else {
      // Closing bracket — must match top of stack
      if (stack.pop() !== matchFor[ch]) return false;
    }
  }
  return stack.length === 0; // all opened brackets were closed
}
// Time: O(n)  Space: O(n)
```

Extension: if the string can contain non-bracket characters, skip them with `continue`. If `*` can be `(`, `)`, or empty, use two stacks or a greedy range.

### Pattern 2: Next Greater Element

```js
// For each element, find the first element to its right that is greater.
// Returns -1 for elements with no next greater element.
function nextGreaterElement(nums) {
  const result = new Array(nums.length).fill(-1);
  const stack = []; // stores indices; maintained in decreasing value order

  for (let i = 0; i < nums.length; i++) {
    // All elements smaller than nums[i] have found their NGE
    while (stack.length && nums[stack[stack.length - 1]] < nums[i]) {
      const idx = stack.pop();
      result[idx] = nums[i];
    }
    stack.push(i);
  }
  // Remaining elements on the stack have no NGE → stay -1
  return result;
}
// Time: O(n)  Space: O(n)
```

For circular arrays (NGE wraps around), iterate `2n` times using `i % n` as the index, and only push in the first `n` iterations.

### Pattern 3: Daily Temperatures

```js
// For each day, how many days until a warmer temperature?
// This is "next greater element" with distance instead of value.
function dailyTemperatures(temperatures) {
  const result = new Array(temperatures.length).fill(0);
  const stack = []; // indices of unresolved days

  for (let i = 0; i < temperatures.length; i++) {
    while (stack.length && temperatures[stack[stack.length - 1]] < temperatures[i]) {
      const idx = stack.pop();
      result[idx] = i - idx; // days until warmer temperature
    }
    stack.push(i);
  }
  return result;
}
// Time: O(n)  Space: O(n)
```

### Pattern 4: Monotonic Stack for Histogram Area

```js
// Largest rectangle in a histogram: find the maximal rectangle area.
// Key insight: for each bar, find the nearest shorter bar on left and right.
function largestRectangleInHistogram(heights) {
  const stack = []; // indices of bars in increasing height order
  let maxArea = 0;

  // Add a sentinel bar of height 0 to flush all remaining bars at the end
  const h = [...heights, 0];

  for (let i = 0; i < h.length; i++) {
    // When current bar is shorter than top of stack, the top bar's
    // rectangle extends from stack[-2] to i (exclusive)
    while (stack.length && h[stack[stack.length - 1]] > h[i]) {
      const height = h[stack.pop()];
      const width = stack.length ? i - stack[stack.length - 1] - 1 : i;
      maxArea = Math.max(maxArea, height * width);
    }
    stack.push(i);
  }
  return maxArea;
}
// Time: O(n)  Space: O(n)
```

### Pattern 5: Evaluate Arithmetic Expressions

```js
// Basic calculator: evaluate string with +, -, (, )
function calculate(s) {
  const stack = [];
  let num = 0;
  let sign = 1; // +1 for positive, -1 for negative
  let result = 0;

  for (const ch of s) {
    if (ch >= '0' && ch <= '9') {
      num = num * 10 + Number(ch);
    } else if (ch === '+') {
      result += sign * num;
      num = 0;
      sign = 1;
    } else if (ch === '-') {
      result += sign * num;
      num = 0;
      sign = -1;
    } else if (ch === '(') {
      // Save current state, start fresh inside parentheses
      stack.push(result, sign);
      result = 0;
      sign = 1;
    } else if (ch === ')') {
      result += sign * num;
      num = 0;
      const outerSign = stack.pop();
      const outerResult = stack.pop();
      result = outerResult + outerSign * result;
    }
    // Ignore spaces
  }
  return result + sign * num;
}
// Time: O(n)  Space: O(n)
```

## Code Examples

### Example 1: Decode String with Nested Brackets

```js
/**
 * Decode a string like "3[a2[c]]" → "accaccacc"
 * Each k[encoded] means repeat encoded k times. Brackets can be nested.
 *
 * Approach: use two stacks — one for repeat counts, one for partial strings.
 * When we see '[', save state. When we see ']', pop and build.
 *
 * Time: O(n · maxK)   Space: O(n)
 */
function decodeString(s) {
  const countStack = []; // nesting-level repeat counts
  const strStack = [];   // partial strings being built at each nesting level
  let currentStr = '';
  let currentNum = 0;

  for (const ch of s) {
    if (ch >= '0' && ch <= '9') {
      // Accumulate multi-digit numbers
      currentNum = currentNum * 10 + Number(ch);
    } else if (ch === '[') {
      // Push current state and start fresh for the inner group
      countStack.push(currentNum);
      strStack.push(currentStr);
      currentNum = 0;
      currentStr = '';
    } else if (ch === ']') {
      // Pop and repeat the current group, append to the outer string
      const repeatCount = countStack.pop();
      const prevStr = strStack.pop();
      currentStr = prevStr + currentStr.repeat(repeatCount);
    } else {
      currentStr += ch;
    }
  }
  return currentStr;
}

console.log(decodeString('3[a]2[bc]'));   // 'aaabcbc'
console.log(decodeString('3[a2[c]]'));    // 'accaccacc'
console.log(decodeString('2[abc]3[cd]')); // 'abcabccdcdcd'
```

### Example 2: Stock Span (Monotonic Stack)

```js
/**
 * The stock span problem: for each day's price, the span is the number
 * of consecutive days (up to and including today) for which the price
 * was <= today's price.
 *
 * Equivalent to: 1 + number of days since the previous higher price.
 * This is "previous greater element" using a monotonic decreasing stack.
 *
 * Time: O(n) amortized   Space: O(n)
 */
class StockSpanner {
  constructor() {
    // Stack stores [price, span] pairs
    // Maintained in decreasing price order
    this.stack = [];
  }

  next(price) {
    let span = 1;
    // Accumulate spans from days with smaller or equal prices
    while (this.stack.length && this.stack[this.stack.length - 1][0] <= price) {
      span += this.stack.pop()[1];
    }
    this.stack.push([price, span]);
    return span;
  }
}

const spanner = new StockSpanner();
console.log(spanner.next(100)); // 1
console.log(spanner.next(80));  // 1
console.log(spanner.next(60));  // 1
console.log(spanner.next(70));  // 2  (70 >= 60)
console.log(spanner.next(60));  // 1
console.log(spanner.next(75));  // 4  (75 >= 60, 70, 60)
console.log(spanner.next(85));  // 6  (85 >= all of the above except 100)
```

## Best Practices

- **Use an explicit stack array with `.push()` and `.pop()`** — both are O(1) in JavaScript arrays. Avoid `.shift()` and `.unshift()` (O(n)) on your stack.
- **Push indices, not values, in monotonic stack problems** — you usually need both the position and the value, and storing the index lets you compute distances and access values.
- **Add sentinel values to simplify boundary handling** — in histogram problems, appending `0` to the array ensures all bars are flushed without separate post-loop logic.
- **Verify the empty-stack condition before every pop** — always check `stack.length > 0` (or `.length`) before calling `.pop()`. Popping an empty array in JavaScript returns `undefined`, which silently propagates errors.
- **Check `stack.length === 0` at the end for matching problems** — after processing the full string, an empty stack means all opens were closed. Any remaining open brackets mean the string is invalid.
- **Think about what "unresolved" means in your problem** — in NGE, "unresolved" means "hasn't found its next greater element yet." Make sure the stack invariant matches your definition of "unresolved."
- **Monotonic stacks run in O(n) even with the inner while loop** — don't be misled by the nested loop. Each element is pushed once and popped once, so total work is O(2n) = O(n).

## Common Interview Questions

**Q1: What data structure should you use for bracket matching, and why?**
A: A stack. When you encounter a closing bracket, the correct matching open bracket is the most recently opened one still waiting — that's exactly what the top of a LIFO stack stores.

**Q2: What is a monotonic stack and what problems does it solve?**
A: A monotonic stack maintains elements in strictly increasing or decreasing order. It solves "next/previous greater/smaller element" problems in O(n) by popping smaller elements when a larger one arrives — those popped elements have just found their "next greater element."

**Q3: What is the time complexity of the monotonic stack for "next greater element"?**
A: O(n), not O(n²). Despite the while loop, each element is pushed exactly once and popped at most once. Total operations = 2n → O(n).

**Q4: How would you use a stack to evaluate a mathematical expression with parentheses?**
A: Use a stack to save the (running total, sign) pair when entering a parenthesized group. When the group closes, pop the saved state and combine it with the group's result. Handles arbitrary nesting.

**Q5: How do you find the largest rectangle in a histogram in O(n)?**
A: Use a monotonic increasing stack of indices. When a shorter bar is encountered, the tallest bar on the stack has just found its right boundary. The left boundary is the index now at the top of the stack (after popping). Width = right - left - 1, area = height × width.

**Q6: What is the difference between a monotonic increasing and monotonic decreasing stack?**
A: Monotonic increasing (top = largest): pop when a smaller element arrives → finds next smaller element. Monotonic decreasing (top = smallest): pop when a larger element arrives → finds next greater element.

**Q7: How would you implement a min-stack (a stack that supports getMin() in O(1))?**
A: Maintain a second stack of minimums. Push the current minimum alongside each element. On push: new min = min(current min, new value). On pop: also pop from the min stack. `getMin()` returns the top of the min stack.

**Q8: When would you convert a recursive DFS to an iterative stack-based DFS?**
A: When the recursion depth could exceed the call stack limit (in JavaScript, ~10,000-15,000 calls). For example, a linked list of 100,000 nodes processed recursively will overflow. The iterative version uses an explicit stack and avoids this limit.

## Practice Exercises

**Exercise 1 — Valid Bracket Extensions (Beginner)**
Extend the bracket matching problem to handle wildcards: `*` can match `(`, `)`, or be empty. A string is valid if at least one assignment of `*` characters makes it a valid bracket sequence. Think carefully about what range of "open bracket counts" is reachable.
Hint: Track a range `[minOpen, maxOpen]` — the minimum and maximum possible count of unmatched open brackets. The string is valid if `minOpen === 0` at the end.

**Exercise 2 — Simplify Unix Path (Beginner-Intermediate)**
Given an absolute Unix-style file path (like `/home/user/../docs/./file`), simplify it to its canonical form. `..` means go up one directory, `.` means current directory, empty segments are ignored. A stack of directory names models the current path perfectly.
Hint: Split on `/`, push non-empty non-`.` segments, pop on `..`. Join with `/` at the end.

**Exercise 3 — Asteroid Collision (Intermediate)**
An array represents asteroids in a row; positive = moving right, negative = moving left. When two asteroids meet, the smaller explodes. If equal, both explode. Asteroids moving in the same direction never meet. Find the final state. Think carefully about when a collision occurs and who wins.
Hint: Use a stack. A collision only happens when the top of the stack is positive (moving right) and the new asteroid is negative (moving left). Keep resolving until no collision or the incoming asteroid is destroyed.

**Exercise 4 — Trapping Rain Water with Stack (Intermediate)**
Solve "trapping rain water" using a stack instead of two-pointer. The stack approach processes bars left-to-right and calculates water when it finds a taller bar. For each popped bar, the water height is `min(current bar, stack top) - popped bar` and the width is the distance between them. Implement this approach.
Hint: The stack holds indices of bars in non-increasing order. When `heights[i] > heights[stack top]`, the popped bar is the "floor" of the water pocket.

**Exercise 5 — Maximum Score from Removing Substrings (Advanced)**
Given a string and two substrings (`p1` with score s1, `p2` with score s2), repeatedly remove one occurrence of the higher-scoring substring, then the lower-scoring one, accumulating scores. A stack-based approach can process each string in O(n). The challenge is choosing the removal order correctly. Why should you always remove the higher-value substring first?
Hint: Use two passes: first pass uses a stack to remove all occurrences of the higher-value pair, second pass removes the lower-value pair from the remaining string.

## Key Takeaways

- Stacks (LIFO) are the natural choice when the answer for an element depends on the most recently unresolved earlier element.
- Bracket matching: push opens, verify-and-pop on closes, empty stack at end means valid.
- Monotonic stack: maintain sorted order by popping violators, enabling O(n) solutions for next/previous greater/smaller element problems.
- Monotonic stacks are O(n) total — each element is pushed once and popped at most once, despite the inner while loop.
- Store indices in the stack (not values) when you need position information to compute distances or array ranges.
- Sentinel values (like appending `0` to a histogram) simplify post-loop cleanup.
- Any recursion can be converted to an iterative stack — useful for avoiding stack overflow on large inputs.
- The pattern extends to: histogram area, stock span, expression evaluation, path simplification, and asteroid collision.
