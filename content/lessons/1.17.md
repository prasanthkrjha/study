# 2-D Dynamic Programming

Two-dimensional DP extends the same core idea as 1-D DP — store and reuse subproblem results — to problems where the state requires two independent variables to describe "where you are" in the computation. The most common configurations are two positions in two different strings (LCS, edit distance), or a position and a capacity/weight (knapsack), or row and column indices in a grid (path counting). The transition from 1-D to 2-D is conceptual, not mechanical: you trade a 1-D array for a 2-D table, but the four-step framework (define state, write recurrence, establish base cases, decide fill order) is identical.

The practical challenge of 2-D DP is that the state space — and therefore the table — grows as the product of the two state dimensions. A problem over two strings of length m and n has O(m×n) states; a knapsack over n items with capacity W has O(n×W) states. This means you need to be careful about both time and space: O(m×n) time is fine for strings up to a few thousand characters, but O(n×W) can be problematic if W is large (up to 10⁶ in some problems). Space optimization by keeping only the current and previous row of the DP table is a frequently useful technique.

Understanding the shape of these recurrences — and recognizing which shape applies to a given problem — is the main skill being developed here. Grid paths, two-sequence comparisons, and subset-selection with a budget are three distinct shapes, each with its own recurrence form. A problem that looks unfamiliar often maps cleanly onto one of these shapes once the state definition is worked out.

## Theory & Fundamentals

### When to use 2-D DP

The clearest signal is that you need two indices to describe "where you are":
- Comparing two sequences character by character → `dp[i][j]` = answer for first i chars of string 1 and first j chars of string 2.
- Moving through a grid → `dp[r][c]` = answer when at row r, column c.
- Choosing items under a constraint → `dp[i][w]` = answer using the first i items with budget w.

If you try to define `dp[i]` but find that knowing i is not enough — you also need to know how far along you are in a second dimension — you're in 2-D DP territory.

### Fill order and dependencies

For all standard 2-D DP problems:
- Grid paths and sequence comparisons: fill row by row, left to right (cell depends on left, above, or upper-left neighbor).
- Knapsack: fill items in order; for each item, iterate over capacities. Can be done with two 1-D arrays (or one, with a backward loop to prevent reuse of the same item).

The fill order must respect dependencies: compute all cells that a cell depends on before computing that cell.

### Space optimization

Most 2-D DP tables only use the current and previous row:
- LCS and edit distance: `dp[i][j]` depends on `dp[i-1][j-1]`, `dp[i-1][j]`, and `dp[i][j-1]` — keep two rows.
- Knapsack: `dp[i][w]` depends on `dp[i-1][w]` and `dp[i-1][w - weight[i]]` — keep one row, iterate w **backwards** to avoid using the same item twice.

Grid paths: `dp[r][c]` depends on `dp[r-1][c]` and `dp[r][c-1]` — keep one row.

### Common 2-D DP problems and their shapes

| Problem | State | Recurrence key |
|---|---|---|
| Grid paths | `dp[r][c]` = paths to (r,c) | `dp[r][c] = dp[r-1][c] + dp[r][c-1]` |
| LCS | `dp[i][j]` = LCS of first i, j chars | Match → extend diagonal; else max(up, left) |
| Edit distance | `dp[i][j]` = edits to convert | Match → diagonal; else 1 + min(3 neighbors) |
| 0/1 Knapsack | `dp[i][w]` = max value, i items, cap w | Skip item or take it if it fits |
| Coin change (2D count) | `dp[i][a]` = ways using first i coins | Use coin or skip it |

## Core Patterns / Techniques

### Pattern 1: Grid paths with obstacles

```js
// Count paths from top-left to bottom-right, right/down only, avoiding obstacles
function uniquePathsWithObstacles(grid) {
  const m = grid.length, n = grid[0].length;
  const dp = new Array(n).fill(0);
  dp[0] = grid[0][0] === 0 ? 1 : 0; // starting cell is blocked → 0 paths

  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (grid[r][c] === 1) {
        dp[c] = 0; // obstacle: no paths reach this cell
      } else if (c > 0) {
        dp[c] += dp[c - 1]; // dp[c] = "from above" (unchanged) + "from left" (dp[c-1])
      }
    }
  }
  return dp[n - 1];
}
```

### Pattern 2: Longest common subsequence

```js
// dp[i][j] = LCS of text1[0..i-1] and text2[0..j-1]
function lcs(text1, text2) {
  const m = text1.length, n = text2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (text1[i - 1] === text2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1; // characters match — extend diagonal
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]); // drop one char from either
      }
    }
  }
  return dp[m][n];
}
```

### Pattern 3: Edit distance (Levenshtein)

```js
// dp[i][j] = min edits to convert word1[0..i-1] to word2[0..j-1]
// Three operations: insert, delete, substitute (each costs 1)
function editDistance(word1, word2) {
  const m = word1.length, n = word2.length;
  const dp = Array.from({ length: m + 1 }, (_, i) =>
    Array.from({ length: n + 1 }, (_, j) => i === 0 ? j : j === 0 ? i : 0)
  );
  // Base: dp[i][0] = i (delete i chars), dp[0][j] = j (insert j chars)

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1]; // no edit needed
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i - 1][j - 1], // substitute
          dp[i - 1][j],     // delete from word1
          dp[i][j - 1]      // insert into word1
        );
      }
    }
  }
  return dp[m][n];
}
```

### Pattern 4: 0/1 Knapsack

```js
// dp[i][w] = max value from first i items with weight capacity w
function knapsack(weights, values, capacity) {
  const n = weights.length;
  // Space-optimized: single 1-D array, iterate capacity backwards
  const dp = new Array(capacity + 1).fill(0);

  for (let i = 0; i < n; i++) {
    // Iterate capacity backwards to prevent using item i more than once
    for (let w = capacity; w >= weights[i]; w--) {
      dp[w] = Math.max(dp[w], dp[w - weights[i]] + values[i]);
    }
  }
  return dp[capacity];
}
```

## Code Examples

### Example 1: Longest common subsequence with backtracking to recover the sequence

```js
/**
 * Find the length AND the actual longest common subsequence of two strings.
 *
 * Phase 1: Fill dp table (standard LCS).
 * Phase 2: Backtrack from dp[m][n] to reconstruct the sequence.
 *   - If characters match, go diagonally up-left and include the character.
 *   - If dp[i-1][j] > dp[i][j-1], go up (drop from text1).
 *   - Else go left (drop from text2).
 *
 * Time: O(m * n), Space: O(m * n)
 */
function lcsWithSequence(text1, text2) {
  const m = text1.length, n = text2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      dp[i][j] = text1[i-1] === text2[j-1]
        ? dp[i-1][j-1] + 1
        : Math.max(dp[i-1][j], dp[i][j-1]);
    }
  }

  // Backtrack to recover the actual subsequence
  const result = [];
  let i = m, j = n;
  while (i > 0 && j > 0) {
    if (text1[i-1] === text2[j-1]) {
      result.push(text1[i-1]); // this character is part of the LCS
      i--; j--;
    } else if (dp[i-1][j] > dp[i][j-1]) {
      i--; // go up
    } else {
      j--; // go left
    }
  }

  return {
    length: dp[m][n],
    sequence: result.reverse().join('')
  };
}

console.log(lcsWithSequence('abcde', 'ace'));
// { length: 3, sequence: 'ace' }

console.log(lcsWithSequence('AGGTAB', 'GXTXAYB'));
// { length: 4, sequence: 'GTAB' }
```

### Example 2: Minimum path sum in a grid

```js
/**
 * Given an m×n grid of non-negative integers, find a path from
 * top-left to bottom-right (only right or down moves) that minimizes
 * the sum of all numbers along the path.
 *
 * State: dp[r][c] = minimum cost to reach cell (r, c).
 * Recurrence: dp[r][c] = grid[r][c] + min(dp[r-1][c], dp[r][c-1])
 * Base: first row and column can only be reached by going straight.
 *
 * Space-optimized to O(n) by keeping only one row.
 * Time: O(m * n)
 */
function minPathSum(grid) {
  const m = grid.length, n = grid[0].length;
  const dp = new Array(n).fill(0);

  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (r === 0 && c === 0) {
        dp[c] = grid[0][0]; // starting cell
      } else if (r === 0) {
        dp[c] = dp[c - 1] + grid[r][c]; // first row: only from left
      } else if (c === 0) {
        dp[c] = dp[c] + grid[r][c];     // first col: only from above (dp[c] = prev row)
      } else {
        dp[c] = Math.min(dp[c], dp[c - 1]) + grid[r][c]; // min of above and left
      }
    }
  }

  return dp[n - 1];
}

const grid = [
  [1, 3, 1],
  [1, 5, 1],
  [4, 2, 1]
];
console.log(minPathSum(grid)); // 7: path 1→3→1→1→1
```

## Best Practices

- **Define `dp[i][j]` in precise words before writing code.** "dp[i][j] = the length of the longest common subsequence of the first i characters of text1 and the first j characters of text2" makes the recurrence obvious. Vague state definitions produce bugs.
- **Pad strings/arrays by 1 for cleaner base cases.** Using `dp[0][j] = 0` as the "empty string" base case avoids special-casing the first row/column in your loops.
- **Distinguish LCS from edit distance recurrences.** They look similar but differ in the mismatch case: LCS takes `max(up, left)`; edit distance takes `1 + min(diagonal, up, left)`. Confusing these is a common mistake.
- **For 0/1 knapsack space optimization, iterate capacity backwards.** If you iterate forwards, `dp[w - weight]` may already reflect the current item being included, meaning you'd use the same item twice. Backwards iteration ensures you use the previous row's values.
- **Space-optimize only after confirming correctness.** Start with the full 2-D table, verify your solution is correct on a few examples, then optimize. Debugging space-optimized DP is much harder.
- **When recovering the actual sequence (not just the length), keep the full table.** Space optimization loses the information needed for backtracking. Decide upfront whether you need the sequence or just its length.
- **Coin change II (count ways) vs. coin change I (min coins) have different initializations.** For counting ways: `dp[0] = 1` (one way to make 0). For minimum coins: `dp[0] = 0`, `dp[1..amount] = Infinity`. Swapping these gives wrong results.

## Common Interview Questions

**Q1: What is the state definition and recurrence for edit distance?**

A: `dp[i][j]` = minimum number of operations (insert, delete, substitute) to convert `word1[0..i-1]` to `word2[0..j-1]`. If characters match: `dp[i][j] = dp[i-1][j-1]`. If not: `dp[i][j] = 1 + min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1])` for substitute, delete, and insert respectively.

**Q2: What are the base cases for LCS?**

A: `dp[i][0] = 0` for all i (LCS of any string with an empty string is 0) and `dp[0][j] = 0` for all j (same reason). These are automatically set if you initialize the table to zeros.

**Q3: How does 0/1 knapsack differ from unbounded knapsack (coin change)?**

A: In 0/1 knapsack, each item can be used at most once. In unbounded knapsack (like coin change), each item can be reused. For 0/1, the space-optimized DP iterates capacity backwards to prevent reusing an item. For unbounded, capacity iterates forwards because reuse is allowed.

**Q4: What is the time and space complexity of LCS on two strings of length m and n?**

A: Time: O(m×n) — fill every cell of the m+1 by n+1 table once. Space: O(m×n) for the full table, or O(min(m,n)) with space optimization (keep only two rows). Backtracking to recover the sequence requires the full O(m×n) table.

**Q5: Why does the grid path problem have all 1s in the first row and column?**

A: There is exactly one way to reach any cell in the first row: move right from the start along the top edge. Similarly, one way for every cell in the first column: move down from the start. These are the base cases that subsequent cells build on. An obstacle in the first row/column cuts off everything past it (sets those cells to 0).

**Q6: How do you approach a problem that asks for the number of distinct ways to make a sum using coins (each usable multiple times)?**

A: Use 2-D DP (or 1-D with a forward loop). `dp[i][a]` = number of ways to reach amount `a` using the first `i` coin types. Recurrence: either don't use coin i (`dp[i-1][a]`) or use it if it fits (`dp[i][a - coin_i]`). Use coin type i again by referring to `dp[i][...]` not `dp[i-1][...]`. Initialize `dp[*][0] = 1`.

**Q7: What is the difference between LCS and the longest common substring?**

A: LCS (subsequence) allows skipping characters — the characters must appear in order but need not be contiguous. Longest common substring requires contiguous characters. The LCS recurrence on mismatch takes `max(up, left)` and "remembers" past characters. The substring recurrence resets to 0 on mismatch: `dp[i][j] = match ? dp[i-1][j-1] + 1 : 0`.

**Q8: How do you recover the actual path in a minimum-path-sum grid problem?**

A: During the DP forward pass, record which direction (from above or from the left) gave the minimum at each cell in a separate `parent` array. After finding `dp[m-1][n-1]`, trace back from the bottom-right cell to the top-left via the parent pointers, then reverse the path.

## Practice Exercises

**Exercise 1 — Unique Paths (Easy)**
A robot starts at the top-left of an m×n grid and wants to reach the bottom-right. It can only move right or down. How many unique paths are there?
Hint: `dp[r][c] = dp[r-1][c] + dp[r][c-1]`. First row and column are all 1s. This can be solved in O(n) space with a single 1-D array.

**Exercise 2 — Interleaving String (Medium)**
Given strings s1, s2, and s3, determine if s3 is formed by an interleaving of s1 and s2 (the relative order of characters from each string is preserved).
Hint: `dp[i][j]` = true if `s3[0..i+j-1]` can be formed from `s1[0..i-1]` and `s2[0..j-1]`. Recurrence: dp[i][j] = (dp[i-1][j] && s1[i-1]===s3[i+j-1]) || (dp[i][j-1] && s2[j-1]===s3[i+j-1]).

**Exercise 3 — Coin Change II (Medium)**
Given an amount and a list of coin denominations (unlimited use), find the number of distinct combinations of coins that sum to the amount.
Hint: `dp[a]` = number of ways to form amount `a`. For each coin, iterate amounts forward: `dp[a] += dp[a - coin]`. Initialize `dp[0] = 1`. Process one coin denomination at a time (outer loop) to avoid counting permutations as distinct.

**Exercise 4 — Regular Expression Matching (Hard)**
Implement regular expression matching with `.` (matches any single character) and `*` (matches zero or more of the preceding element). The function should return whether the pattern matches the entire string.
Hint: `dp[i][j]` = true if `s[0..i-1]` matches `p[0..j-1]`. Key case: if `p[j-1]` is `'*'`, it can match zero occurrences (`dp[i][j-2]`) or one-plus occurrences if `p[j-2]` matches `s[i-1]` (`dp[i-1][j]`).

**Exercise 5 — Burst Balloons (Hard)**
Given n balloons with values, you burst them one at a time. When you burst balloon i, you gain coins equal to `nums[i-1] * nums[i] * nums[i+1]` (treating out-of-bounds as 1). Find the maximum coins obtainable by bursting all balloons.
Hint: Think in reverse — rather than choosing which balloon to burst first, choose which balloon to burst **last** in each range. `dp[left][right]` = max coins from the subarray between left and right (exclusive, with virtual 1s at boundaries). For each k in (left, right), `dp[left][right] = max(dp[left][k] + nums[left]*nums[k]*nums[right] + dp[k][right])`.

## Key Takeaways

- 2-D DP applies when the problem state requires two indices: two positions in two sequences, or a position plus a budget/capacity.
- The four-step framework (define state, write recurrence, establish base cases, determine fill order) is identical to 1-D DP — only the table dimension changes.
- LCS and edit distance share the same table shape but differ in the mismatch case: LCS takes `max(up, left)`; edit distance takes `1 + min(diagonal, up, left)`.
- 0/1 knapsack iterates capacity backwards for space optimization; unbounded knapsack (coin change) iterates forwards.
- Grid problems (path counting, minimum sum path) reduce to a single row of DP by overwriting column by column, achieving O(n) space.
- Always define your state in precise words first — vague state definitions produce bugs that are hard to diagnose.
- Recovering the actual sequence (not just its length) requires keeping the full table; space optimization is incompatible with backtracking.
- Burst Balloons is a classic hard problem that requires reframing from "which to pop first" to "which to pop last" — the interval DP pattern that converts O(n³) thinking into correct recurrences.
