# 2-D Dynamic Programming

Same core idea as 1-D DP, except state now depends on **two** changing quantities — two positions in a grid, or a position in each of two strings/sequences. The `dp` structure becomes a 2D table instead of a 1D array.

## Grid paths

Counting paths from top-left to bottom-right of a grid, moving only right or down: each cell's answer is the sum of the cell above and the cell to the left, since those are the only two ways to arrive.

```js
function uniquePaths(m, n) {
  const dp = Array.from({ length: m }, () => new Array(n).fill(1));
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      dp[r][c] = dp[r - 1][c] + dp[r][c - 1];
    }
  }
  return dp[m - 1][n - 1];
}
```

The first row and column are all 1s (only one way to reach them: keep going straight) — that's the base case.

## Longest common subsequence (LCS)

`dp[i][j]` = length of the LCS of `text1[0..i)` and `text2[0..j)`. If the current characters match, extend the diagonal; otherwise take the best of dropping one character from either string:

```js
function longestCommonSubsequence(text1, text2) {
  const m = text1.length, n = text2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      dp[i][j] = text1[i - 1] === text2[j - 1]
        ? dp[i - 1][j - 1] + 1
        : Math.max(dp[i - 1][j], dp[i][j - 1]);
    }
  }
  return dp[m][n];
}
```

## Edit distance

Minimum insertions/deletions/substitutions to turn one string into another — same table shape as LCS, but every mismatch costs 1 and you take the min of three neighbors (insert, delete, substitute) instead of two:

```js
function editDistance(word1, word2) {
  const m = word1.length, n = word2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      dp[i][j] = word1[i - 1] === word2[j - 1]
        ? dp[i - 1][j - 1]
        : 1 + Math.min(dp[i - 1][j - 1], dp[i - 1][j], dp[i][j - 1]);
    }
  }
  return dp[m][n];
}
```

## 0/1 Knapsack

Maximize value within a weight limit, each item usable at most once. `dp[i][w]` = best value using the first `i` items with capacity `w`. For each item, either skip it (`dp[i-1][w]`) or take it if it fits (`dp[i-1][w-weight] + value`):

```js
function knapsack(weights, values, capacity) {
  const n = weights.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(capacity + 1).fill(0));
  for (let i = 1; i <= n; i++) {
    for (let w = 0; w <= capacity; w++) {
      dp[i][w] = dp[i - 1][w]; // skip item i
      if (weights[i - 1] <= w) {
        dp[i][w] = Math.max(dp[i][w], dp[i - 1][w - weights[i - 1]] + values[i - 1]);
      }
    }
  }
  return dp[n][capacity];
}
```

This is exactly the problem where greedy (sort by value/weight ratio) fails — see the Greedy unit for why.

## Recognizing the pattern

Two strings being compared → LCS/edit-distance shape. A grid with movement constraints → grid-path shape. "Choose a subset under a capacity constraint, each item used once" → knapsack shape. If your state needs two indices to describe "where you are" in the problem, you're in 2-D DP territory.
