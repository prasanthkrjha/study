# Backtracking

Backtracking is a systematic search technique for problems that require exploring all possible configurations of a solution. The key insight is that you build a candidate solution incrementally — one decision at a time — and the moment that partial solution violates a constraint and can't possibly be completed into a valid answer, you immediately undo the last decision ("backtrack") and try the next option. This prunes the search tree at the earliest opportunity instead of fully building every candidate before checking it.

The mental model is a decision tree. Each level of the tree represents one choice; each branch represents one option for that choice. A path from root to leaf is one complete candidate. Backtracking is DFS on this decision tree, but with early termination: if you're at a node where no valid completion exists, you cut off the entire subtree below it. Without pruning, you would explore every leaf; with good pruning, you may cut the explored tree to a fraction of its theoretical size.

Backtracking is the right tool when a problem asks for all valid configurations — every subset, every permutation, every board arrangement. It is not the right tool when the problem asks for a single optimal value (that's usually greedy or dynamic programming), because backtracking's cost is proportional to the total number of valid and partially-explored configurations, which grows exponentially with the input size.

## Theory & Fundamentals

### The backtracking template

Every backtracking solution follows the same three-step cycle inside a recursive function:

1. **Choose:** Pick the next option and add it to the current path.
2. **Explore:** Recursively solve the rest of the problem with that choice made.
3. **Un-choose:** Remove the choice from the current path, restoring state for the next option.

The "un-choose" step is the whole idea — you are reusing the same path array across all branches. Not restoring state is the most common backtracking bug.

```js
function backtrack(path, start, choices, results) {
  // Base case: a complete solution has been built
  if (isComplete(path)) {
    results.push([...path]); // always push a COPY — path is mutated later
    return;
  }

  for (let i = start; i < choices.length; i++) {
    if (!isValid(choices[i], path)) continue; // pruning: skip invalid choices early

    path.push(choices[i]);                    // choose
    backtrack(path, i + 1, choices, results); // explore
    path.pop();                               // un-choose
  }
}
```

### State space complexity

For n elements:
- Subsets: 2ⁿ (each element is in or out) → O(n · 2ⁿ) total work (copying each result takes O(n))
- Permutations: n! arrangements → O(n · n!) total work
- Combinations of size k: C(n,k) results

These are exponential. Backtracking is not polynomial — it is only tractable because real problems usually have constraints that prune large portions of the tree.

### Pruning strategies

- **Validity check before recursing:** Check constraints immediately after making a choice, before exploring further. The earlier you detect an invalid state, the more subtree you skip.
- **Forward checking:** Before choosing, verify that a valid completion is still possible (useful in constraint satisfaction problems like N-Queens or Sudoku).
- **Symmetry elimination:** For subsets, always iterate forward (i starts at `start`, not 0) to avoid generating duplicate subsets in different orders.
- **Duplicate handling:** If the input has duplicate values, sort first and skip consecutive duplicates at the same recursion level to avoid duplicate results.

## Core Patterns / Techniques

### Pattern 1: Subsets (each element in or out)

```js
function subsets(nums) {
  const results = [];

  function backtrack(start, path) {
    results.push([...path]); // every prefix is a valid subset (including empty)

    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);        // choose nums[i]
      backtrack(i + 1, path);   // explore: only consider elements after i
      path.pop();                // un-choose
    }
  }

  backtrack(0, []);
  return results;
}
// subsets([1,2,3]) → [[], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]]
```

### Pattern 2: Permutations (all orderings)

```js
function permute(nums) {
  const results = [];
  const used = new Array(nums.length).fill(false);

  function backtrack(path) {
    if (path.length === nums.length) {
      results.push([...path]);
      return;
    }
    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;      // skip already-used elements
      used[i] = true;
      path.push(nums[i]);
      backtrack(path);
      path.pop();
      used[i] = false;
    }
  }

  backtrack([]);
  return results;
}
```

### Pattern 3: Combinations of size k

```js
function combine(n, k) {
  const results = [];

  function backtrack(start, path) {
    if (path.length === k) {        // base case: combination is complete
      results.push([...path]);
      return;
    }
    // Pruning: if remaining elements can't fill the combination, stop early
    const remaining = k - path.length;
    for (let i = start; i <= n - remaining + 1; i++) {
      path.push(i);
      backtrack(i + 1, path);
      path.pop();
    }
  }

  backtrack(1, []);
  return results;
}
```

### Pattern 4: Constraint satisfaction (N-Queens)

```js
function solveNQueens(n) {
  const results = [];
  // Track which columns and diagonals are occupied
  const cols = new Set();
  const diag1 = new Set(); // row - col is constant on "\" diagonals
  const diag2 = new Set(); // row + col is constant on "/" diagonals

  function backtrack(row, board) {
    if (row === n) {
      results.push(board.map(cols => {
        const row = Array(n).fill('.');
        row[cols] = 'Q';
        return row.join('');
      }));
      return;
    }
    for (let col = 0; col < n; col++) {
      if (cols.has(col) || diag1.has(row - col) || diag2.has(row + col)) continue;
      // Choose
      cols.add(col); diag1.add(row - col); diag2.add(row + col);
      board.push(col);
      // Explore
      backtrack(row + 1, board);
      // Un-choose
      board.pop();
      cols.delete(col); diag1.delete(row - col); diag2.delete(row + col);
    }
  }

  backtrack(0, []);
  return results;
}
```

## Code Examples

### Example 1: Combination sum (elements reusable, target sum)

```js
/**
 * Find all combinations of candidates that sum to target.
 * Each candidate may be used an unlimited number of times.
 * Input: candidates = [2, 3, 6, 7], target = 7
 * Output: [[2,2,3], [7]]
 */
function combinationSum(candidates, target) {
  const results = [];
  candidates.sort((a, b) => a - b); // sort to enable early termination

  function backtrack(start, path, remaining) {
    if (remaining === 0) {
      results.push([...path]); // exact match found
      return;
    }

    for (let i = start; i < candidates.length; i++) {
      const c = candidates[i];
      if (c > remaining) break; // sorted: no point checking larger candidates

      path.push(c);
      backtrack(i, path, remaining - c); // i (not i+1) because reuse is allowed
      path.pop();
    }
  }

  backtrack(0, [], target);
  return results;
}

console.log(combinationSum([2, 3, 6, 7], 7));
// [[2, 2, 3], [7]]
```

### Example 2: Word search in a grid

```js
/**
 * Given a 2D grid of characters, find if a word exists as a connected
 * sequence of adjacent cells (horizontal or vertical, no reuse).
 * Classic DFS + backtracking on a matrix.
 */
function exist(board, word) {
  const rows = board.length;
  const cols = board[0].length;

  function dfs(r, c, idx) {
    if (idx === word.length) return true;  // all characters matched
    if (r < 0 || r >= rows || c < 0 || c >= cols) return false;
    if (board[r][c] !== word[idx]) return false;

    // Mark visited in place (avoids a separate visited array)
    const temp = board[r][c];
    board[r][c] = '#';

    // Explore all 4 directions
    const found = dfs(r+1,c,idx+1) || dfs(r-1,c,idx+1) ||
                  dfs(r,c+1,idx+1) || dfs(r,c-1,idx+1);

    board[r][c] = temp; // un-choose: restore the cell
    return found;
  }

  // Try starting the search from every cell
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (dfs(r, c, 0)) return true;
    }
  }
  return false;
}

const board = [
  ['A','B','C','E'],
  ['S','F','C','S'],
  ['A','D','E','E']
];
console.log(exist(board, 'ABCCED')); // true
console.log(exist(board, 'SEE'));    // true
console.log(exist(board, 'ABCB'));   // false
```

## Best Practices

- **Always push a copy of path, never the reference.** `results.push([...path])` — if you push `path` directly, all result entries will point to the same (eventually empty) array.
- **Sort input before backtracking when duplicates are present.** Then skip `candidates[i] === candidates[i-1]` at the same recursion level to prevent duplicate results without a hash set.
- **Use incremental constraint checking, not post-hoc validation.** Check if adding a choice is valid before recursing, not after building a full candidate. Every invalid partial state you prune eliminates an entire subtree.
- **In-place marking is faster than a separate `visited` set for grid problems.** Temporarily overwrite the cell with a sentinel (e.g., `'#'`) and restore it after backtracking. This saves memory and avoids hash set overhead.
- **The `start` parameter prevents re-use of earlier elements in subset/combination problems.** Always pass `i + 1` (or `i` if reuse is allowed) to the next recursive call, not `0`.
- **Backtracking is for enumeration; use DP when you only need a count or optimal value.** If the problem asks "how many combinations" rather than "what are all combinations," DP is likely faster.
- **Measure pruning effectiveness when optimizing.** If your solution times out, look for places to add early exits — can you determine sooner that the current path cannot lead to a valid solution?

## Common Interview Questions

**Q1: What is the difference between backtracking and brute force?**

A: Brute force generates all candidates and then filters. Backtracking abandons a candidate as soon as a constraint is violated, without generating all of its extensions. In practice, backtracking is brute force with early termination — the search space explored is often much smaller, but worst-case is the same.

**Q2: Why do we pass `i + 1` (not `start + 1`) as the next start index in the subsets problem?**

A: We use `i + 1` to start the next recursive call from the element after the one just chosen. `i` is the current position we just committed to, and we want subsequent choices to only look ahead, preventing duplicate subsets like `[1, 2]` and `[2, 1]`.

**Q3: How do you handle duplicate elements in a permutation problem?**

A: Sort the input array first. In the main loop, skip `nums[i]` if `i > 0 && nums[i] === nums[i-1] && !used[i-1]`. The condition `!used[i-1]` ensures we only skip the current element when its twin appeared at the same recursive level (not in an ancestor call).

**Q4: What makes N-Queens different from subset/permutation problems?**

A: N-Queens is a constraint satisfaction problem (CSP) with non-trivial validity checks: a queen must not share a column or diagonal with any previously placed queen. The constraint check occurs before each recursive call, making pruning the central technique. Each row has exactly one queen, so the decision at each level is "which column?", not "include or exclude".

**Q5: When should you use backtracking versus dynamic programming?**

A: Use backtracking when the problem asks for all valid configurations (enumeration). Use DP when it asks for a single optimal value or count. Backtracking explores exponential configurations; DP avoids recomputing overlapping subproblems and runs in polynomial time. If you can reduce a problem to "find the optimal value," prefer DP.

**Q6: What is the time complexity of generating all permutations of n elements?**

A: O(n! × n). There are n! permutations and copying each to the results list takes O(n), giving O(n × n!) total. The backtracking tree itself has n! leaves and n × n! total nodes.

**Q7: How do you solve Sudoku using backtracking?**

A: Try placing each digit 1-9 in the first empty cell. Before placing, check that the digit doesn't already appear in the same row, column, or 3×3 box. If valid, place it and recurse to the next empty cell. If any conflict is found or all later cells fail, reset the cell and try the next digit. Return true when all cells are filled.

**Q8: Can backtracking be iterative instead of recursive?**

A: Yes. The call stack can be simulated with an explicit stack, storing (path, start, choices) tuples. However, recursive implementations are far more readable and are almost always used in interviews. The "un-choose" step maps cleanly to actions taken after returning from a recursive call.

## Practice Exercises

**Exercise 1 — Phone Number Letter Combinations (Medium)**
Given a string of digits (2-9), return all possible letter combinations using a phone keypad mapping (2 → "abc", 3 → "def", etc.). An empty input returns an empty list.
Hint: At each level of recursion, one digit is resolved. The number of levels equals the number of digits in the input.

**Exercise 2 — Palindrome Partitioning (Medium)**
Given a string s, partition it such that every substring of the partition is a palindrome. Return all possible palindrome partitioning.
Hint: At each position, try cutting the string at every valid endpoint. Before recursing, check if the current substring is a palindrome. A precomputed 2D boolean table (DP) can speed up palindrome checks from O(n) each to O(1).

**Exercise 3 — Restore IP Addresses (Medium)**
Given a string of digits, return all valid IPv4 addresses that can be formed by inserting exactly three dots. Each segment must be between 0 and 255, and no segment may have leading zeros unless it is exactly "0".
Hint: Use backtracking with 4 segments to fill. At each step, try 1, 2, and 3-digit substrings. Validate before recursing.

**Exercise 4 — Expression Add Operators (Hard)**
Given a string of digits and a target integer, return all expressions formed by inserting `+`, `-`, or `*` between the digits (without leading zeros in any number) that evaluate to the target.
Hint: Track the current evaluation value and the value of the last term (needed to "undo" its contribution when applying multiplication). This requires careful integer arithmetic — no `eval`.

**Exercise 5 — Sudoku Solver (Hard)**
Write a function that fills in the empty cells of a 9×9 Sudoku board (partially filled with digits 1-9 and dots for empty cells). The solution must satisfy all standard Sudoku rules: each digit appears exactly once per row, column, and 3×3 box.
Hint: Find the first empty cell. Try each digit 1-9, checking all three constraints before placing. Recurse; if no digit leads to a solution, backtrack by clearing the cell.

## Key Takeaways

- Backtracking is DFS on a decision tree with early pruning — it enumerates all valid configurations by trying each option and immediately abandoning paths that violate constraints.
- The three-step cycle is universal: **choose, explore, un-choose**. The un-choose step restores state and is what makes the recursion correct.
- Always push a **copy** of the current path to the results list, not the path itself.
- Sort input when duplicates are present and skip consecutive equal elements at the same recursion level to avoid duplicate results.
- Pruning is the lever for performance: the earlier you detect an invalid state, the more subtrees you skip. Measure whether constraints are being checked as early as possible.
- Grid problems (word search, maze solving) use in-place marking with restoration as the "un-choose" step, avoiding a separate visited set.
- Backtracking is exponential by nature — use DP when the problem only asks for a count or optimal value, not all configurations.
- N-Queens and Sudoku are the canonical constraint satisfaction examples; understand how auxiliary data structures (column sets, diagonal sets) make constraint checks O(1) per candidate.
