# Backtracking

Backtracking is systematic trial-and-error: build a candidate solution incrementally, and the moment it can't possibly succeed, undo the last choice and try the next one. It's how you enumerate **all** valid configurations — subsets, permutations, combinations, or board arrangements — without missing any or duplicating work.

## The template

Every backtracking solution follows the same shape:

```js
function backtrack(path, choices) {
  if (isComplete(path)) {
    results.push([...path]); // record a copy, not the mutable reference
    return;
  }
  for (const choice of choices) {
    if (!isValid(choice, path)) continue;
    path.push(choice);        // choose
    backtrack(path, remainingChoices(choices, choice));
    path.pop();                // un-choose — this is the "backtrack" step
  }
}
```

The `path.pop()` after the recursive call is the entire idea: you're reusing the same array/state across all branches instead of allocating new copies, which keeps space usage down to the depth of recursion.

## Subsets

Every element is either "in" or "out" — this naturally forms a binary decision tree of depth `n`:

```js
function subsets(nums) {
  const results = [];
  function go(start, path) {
    results.push([...path]);
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);
      go(i + 1, path); // i + 1, not start + 1 — never reuse the same index
      path.pop();
    }
  }
  go(0, []);
  return results;
}
```

## Permutations

Unlike subsets, order matters and every element must be used — track which indices are already placed:

```js
function permute(nums) {
  const results = [];
  const used = new Array(nums.length).fill(false);
  function go(path) {
    if (path.length === nums.length) { results.push([...path]); return; }
    for (let i = 0; i < nums.length; i++) {
      if (used[i]) continue;
      used[i] = true;
      path.push(nums[i]);
      go(path);
      path.pop();
      used[i] = false;
    }
  }
  go([]);
  return results;
}
```

## Combinations & constraint satisfaction (N-Queens style)

Combinations are subsets of a fixed size — same skeleton as `subsets`, with a length check added to the base case. N-Queens-style problems add a **validity check** before each choice (does placing a queen here conflict with any queen already placed?) — this is where "pruning" pays off: reject a bad choice as early as possible instead of building out the whole invalid branch first.

## Recognizing the pattern

Phrases like "all possible," "every combination," "every arrangement," or "find all ways to..." are the giveaway. If the problem wants *one* optimal answer rather than *all* answers, you likely want dynamic programming or greedy instead — backtracking's cost is proportional to the number of valid (and attempted-but-rejected) configurations, which is fine for enumeration but often too slow for pure optimization.
