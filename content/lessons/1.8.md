# Trees

Trees are recursive by nature, so the biggest unlock in this unit is trusting recursion: assume the function already works correctly on subtrees, and write the combining step.

## DFS traversals: preorder, inorder, postorder

```js
function preorder(node, out = []) {
  if (!node) return out;
  out.push(node.val);      // visit
  preorder(node.left, out);
  preorder(node.right, out);
  return out;
}
```

- **Preorder** (visit → left → right): good for copying/serializing a tree.
- **Inorder** (left → visit → right): visits a **BST** in sorted order — this is the single most useful fact in this unit.
- **Postorder** (left → right → visit): good when children must be fully processed before the parent (computing subtree sizes, deleting a tree, evaluating an expression tree).

## BFS / level order

Level order needs a queue, not recursion, since you're processing the tree breadth-first:

```js
function levelOrder(root) {
  if (!root) return [];
  const result = [];
  let queue = [root];
  while (queue.length) {
    const level = [];
    const next = [];
    for (const node of queue) {
      level.push(node.val);
      if (node.left) next.push(node.left);
      if (node.right) next.push(node.right);
    }
    result.push(level);
    queue = next;
  }
  return result;
}
```

## BST properties

In a binary search tree, every node's left subtree is entirely smaller and its right subtree entirely larger. This gives you O(log n) search/insert/delete on a **balanced** BST, and it means an inorder traversal always yields sorted output — a fact that instantly solves "validate BST" and "kth smallest element" problems.

## Tree construction / serialization

Building a tree from traversal arrays (e.g. preorder + inorder) relies on: the first element of preorder is always the root, and that value's position in inorder splits the array into left/right subtrees. Serialization (tree ↔ string) typically uses preorder with explicit null markers so it can be deserialized unambiguously.

## Recognizing the pattern

Default to recursion for anything phrased as "for each subtree..." Reach for BFS/queue specifically when the problem talks about **levels** ("level order," "right side view," "zigzag traversal," "minimum depth" via shortest path). Reach for BST properties whenever the input is explicitly a BST — most tree problems become much easier once you use the sorted-order guarantee instead of treating it like a generic binary tree.
