# Trees

Trees are the data structure most frequently tested in interviews at top companies — graphs and dynamic programming get more variety, but trees get more volume. The reason is their recursive nature: every tree problem decomposes into the same subproblem on a smaller tree. Once you internalize the recursive template ("solve for the left subtree, solve for the right subtree, combine the results"), a large fraction of tree problems reduce to filling in that template correctly.

The two core traversal families are DFS (depth-first search, using a call stack or explicit stack) and BFS (breadth-first search, using a queue). DFS has three orderings — preorder, inorder, postorder — each suited to different tasks. BFS processes nodes level by level, making it the natural choice for problems that talk about depth, height, or "level order." When the tree is a BST (binary search tree), the sorted-order guarantee from inorder traversal unlocks an additional family of tricks.

## Theory & Fundamentals

### Tree Terminology

A **tree** is a connected acyclic graph. In coding interviews, "tree" almost always means a **rooted binary tree**: each node has at most two children (left and right), and there is exactly one root (a node with no parent).

Key terms:
- **Leaf**: a node with no children
- **Height**: length of the longest path from root to any leaf
- **Depth**: length of the path from root to a specific node
- **Subtree**: a node and all its descendants
- **BST (Binary Search Tree)**: a binary tree where every node's left subtree has smaller values and right subtree has larger values

### Binary Search Tree Property

For every node `n` in a BST:
- All values in `n.left` subtree < `n.val`
- All values in `n.right` subtree > `n.val`

This property allows O(log n) search, insert, and delete on **balanced** trees. On an unbalanced tree (worst case: a linked list), these degrade to O(n).

### Balanced vs. Unbalanced

A tree is **balanced** if the heights of any node's left and right subtrees differ by at most 1. Balanced trees guarantee O(log n) height, enabling O(log n) operations. Self-balancing trees (AVL, Red-Black) maintain balance automatically; plain BSTs can become unbalanced through sequential insertions.

## Core Patterns / Techniques

### DFS Traversals

There are three canonical DFS orderings for binary trees:

```js
function preorder(node, out = []) {
  if (!node) return out;
  out.push(node.val);               // visit ROOT first
  preorder(node.left, out);
  preorder(node.right, out);
  return out;
}

function inorder(node, out = []) {
  if (!node) return out;
  inorder(node.left, out);
  out.push(node.val);               // visit ROOT between children
  inorder(node.right, out);
  return out;
}
// For a BST, inorder produces sorted output!

function postorder(node, out = []) {
  if (!node) return out;
  postorder(node.left, out);
  postorder(node.right, out);
  out.push(node.val);               // visit ROOT last
  return out;
}
```

**When to use which:**
- **Preorder**: serialize a tree, copy a tree, process a node before its children
- **Inorder**: sort a BST, validate BST property
- **Postorder**: delete a tree, compute subtree aggregates (height, sum), process children before parent

### BFS / Level-Order Traversal

Level-order traversal uses a queue to visit nodes level by level:

```js
function levelOrder(root) {
  if (!root) return [];
  const result = [];
  const queue = [root];

  while (queue.length) {
    const levelSize = queue.length;   // snapshot current level size
    const level = [];

    for (let i = 0; i < levelSize; i++) {
      const node = queue.shift();
      level.push(node.val);
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    result.push(level);
  }
  return result;
}
```

Use BFS when you need: level-by-level processing, minimum depth, or right/left side view.

### The Universal Recursive Template

Most tree problems fit this shape:

```js
function solve(node) {
  // Base case — null node
  if (!node) return baseValue;

  // Trust recursion on subtrees
  const leftResult = solve(node.left);
  const rightResult = solve(node.right);

  // Combine results with current node
  return combine(node.val, leftResult, rightResult);
}
```

The key insight: **trust the recursive hypothesis**. Assume `solve(node.left)` already returns the correct answer for the left subtree, and just write the combination step.

### Tree Height and Diameter

```js
// Height: O(n) — visit every node once
function height(node) {
  if (!node) return 0;
  return 1 + Math.max(height(node.left), height(node.right));
}

// Diameter: longest path between any two leaf nodes
// The key insight: path goes THROUGH some turning-point node
let maxDiameter = 0;
function diameterHelper(node) {
  if (!node) return 0;
  const L = diameterHelper(node.left);
  const R = diameterHelper(node.right);
  maxDiameter = Math.max(maxDiameter, L + R); // path through this node
  return 1 + Math.max(L, R);                  // height contribution upward
}
```

### Lowest Common Ancestor (LCA)

```js
function lca(root, p, q) {
  if (!root || root === p || root === q) return root;

  const left = lca(root.left, p, q);
  const right = lca(root.right, p, q);

  // If p and q found in different subtrees, this node is LCA
  if (left && right) return root;
  // Otherwise, LCA is in whichever subtree returned non-null
  return left || right;
}
// Time: O(n), Space: O(h)
```

## Code Examples

### Example 1: Validate Binary Search Tree

```js
// O(n) time, O(h) space (h = height for call stack)
function isValidBST(root, min = -Infinity, max = Infinity) {
  if (!root) return true;
  if (root.val <= min || root.val >= max) return false;

  // Left subtree: max shrinks to current value
  // Right subtree: min grows to current value
  return isValidBST(root.left, min, root.val) &&
         isValidBST(root.right, root.val, max);
}
```

The range-passing technique is the canonical BST validation approach. The common mistake is to only compare a node with its direct parent — this fails for grandparents. Propagating the valid range through recursion catches all ancestor violations.

### Example 2: Maximum Path Sum

```js
// O(n) time, O(h) space
// The path can start and end at any node (not necessarily root-to-leaf)

let maxSum = -Infinity;

function maxPathSumHelper(node) {
  if (!node) return 0;

  // Only include a child if it contributes positively
  const leftGain = Math.max(maxPathSumHelper(node.left), 0);
  const rightGain = Math.max(maxPathSumHelper(node.right), 0);

  // Path that goes left → node → right (doesn't continue upward)
  maxSum = Math.max(maxSum, node.val + leftGain + rightGain);

  // Return the best single-arm extension upward
  return node.val + Math.max(leftGain, rightGain);
}

function maxPathSum(root) {
  maxSum = -Infinity;
  maxPathSumHelper(root);
  return maxSum;
}
```

This is the "global variable updated during recursion" pattern — common when the answer path may turn at a node and cannot continue up to the root.

### Example 3: Serialize and Deserialize

```js
// Preorder serialization with null markers
// "1,2,null,null,3,null,null" for the tree [1,2,3]
function serialize(root) {
  if (!root) return "null";
  return `${root.val},${serialize(root.left)},${serialize(root.right)}`;
}

function deserialize(data) {
  const vals = data.split(",");
  let i = 0;

  function build() {
    if (vals[i] === "null") { i++; return null; }
    const node = new TreeNode(parseInt(vals[i++]));
    node.left = build();
    node.right = build();
    return node;
  }

  return build();
}
// Time and space: O(n) — process each node once
```

## Best Practices

- **Always handle the null base case first** — every recursive tree function starts with `if (!node) return ...`. Missing this causes null pointer errors.
- **Identify which traversal order you need** before writing code — preorder for top-down, postorder for bottom-up aggregation, inorder for BST order.
- **Use a wrapper or closure for global state** — for problems where the answer path turns at a node (max path sum, diameter), track the answer in a variable updated during the recursive pass.
- **State the height complexity** — recursive solutions use O(h) call stack space where h = O(log n) for balanced trees and O(n) for unbalanced ones.
- **BFS problems need level separation** — use `const levelSize = queue.length` at the start of each while-loop iteration to process exactly one level.
- **Iterative DFS uses an explicit stack** — preorder and postorder are straightforward; inorder requires tracking a `current` pointer alongside the stack.

## Common Interview Questions

**Q1: What's the difference between a binary tree and a BST?**
A: A binary tree is any tree where each node has at most 2 children — no ordering constraint. A BST adds the invariant: left subtree values < node value < right subtree values, enabling O(log n) search on balanced trees.

**Q2: What's the time complexity of tree DFS traversal?**
A: O(n) — every node is visited exactly once. Space is O(h) for the call stack: O(log n) balanced, O(n) worst case.

**Q3: When would you use BFS over DFS on a tree?**
A: Use BFS for anything involving levels (level-order output, minimum depth, right side view). Use DFS for subtree-based problems (height, path sum, LCA). BFS gives shortest path in unweighted graphs; on a tree, DFS also works since there's exactly one path to each node.

**Q4: How do you find LCA in a BST vs. a general binary tree?**
A: In a BST: use the BST property — if both p and q are smaller than root, recurse left; if both larger, recurse right; otherwise root is LCA. O(log n) average. In a general binary tree: the O(n) algorithm that returns the first node that has p or q in both subtrees.

**Q5: What is a complete binary tree?**
A: All levels are fully filled except possibly the last, which is filled left-to-right. A heap uses this structure (stored as an array). Different from balanced: a balanced tree need not be complete.

**Q6: What's the space complexity of BFS on a tree?**
A: O(w) where w is the maximum width. For a complete binary tree, the last level has n/2 nodes, so O(n) worst case. For a skewed tree, O(1).

**Q7: Why does inorder traversal of a BST give sorted output?**
A: The BST invariant guarantees that for any node, the entire left subtree has smaller values and the entire right subtree has larger values. Inorder visits left, then root, then right — so it processes all smaller values before the root and the root before all larger values, yielding ascending order.

## Practice Exercises

**Exercise 1 — Inorder Iteratively (Beginner)**
Implement inorder traversal without recursion using an explicit stack. Hint: push nodes leftward until null, then pop and visit, then go right.

**Exercise 2 — Level Order Right Side View (Beginner-Intermediate)**
Given a binary tree, return the values visible from the right side (rightmost node at each level). Hint: BFS, take the last node at each level.

**Exercise 3 — Construct Tree from Preorder + Inorder (Intermediate)**
Given preorder and inorder traversal arrays, reconstruct the binary tree. Hint: preorder[0] is always the root; find it in inorder to split left and right subtrees.

**Exercise 4 — Kth Smallest in BST (Intermediate)**
Find the kth smallest element in a BST in O(h + k) time. Hint: inorder traversal of a BST is sorted — stop at the kth element.

**Exercise 5 — Count Good Nodes (Intermediate)**
A node is "good" if the path from root to that node has no value greater than the node's value. Count good nodes. Hint: pass the running maximum down through the recursion.

## Key Takeaways

- Every binary tree problem decomposes recursively: solve for left subtree, right subtree, combine.
- Preorder = root first, inorder = root between children (BST → sorted), postorder = root last (bottom-up aggregation).
- BFS with level-size tracking is the pattern for level-based problems.
- BSTs enable O(log n) operations when balanced; inorder traversal yields sorted output.
- Call stack space is O(h): O(log n) for balanced trees, O(n) for degenerate (skewed) trees.
- For problems where the answer path turns at a node (diameter, max path sum), use a global variable updated during a postorder pass.
