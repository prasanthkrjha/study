# 1-D Dynamic Programming

Dynamic programming (DP) is an optimization technique for problems where a brute-force recursive solution repeatedly solves the same smaller subproblems. The key insight is that if the answer to `f(n)` depends on `f(n-1)` and `f(n-2)`, and those are each computed independently from scratch, you do exponential redundant work. DP eliminates the redundancy by solving each subproblem exactly once and storing the result.

Two structural properties must hold for DP to apply: **overlapping subproblems** (the same subproblems recur during the recursion) and **optimal substructure** (the optimal solution to the original problem can be constructed from optimal solutions to subproblems). Fibonacci numbers satisfy both: `fib(n) = fib(n-1) + fib(n-2)`, the same sub-values appear repeatedly, and the correct value for `fib(n)` directly depends on the correct values of its sub-cases.

There are two equivalent formulations of DP: **memoization** (top-down) adds a cache to the natural recursive solution and stores results as they are computed; **tabulation** (bottom-up) fills a table iteratively starting from the base cases and working upward. Memoization is easier to derive (you start from the recursion you already have), while tabulation avoids recursion overhead and call stack limits and often achieves better space efficiency. In practice, both approaches appear in interviews and you should be comfortable with both.

## Theory & Fundamentals

### Identifying a DP problem

Ask yourself:
1. Does a brute-force recursion for this problem call itself with the same arguments more than once?
2. Does the problem ask for a minimum, maximum, count, or yes/no that depends on choices made over a sequence?
3. Can you define `dp[i]` as "the answer for the first i elements (or for amount i, or for position i)"?

If yes to these, DP likely applies. The most important step — the one people skip and then get stuck — is defining what `dp[i]` **means** in precise English before writing any code.

### Memoization vs. tabulation

```
Memoization (top-down):                 Tabulation (bottom-up):
─────────────────────────────────────   ────────────────────────────────────
+ Natural — start from the recursion    + No recursion — avoids stack overflow
+ Only computes needed subproblems      + Better cache locality
+ Easier to derive from brute force     + Often uses less space (rolling array)
- Call stack overhead                   - Must figure out fill order
- Stack overflow on large n             - Slightly harder to derive
```

For 1-D DP problems specifically, tabulation with O(1) space (using two rolling variables) is often possible when `dp[i]` only depends on the previous 1-2 values.

### The 4-step DP framework

1. **Define the state:** What does `dp[i]` represent? Write it in words.
2. **Write the recurrence:** How does `dp[i]` depend on `dp[j]` for `j < i`?
3. **Identify base cases:** What are the smallest values where the answer is known directly?
4. **Choose top-down or bottom-up** and implement accordingly.

### Space optimization

When `dp[i]` only depends on `dp[i-1]` (and maybe `dp[i-2]`), you do not need to store the entire array. Two variables (or a small fixed window) suffice, reducing space from O(n) to O(1).

## Core Patterns / Techniques

### Pattern 1: Fibonacci-style (one or two previous values)

```js
// Standard Fibonacci — O(n) time, O(1) space with rolling variables
function fib(n) {
  if (n <= 1) return n;
  let prev2 = 0, prev1 = 1;
  for (let i = 2; i <= n; i++) {
    const curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
  }
  return prev1;
}

// Climbing stairs: ways to reach step n taking 1 or 2 steps
// Same recurrence: ways(n) = ways(n-1) + ways(n-2)
function climbStairs(n) {
  if (n <= 2) return n;
  let a = 1, b = 2;
  for (let i = 3; i <= n; i++) [a, b] = [b, a + b];
  return b;
}
```

### Pattern 2: House robber (cannot take adjacent elements)

```js
// dp[i] = max money robbable from houses 0..i
// dp[i] = max(dp[i-1], dp[i-2] + nums[i])
// dp[i-1]: skip house i; dp[i-2] + nums[i]: rob house i
function rob(nums) {
  if (!nums.length) return 0;
  let prevNo = 0, prevYes = 0;
  for (const n of nums) {
    const newYes = prevNo + n;    // rob this house (can't have robbed previous)
    const newNo = Math.max(prevNo, prevYes); // skip this house (take best of both)
    prevNo = newNo;
    prevYes = newYes;
  }
  return Math.max(prevNo, prevYes);
}
```

### Pattern 3: Linear sequence with forward/backward lookahead

```js
// Longest increasing subsequence (LIS) — O(n²) DP
// dp[i] = length of longest increasing subsequence ending at index i
function lengthOfLIS(nums) {
  const dp = new Array(nums.length).fill(1); // every element alone is a subsequence
  let maxLen = 1;
  for (let i = 1; i < nums.length; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1); // extend subsequence ending at j
      }
    }
    maxLen = Math.max(maxLen, dp[i]);
  }
  return maxLen;
}
```

### Pattern 4: Coin change (unbounded, minimize count)

```js
// dp[a] = minimum coins needed to make amount a
// dp[a] = min over all coins c of (dp[a - c] + 1)
function coinChange(coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0; // base case: 0 coins to make amount 0

  for (let a = 1; a <= amount; a++) {
    for (const coin of coins) {
      if (coin <= a && dp[a - coin] !== Infinity) {
        dp[a] = Math.min(dp[a], dp[a - coin] + 1);
      }
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

## Code Examples

### Example 1: House Robber II (circular arrangement)

```js
/**
 * Houses are arranged in a circle — the first and last are adjacent.
 * You cannot rob both the first and last house.
 *
 * Insight: run the linear house robber twice —
 *   once on houses [0, n-2] (exclude last),
 *   once on houses [1, n-1] (exclude first).
 * Take the maximum of the two.
 *
 * Time: O(n), Space: O(1)
 */
function robCircular(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];
  if (n === 2) return Math.max(nums[0], nums[1]);

  function linearRob(start, end) {
    let prevNo = 0, prevYes = 0;
    for (let i = start; i <= end; i++) {
      const newYes = prevNo + nums[i];
      const newNo = Math.max(prevNo, prevYes);
      prevNo = newNo;
      prevYes = newYes;
    }
    return Math.max(prevNo, prevYes);
  }

  // Case 1: include first house, exclude last → rob nums[0..n-2]
  // Case 2: exclude first house, include last → rob nums[1..n-1]
  return Math.max(linearRob(0, n - 2), linearRob(1, n - 1));
}

console.log(robCircular([2, 3, 2])); // 3 (rob index 1)
console.log(robCircular([1, 2, 3, 1])); // 4 (rob indices 0 and 2)
```

### Example 2: Word break

```js
/**
 * Given a string s and a dictionary wordDict, determine if s can be
 * segmented into a space-separated sequence of dictionary words.
 *
 * State: dp[i] = true if s[0..i-1] can be segmented using wordDict.
 * Recurrence: dp[i] = true if there exists j < i where dp[j] = true
 *             and s[j..i-1] is in wordDict.
 * Base case: dp[0] = true (empty string is trivially segmentable).
 *
 * Time: O(n² * m) where n = s.length, m = average word length
 * Space: O(n)
 */
function wordBreak(s, wordDict) {
  const wordSet = new Set(wordDict); // O(1) lookup
  const n = s.length;
  const dp = new Array(n + 1).fill(false);
  dp[0] = true; // empty prefix is always segmentable

  for (let i = 1; i <= n; i++) {
    for (let j = 0; j < i; j++) {
      // If s[0..j-1] is segmentable AND s[j..i-1] is a valid word
      if (dp[j] && wordSet.has(s.slice(j, i))) {
        dp[i] = true;
        break; // no need to check further j values
      }
    }
  }

  return dp[n];
}

console.log(wordBreak('leetcode', ['leet', 'code']));       // true
console.log(wordBreak('applepenapple', ['apple', 'pen'])); // true
console.log(wordBreak('catsandog', ['cats', 'dog', 'sand', 'and', 'cat'])); // false
```

## Best Practices

- **Define `dp[i]` in words before writing any code.** This is the single most important step. "dp[i] = maximum money robbable from the first i houses" is precise and makes the recurrence obvious. "dp[i] = something about houses" is not.
- **Always establish base cases explicitly.** Off-by-one errors in base cases are the most common DP bug. Verify base cases by hand before running anything.
- **Start with memoization, optimize to tabulation if needed.** It's faster to write the memoized version (it mirrors the recursion), and most interviews accept it. Convert to tabulation if you need O(1) space or to avoid stack overflow.
- **Consider space optimization when `dp[i]` depends only on 1-2 previous values.** Rolling variables reduce O(n) space to O(1). Do this after correctness is confirmed, not before.
- **Draw the recurrence relation as a dependency graph.** If `dp[i]` depends on `dp[i-1]` and `dp[i-2]`, draw arrows. This confirms your fill order (always fill dependencies before the current cell) and catches circular dependencies early.
- **Test with small examples by hand.** Trace through a length-3 or length-4 input manually, filling the DP table. This catches off-by-one errors in recurrence or base cases that are invisible in code.
- **When counting (not optimizing), initialize differently.** For "number of ways" problems, `dp[0] = 1` (one way to do nothing). For "minimum cost" problems, `dp[0] = 0`. These differ and the wrong initialization produces wrong results.

## Common Interview Questions

**Q1: What are the two properties a problem must have for dynamic programming to apply?**

A: Overlapping subproblems (the same smaller subproblems are solved multiple times in a naive recursion) and optimal substructure (the optimal solution to the problem can be built from optimal solutions to subproblems). Greedy only needs optimal substructure; DP needs both.

**Q2: What is the difference between memoization and tabulation?**

A: Memoization (top-down) adds a cache to a recursive function and stores results when first computed. Tabulation (bottom-up) iteratively fills a table from base cases upward. Both are O(n) time. Memoization is easier to derive; tabulation avoids recursion overhead, is cache-friendlier, and often achieves better space efficiency via rolling arrays.

**Q3: How does the house robber recurrence work?**

A: `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`. Either skip house i (then best is whatever was optimal for the first i-1 houses) or rob house i (then add its value to the best possible for the first i-2 houses, since i-1 must be skipped). Base cases: dp[0] = nums[0], dp[1] = max(nums[0], nums[1]).

**Q4: In the coin change problem, why initialize dp[1..amount] to Infinity rather than 0?**

A: Infinity represents "not yet reachable." If we initialized to 0, `Math.min(0, dp[a - coin] + 1)` would always return 0, hiding the actual minimum. Using Infinity means the minimum correctly starts at "unknown" and is only reduced when a valid path (coin sequence) to that amount is found.

**Q5: How does the word break problem differ from coin change in its DP state definition?**

A: Coin change uses `dp[a]` = minimum coins for amount `a` (a numeric optimization). Word break uses `dp[i]` = boolean — can `s[0..i-1]` be segmented? The recurrence for word break checks all split points; for coin change it checks all coin denominations. Both are 1-D DP with index-based state.

**Q6: What is the time complexity of the longest increasing subsequence (LIS) DP?**

A: The standard DP is O(n²): for each index i, check all j < i. An O(n log n) solution exists using binary search with a patience sorting approach, but O(n²) is typically accepted in interviews unless n is large (>10,000).

**Q7: Why does the climbing stairs problem have the same recurrence as Fibonacci?**

A: To reach step n, your last move was either 1 step from n-1 or 2 steps from n-2. So the number of ways to reach n equals the number of ways to reach n-1 plus the number of ways to reach n-2. That is exactly the Fibonacci recurrence, with different base cases (ways(1) = 1, ways(2) = 2).

**Q8: How do you handle the house robber problem on a circular array?**

A: Since the first and last houses are adjacent, you can't rob both. Split into two linear subproblems: `rob(nums[0..n-2])` and `rob(nums[1..n-1])`. Take the maximum. This works because any optimal solution either includes the first house (and therefore excludes the last) or excludes the first (and may include the last).

## Practice Exercises

**Exercise 1 — Min Cost Climbing Stairs (Easy)**
You can climb 1 or 2 steps at a time. Each step has a cost. After paying the cost of a step, you can climb 1 or 2 steps. Find the minimum cost to reach the top (one step past the last element). You may start from index 0 or 1.
Hint: `dp[i] = cost[i] + min(dp[i-1], dp[i-2])`. Answer = `min(dp[n-1], dp[n-2])`.

**Exercise 2 — Decode Ways (Medium)**
A message of digits can be decoded as letters (1 → 'A', 2 → 'B', ..., 26 → 'Z'). Count the number of ways to decode a given digit string.
Hint: `dp[i]` = number of ways to decode `s[0..i-1]`. Single digit at s[i-1]: if non-zero, `dp[i] += dp[i-1]`. Two digits at s[i-2..i-1]: if between 10-26, `dp[i] += dp[i-2]`. Watch out for leading zeros.

**Exercise 3 — Palindromic Substrings (Medium)**
Count the number of palindromic substrings in a given string.
Hint: Expand around each center (both single-character and between-character centers). For each center, expand outward while the left and right characters match. Count each palindrome found. O(n²) time, O(1) space — no DP table needed, but DP is also valid.

**Exercise 4 — Maximum Product Subarray (Medium)**
Find the contiguous subarray with the largest product. The array may contain negative numbers.
Hint: Track both the maximum and minimum product ending at the current index. A negative number flips max and min. `maxProd[i] = max(nums[i], nums[i] * maxProd[i-1], nums[i] * minProd[i-1])`.

**Exercise 5 — Partition Equal Subset Sum (Medium)**
Given an integer array, determine if it can be partitioned into two subsets with equal sum.
Hint: This is equivalent to finding a subset that sums to `totalSum / 2`. Use 1-D DP with a boolean set tracking achievable sums. For each number, update the set: `newSums = union(currentSums, {s + num for s in currentSums})`. If `totalSum / 2` is achievable, return true.

## Key Takeaways

- DP applies when a recursive solution has overlapping subproblems and optimal substructure — cache results to avoid exponential redundancy.
- Define `dp[i]` in precise English first. The recurrence follows directly from a clear state definition.
- Memoization is easier to derive; tabulation is more space-efficient and avoids stack overflow. Both give the same O(n) time.
- When `dp[i]` depends only on 1-2 previous values, use rolling variables to achieve O(1) space.
- Base cases are where bugs hide — always fill them explicitly and verify by hand.
- House robber, coin change, LIS, and word break are the canonical 1-D DP problems; their recurrences appear repeatedly in disguised form.
- Counting problems use `dp[0] = 1` (one way to do nothing); minimization problems use `dp[0] = 0` and `dp[1..n] = Infinity` initially.
- The difference between DP and greedy: DP explores all choices at each step; greedy commits to one. Use DP when choices interact in ways that make local optimality unreliable.
