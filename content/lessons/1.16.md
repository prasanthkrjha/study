# 1-D Dynamic Programming

DP is for problems with **overlapping subproblems** and **optimal substructure** — the answer to a bigger problem is built from answers to smaller versions of the same problem, and those smaller versions get recomputed many times if you don't cache them.

## The Fibonacci lens

Naive recursive Fibonacci is O(2ⁿ) because `fib(5)` calls `fib(4)` and `fib(3)`, and `fib(4)` *also* calls `fib(3)` — the same subproblem gets solved repeatedly:

```js
// Memoization (top-down): cache results the first time you compute them
function fib(n, memo = new Map()) {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);
  const result = fib(n - 1, memo) + fib(n - 2, memo);
  memo.set(n, result);
  return result;
}

// Tabulation (bottom-up): build the answer iteratively, smallest to largest
function fibTab(n) {
  if (n <= 1) return n;
  let prev2 = 0, prev1 = 1;
  for (let i = 2; i <= n; i++) {
    [prev2, prev1] = [prev1, prev1 + prev2];
  }
  return prev1;
}
```

Both are O(n) instead of O(2ⁿ). **Memoization** is usually easier to derive from the recursive definition; **tabulation** is usually more space-efficient (notice `fibTab` uses O(1) space, while memoized recursion uses O(n) call-stack space).

## House robber

You can't rob two adjacent houses. At each house, you either skip it (keep the best total so far) or rob it (best total from two houses back, plus this house's value):

```js
function rob(nums) {
  let prevNoRob = 0, prevRob = 0;
  for (const n of nums) {
    const newRob = prevNoRob + n;
    prevNoRob = Math.max(prevNoRob, prevRob);
    prevRob = newRob;
  }
  return Math.max(prevNoRob, prevRob);
}
```

## Climbing stairs

Number of ways to reach step `n`, taking 1 or 2 steps at a time — literally Fibonacci with different base cases: `ways(n) = ways(n-1) + ways(n-2)`, because your last move was either a 1-step from `n-1` or a 2-step from `n-2`.

## Coin change

Minimum coins to make amount `n`. For each amount from 1 up to `n`, try every coin denomination and take the best result from `amount - coin`, plus one:

```js
function coinChange(coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (let a = 1; a <= amount; a++) {
    for (const coin of coins) {
      if (coin <= a) dp[a] = Math.min(dp[a], dp[a - coin] + 1);
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

## How to approach any new 1-D DP problem

1. Define what `dp[i]` **means** in words first (e.g. "max money robbable from houses 0..i"). This is the step people skip and then get stuck.
2. Write the recurrence: how does `dp[i]` relate to `dp[i-1]`, `dp[i-2]`, etc.?
3. Identify base cases.
4. Decide: memoized recursion (easier to write, matches the recurrence directly) or tabulation (better space, avoids stack overflow on large `n`).

## Recognizing the pattern

"Number of ways to...", "minimum/maximum ... given you can't do X and Y together", or any problem where a brute-force recursive solution visibly recomputes the same smaller inputs — that's 1-D DP.
