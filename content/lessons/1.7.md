# Linked List

A linked list is a chain of nodes where each node holds a value and a pointer to the next node (singly linked) or both the next and previous nodes (doubly linked). Unlike arrays, there is no index-based random access — reaching node k requires traversing k nodes from the head. This O(k) access cost makes lists unsuitable for search, but O(1) insertion and deletion at a known position make them ideal for scenarios where you're constantly modifying the structure.

In interviews, linked list problems almost never test data structure theory — they test pointer manipulation under pressure. The bugs that end interviews are subtle: overwriting a pointer before saving it, forgetting the dummy node when the head might change, and losing track of which node `prev`, `curr`, and `next` point to after a reassignment. Drawing the list on paper — literally boxes with arrows — before writing any code is the single most effective practice habit for this topic.

The techniques in this unit — reversal, fast-slow pointers, merging, and the dummy node — are reusable sub-procedures. They appear as building blocks in problems about palindromes, cycle detection, kth-from-end, reordering, and sorting.

## Theory & Fundamentals

### The Node Structure

```js
class ListNode {
  constructor(val = 0, next = null) {
    this.val = val;
    this.next = next;
  }
}
// Helper to build a list from an array
function buildList(arr) {
  const dummy = new ListNode(0);
  let curr = dummy;
  for (const v of arr) { curr.next = new ListNode(v); curr = curr.next; }
  return dummy.next;
}
// Helper to convert a list to array (for printing/testing)
function listToArray(head) {
  const out = [];
  while (head) { out.push(head.val); head = head.next; }
  return out;
}
```

### Pointer Manipulation Safety Rules

1. **Save `next` before overwriting `curr.next`** — the most common bug in reversal is `curr.next = prev; curr = curr.next` (now `curr` points to `prev`, not the old `next`). Always save: `const next = curr.next; curr.next = prev; curr = next;`.
2. **Use a dummy node whenever the head might change** — if you might delete the head or prepend a new head, a dummy node gives you a stable reference. Return `dummy.next` at the end.
3. **Check both `fast` and `fast.next` before advancing** — the fast pointer moves two steps at a time. If either is null, you're at the end. Checking only `fast` will dereference a null pointer on the second step.

### Visualizing Pointer Operations

Before coding a reversal, draw it:

```
Before:  null ← prev  curr → next → next2 → ...
                        |
                       [3]

Step 1: save next = curr.next
Step 2: curr.next = prev    →  null ← [3]  next → ...
Step 3: prev = curr         →  prev points to [3]
Step 4: curr = next         →  curr points to what was next
```

After n iterations, `prev` is the new head.

### Fast-Slow Pointer Math

When `fast` moves 2 steps per iteration and `slow` moves 1 step per iteration:
- **Middle of a list**: when `fast` reaches the end (null or last node), `slow` is at the middle. For a list of length n, `slow` ends at position ⌊n/2⌋.
- **Cycle detection**: if a cycle exists, fast will eventually "lap" slow inside the cycle. The meeting point is at a specific position related to cycle length.
- **Nth from end**: advance `fast` n steps first. Then advance both until `fast` reaches the end. `slow` is then at the (n from end) position.

## Core Patterns / Techniques

### Pattern 1: Reversal (Iterative)

```js
function reverseList(head) {
  let prev = null;
  let curr = head;

  while (curr) {
    const next = curr.next;  // 1. save next before overwriting
    curr.next = prev;         // 2. reverse the link
    prev = curr;              // 3. advance prev
    curr = next;              // 4. advance curr
  }
  return prev; // prev is the new head (last node of original list)
}
// Time: O(n)  Space: O(1)
```

Recursive version (O(n) space due to call stack):

```js
function reverseListRec(head) {
  if (!head || !head.next) return head; // base case: 0 or 1 node
  const newHead = reverseListRec(head.next); // new head is the tail of the reversed suffix
  head.next.next = head; // the node after head should point back to head
  head.next = null;      // head becomes the new tail
  return newHead;
}
```

### Pattern 2: Fast-Slow Pointers (Cycle Detection)

```js
// Floyd's Cycle Detection — O(n) time, O(1) space
function hasCycle(head) {
  let slow = head;
  let fast = head;

  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true; // pointers met inside the cycle
  }
  return false; // fast reached the end → no cycle
}
```

To find the **start of the cycle**: after detection, reset one pointer to head and advance both one step at a time. They meet at the cycle start.

```js
function detectCycleStart(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) {
      // Reset one pointer to head, advance both at speed 1
      let start = head;
      while (start !== slow) { start = start.next; slow = slow.next; }
      return start;
    }
  }
  return null;
}
```

### Pattern 3: Find Middle

```js
function findMiddle(head) {
  let slow = head;
  let fast = head;

  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
  }
  return slow; // middle node (right-middle for even-length lists)
}
```

### Pattern 4: Merge Two Sorted Lists with Dummy Node

```js
function mergeTwoLists(l1, l2) {
  const dummy = new ListNode(0); // dummy avoids special-casing the head
  let tail = dummy;

  while (l1 && l2) {
    if (l1.val <= l2.val) { tail.next = l1; l1 = l1.next; }
    else { tail.next = l2; l2 = l2.next; }
    tail = tail.next;
  }
  tail.next = l1 ?? l2; // attach the remaining list (whichever is not null)
  return dummy.next;
}
// Time: O(m + n)  Space: O(1) — no new nodes created
```

### Pattern 5: Remove Nth Node from End

```js
function removeNthFromEnd(head, n) {
  const dummy = new ListNode(0, head); // dummy handles head-deletion case
  let fast = dummy;
  let slow = dummy;

  // Advance fast n+1 steps so slow ends one step before the target
  for (let i = 0; i <= n; i++) fast = fast.next;

  while (fast) {
    slow = slow.next;
    fast = fast.next;
  }
  // slow.next is the node to remove
  slow.next = slow.next.next;
  return dummy.next;
}
// Time: O(n)  Space: O(1) — single pass
```

## Code Examples

### Example 1: Reorder List

```js
/**
 * Reorder list L0 → L1 → ... → Ln-1 → Ln
 * to              L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → ...
 *
 * Strategy (three steps):
 * 1. Find the middle (fast-slow)
 * 2. Reverse the second half
 * 3. Merge the two halves by interleaving
 *
 * Time: O(n)   Space: O(1)
 */
function reorderList(head) {
  if (!head || !head.next) return;

  // Step 1: Find middle
  let slow = head, fast = head;
  while (fast.next && fast.next.next) {
    slow = slow.next;
    fast = fast.next.next;
  }
  // slow is the middle; split into two lists
  let second = slow.next;
  slow.next = null; // sever the connection

  // Step 2: Reverse the second half
  let prev = null, curr = second;
  while (curr) {
    const next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
  }
  second = prev; // new head of reversed second half

  // Step 3: Merge by interleaving
  let first = head;
  while (second) {
    const firstNext = first.next;
    const secondNext = second.next;
    first.next = second;    // insert second node after first
    second.next = firstNext; // link back to the rest of first half
    first = firstNext;
    second = secondNext;
  }
}

// Test
const list = buildList([1,2,3,4,5]);
reorderList(list);
console.log(listToArray(list)); // [1,5,2,4,3]
```

### Example 2: Linked List Palindrome Check

```js
/**
 * Determine if a linked list is a palindrome.
 *
 * Strategy:
 * 1. Find the middle with fast-slow pointers
 * 2. Reverse the second half in place
 * 3. Compare first half to reversed second half
 * 4. (Optional) Restore the list
 *
 * Time: O(n)   Space: O(1)
 */
function isPalindrome(head) {
  if (!head || !head.next) return true;

  // Step 1: Find end of first half
  let slow = head, fast = head;
  while (fast.next && fast.next.next) {
    slow = slow.next;
    fast = fast.next.next;
  }

  // Step 2: Reverse second half
  let secondHead = null, curr = slow.next;
  while (curr) {
    const next = curr.next;
    curr.next = secondHead;
    secondHead = curr;
    curr = next;
  }

  // Step 3: Compare
  let p1 = head, p2 = secondHead;
  let result = true;
  while (p2) {
    if (p1.val !== p2.val) { result = false; break; }
    p1 = p1.next;
    p2 = p2.next;
  }
  return result;
}

console.log(isPalindrome(buildList([1,2,2,1]))); // true
console.log(isPalindrome(buildList([1,2])));     // false
console.log(isPalindrome(buildList([1,2,3,2,1]))); // true
```

## Best Practices

- **Draw boxes and arrows before coding** — most linked list bugs come from not tracking where all three pointers (prev, curr, next) are after each step. A quick diagram takes 30 seconds and saves 10 minutes of debugging.
- **Always save `next` before overwriting `curr.next`** — this is the single most common bug. `const next = curr.next` must come first.
- **Use a dummy node when the head might change** — any operation that might delete the head, insert before the head, or produce a new head benefits from a dummy sentinel. Cost: zero; benefit: eliminates an entire class of special cases.
- **Check both `fast` and `fast.next` in fast-slow loops** — fast moves two steps at a time. `while (fast && fast.next)` prevents null dereference on the second step.
- **For merging, never create new nodes — reuse existing ones** — change `.next` pointers to weave existing nodes into the new order. Creating new nodes is unnecessary and wastes space.
- **Verify termination conditions for cycle problems** — if the list has a cycle, a while loop checking `curr !== null` will run forever. Always use the fast-slow pattern for cycle problems, not `null`-terminated loops.
- **Test with single-node and two-node lists** — edge cases that break linked list code most often are empty list, single node, and two nodes (especially for reversal and palindrome detection).

## Common Interview Questions

**Q1: How do you reverse a linked list iteratively? What are the three pointer operations per step?**
A: Maintain `prev`, `curr`, and a saved `next`. Each step: (1) save `next = curr.next`, (2) set `curr.next = prev`, (3) advance `prev = curr`, (4) advance `curr = next`. Return `prev` as the new head.

**Q2: How does Floyd's cycle detection algorithm work? Why do the pointers meet inside the cycle?**
A: One pointer moves 1 step/iteration (slow), another moves 2 steps/iteration (fast). If there is a cycle of length C, once both enter the cycle, the relative speed of fast over slow is 1 step/iteration. Fast will catch up to slow in at most C iterations. They meet inside the cycle.

**Q3: How do you find the kth node from the end of a list in one pass?**
A: Use two pointers starting at head. Advance the first pointer k steps. Then advance both until the first pointer reaches null. The second pointer is now at the kth node from the end.

**Q4: Why use a dummy node in linked list problems?**
A: A dummy (sentinel) node placed before the real head gives you a stable pointer that never moves. This eliminates special-casing when the head itself might be deleted, inserted before, or replaced. You always return `dummy.next` as the true head.

**Q5: How do you detect the start of a cycle in a linked list?**
A: Use Floyd's algorithm to find the meeting point. Then reset one pointer to `head`. Advance both pointers one step at a time. They will meet exactly at the cycle start. (Mathematical proof: the distance from head to cycle start equals the distance from the meeting point to cycle start within the cycle.)

**Q6: How do you merge k sorted linked lists efficiently?**
A: Use a min-heap (priority queue) of size k. Initialize it with the head of each list. Repeatedly extract the minimum, append it to the result, and insert the next node from the same list. Total time: O(n log k) where n = total nodes.

**Q7: How do you check if a linked list is a palindrome in O(n) time and O(1) space?**
A: (1) Find the middle with fast-slow. (2) Reverse the second half in place. (3) Compare the first and reversed second halves node by node. This avoids creating an array copy (O(n) space) or using recursion (O(n) call stack).

**Q8: What is the time complexity of inserting a node at the beginning vs. end of a singly linked list?**
A: Beginning: O(1) — just update the new node's next to head and update head. End: O(n) for a singly linked list without a tail pointer (must traverse to find the last node). With a tail pointer maintained alongside head: O(1).

## Practice Exercises

**Exercise 1 — Reverse a Sublist (Beginner-Intermediate)**
Given a linked list and two positions `left` and `right` (1-indexed), reverse the nodes from position `left` to `right` in place. For example, `[1,2,3,4,5]` with left=2, right=4 → `[1,4,3,2,5]`. Handle the dummy node for the case where left=1.
Hint: Traverse to position `left-1`. Then reverse the sublist from `left` to `right` using the standard reversal technique. Reconnect the reversed sublist to the rest.

**Exercise 2 — Intersection of Two Lists (Beginner-Intermediate)**
Given the heads of two singly linked lists, find the node where they intersect (share the same node object, not just the same value). If they don't intersect, return null. Solve it in O(m+n) time and O(1) space without modifying the lists.
Hint: If you traverse both lists simultaneously, and when one reaches the end, redirect it to the head of the other list, both pointers will reach the intersection point after traversing (m+n) total nodes.

**Exercise 3 — Add Two Numbers (Intermediate)**
Two linked lists represent non-negative integers stored in reverse order (i.e., `[2,4,3]` = 342). Add the two numbers and return the sum as a linked list in the same format. Handle carry propagation and the case where one list is longer than the other.
Hint: Simulate grade-school addition. Use a dummy node for the result. Maintain a carry variable. Continue while either list has nodes or carry is non-zero.

**Exercise 4 — Sort Linked List (Intermediate)**
Sort a linked list in O(n log n) time and O(1) space. The expected approach is merge sort adapted for linked lists (not quicksort, which has poor worst-case behavior and is harder to implement with O(1) space on lists).
Hint: Split the list in half using fast-slow, sort each half recursively, then merge. The merge step uses the standard two-list merge. Stack depth is O(log n) for the recursion.

**Exercise 5 — Copy List with Random Pointer (Advanced)**
A linked list where each node has an additional `random` pointer (pointing to any node or null) must be deep-copied. Return a fully independent copy of the list. The challenge is establishing the correct `random` links without a second pass that is O(n²).
Hint: Use a Map from original nodes to their copies. First pass: create all copied nodes and store in the map. Second pass: set `next` and `random` for each copy using `map.get(original.next)` and `map.get(original.random)`.

## Key Takeaways

- Linked lists require careful pointer management — always save `next` before overwriting `curr.next`.
- The dummy node pattern eliminates special cases whenever the head node might be changed or removed.
- Fast-slow pointers (Floyd's algorithm) detect cycles, find midpoints, and locate kth-from-end nodes in a single O(n) pass.
- Reversal is the fundamental building block — reorder list, palindrome check, and reverse sublists all depend on it.
- Merging two sorted lists uses a dummy node and the same logic as the merge step in merge sort.
- For cycle start detection: after meeting inside the cycle, reset one pointer to head and advance both at speed 1.
- Most linked list operations are O(n) time and O(1) space — you are rewiring existing nodes, not creating new ones.
- Draw diagrams first — a box-and-arrow sketch of before/after state prevents pointer bugs more reliably than any other technique.
