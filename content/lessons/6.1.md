# Python Core Language

Python was flagged as the single biggest blocker in your gap analysis — every AI-adjacent posting lists it as a must-have. The good news: you already think like a programmer, so this unit moves fast through syntax and slows down only where Python's idioms genuinely differ from JS/TS.

## Syntax, data types, control flow

```python
# Indentation defines blocks — no braces
def classify(n):
    if n < 0:
        return "negative"
    elif n == 0:
        return "zero"
    else:
        return "positive"

# Core types: int, float, str, bool, list, tuple, dict, set
numbers = [1, 2, 3]        # mutable, ordered
point = (10, 20)            # immutable, ordered
user = {"name": "Prasanth", "age": 25}   # dict — like a JS object
tags = {"python", "react", "python"}      # set — duplicates collapse automatically
```

The biggest early trip-up coming from JS: Python has no `undefined`/`null` split (just `None`), no `===` vs `==` distinction (Python's `==` already checks value equality, not reference), and truthiness includes empty containers (`[]`, `{}`, `""`, `0` are all falsy).

## Functions

```python
def greet(name, greeting="Hello"):   # default parameter, like JS
    return f"{greeting}, {name}!"     # f-strings — Python's template literals

# *args and **kwargs — variadic positional and keyword arguments
def log(*args, **kwargs):
    print(args, kwargs)

log(1, 2, level="info")  # args = (1, 2), kwargs = {"level": "info"}
```

## OOP basics (classes/inheritance)

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        raise NotImplementedError

class Dog(Animal):
    def speak(self):
        return f"{self.name} says Woof"

d = Dog("Rex")
print(d.speak())  # "Rex says Woof"
```

`__init__` is the constructor. `self` is explicit in every method signature (unlike JS's implicit `this`) — you'll write `self` constantly, it's not optional.

## Virtual environments and pip

Python dependencies are installed per-project via a virtual environment, roughly Python's equivalent of `node_modules` being isolated per project (except Python needs you to opt into isolation explicitly):

```bash
python -m venv venv          # create an isolated environment
source venv/bin/activate      # activate it (Windows: venv\Scripts\activate)
pip install requests pandas   # install packages into the active venv
pip freeze > requirements.txt # snapshot exact versions, like package-lock.json
```

Forgetting to activate a venv before installing is the single most common Python environment bug — packages silently install globally instead of into your project's isolated environment.

## File I/O and JSON handling

```python
with open("data.json", "r") as f:
    import json
    data = json.load(f)

with open("output.json", "w") as f:
    json.dump({"status": "done"}, f)
```

The `with` block auto-closes the file even if an exception occurs — Python's equivalent of a `try/finally` for resource cleanup, and the idiomatic way to handle any file (or network connection, or database cursor) that needs guaranteed cleanup.

## The requests library

```python
import requests

response = requests.get("https://api.github.com/users/octocat")
data = response.json()
print(data["name"])
```

This is Python's `fetch` — the standard way to call an HTTP API, and the first thing you'll reach for building the small CLI tool in Month 1's project.

## Practice tip

Build something real quickly: a script that hits a public API, transforms the JSON response, and writes a summary to a file. That's the fastest path from "reading Python syntax" to "Python stops feeling foreign."
