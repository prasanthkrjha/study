# Python Fundamentals for ML/AI

Python is the lingua franca of machine learning and AI engineering. Unlike web JavaScript, where you can patch knowledge gaps on the fly, ML/AI codebases assume fluency with the data-manipulation primitives that underpin every model training loop, data pipeline, and inference script. The good news if you are coming from JavaScript: Python's syntax is smaller and more consistent — once you internalize list comprehensions, numpy broadcasting, and pandas DataFrames, you have the tools used in 90% of applied ML work.

This unit goes beyond basic Python syntax and targets the specific idioms that appear constantly in ML/AI code: vectorized numeric computation with NumPy, tabular data manipulation with pandas, and file I/O patterns for reading datasets and serializing results. Each of these is not just a library — it represents a different mental model for processing data efficiently without explicit loops.

By the end of this unit you should be able to load a CSV, clean it with pandas, run vectorized computations on numeric columns with NumPy, and write results back to disk — the exact workflow that precedes every model training run in Modules 7 and 8.

## Theory & Fundamentals

**Python data model for containers**: Python's four core containers have distinct performance and semantic profiles. Lists are mutable, ordered, and heterogeneous — good for general sequences but slow for numeric bulk operations. Tuples are immutable ordered sequences — lightweight and hashable (usable as dict keys). Sets are unordered collections of unique hashable values — O(1) membership tests. Dictionaries are hash maps from unique keys to arbitrary values — Python's closest equivalent to JavaScript objects, but with a richer set of built-in methods.

**NumPy arrays vs. Python lists**: A Python list holding numbers is a sequence of pointers to Python integer objects. A NumPy array is a contiguous block of typed C memory (e.g. float64). The implication is not just speed — it is a programming model shift. NumPy operations apply to the entire array at once (vectorization), executed in optimized C/Fortran code. A Python for-loop that iterates over a million-row array and multiplies each element is roughly 100x slower than the equivalent `arr * 2`. This is why ML code avoids explicit Python loops over arrays at all costs.

**pandas DataFrames as typed relational tables**: A DataFrame is two-dimensional labeled data — rows (observations) and columns (named features), each column being a typed NumPy array under the hood. pandas provides SQL-equivalent operations (filter, groupby, join, pivot) as method chains, and its dtype system (int64, float64, object, category, datetime) is what allows bulk vectorized operations on whole columns. Understanding dtypes matters because a column inferred as `object` (string) does not support numeric vectorized operations until converted.

**File I/O patterns**: Data science workflows almost always start with reading external data. Python's `open()` with a context manager (`with` block) guarantees file handles are closed regardless of exceptions. For structured data, `json`, `csv`, and `pickle` are standard library tools; pandas adds `read_csv`, `read_parquet`, `read_json` for bulk tabular I/O. Parquet is increasingly the preferred format for ML datasets because it stores typed columns with compression, dramatically faster than CSV for large files.

## Core Concepts / Techniques

**List and dict comprehensions**:
```python
# List comprehension — builds a new list with a single expression
squares = [x**2 for x in range(10)]               # [0, 1, 4, 9, ...]
evens   = [x for x in range(20) if x % 2 == 0]   # filter while building

# Dict comprehension — builds a mapping in one expression
word_lengths = {word: len(word) for word in ["cat", "elephant", "ox"]}
# {"cat": 3, "elephant": 8, "ox": 2}

# Nested comprehension — flatten a 2D list
matrix = [[1, 2], [3, 4], [5, 6]]
flat   = [item for row in matrix for item in row]  # [1, 2, 3, 4, 5, 6]
```

**NumPy essentials**:
```python
import numpy as np

# Array creation
a = np.array([1.0, 2.0, 3.0, 4.0])
zeros = np.zeros((3, 4))          # 3x4 matrix of zeros
rand  = np.random.randn(100, 5)   # 100 samples, 5 features (standard normal)

# Vectorized arithmetic — no explicit loop
b = a * 2 + 1               # [3., 5., 7., 9.]
c = np.sqrt(a)               # element-wise sqrt

# Boolean indexing
mask = a > 2                 # [False, False, True, True]
a[mask]                      # [3., 4.] — fancy indexing

# Aggregations along axes
m = np.array([[1, 2, 3], [4, 5, 6]])
m.sum(axis=0)   # column sums: [5, 7, 9]
m.mean(axis=1)  # row means:   [2., 5.]

# Reshaping
flat = np.arange(12)
grid = flat.reshape(3, 4)   # (3, 4) without copying data
```

## Code Examples

```python
"""
End-to-end data prep pipeline: load, clean, feature-engineer, save.
This pattern runs before every model training script in Modules 7/8.
"""
import numpy as np
import pandas as pd
from pathlib import Path

# 1. Load
df = pd.read_csv("raw_orders.csv", parse_dates=["created_at"])

# 2. Inspect
print(f"Shape: {df.shape}")
print(df.dtypes)
print(df.isnull().sum())  # null count per column

# 3. Clean
df = df.drop_duplicates(subset=["order_id"])
df = df.dropna(subset=["user_id", "total"])           # required fields
df["discount"] = df["discount"].fillna(0.0)            # optional field
df["product_name"] = df["product_name"].str.strip().str.lower()

# 4. Feature engineering using vectorized NumPy/pandas ops
df["revenue_after_discount"] = df["total"] * (1 - df["discount"] / 100)
df["log_revenue"] = np.log1p(df["revenue_after_discount"])  # log(1+x), handles 0

# 5. Group aggregation for a user-level feature
user_stats = (
    df.groupby("user_id")
      .agg(
          total_orders=("order_id", "count"),
          avg_revenue=("revenue_after_discount", "mean"),
          last_order_date=("created_at", "max"),
      )
      .reset_index()
)

# 6. Merge back onto the main DataFrame
df = df.merge(user_stats, on="user_id", how="left")

# 7. Select model-ready feature columns, convert to NumPy for sklearn
feature_cols = ["log_revenue", "total_orders", "avg_revenue", "discount"]
X = df[feature_cols].to_numpy()  # shape (n_samples, n_features)
y = (df["status"] == "churned").astype(int).to_numpy()

print(f"Feature matrix: {X.shape}, label distribution: {y.mean():.2%} positive")

# 8. Save
Path("processed").mkdir(exist_ok=True)
df.to_parquet("processed/orders_clean.parquet", index=False)
np.save("processed/X.npy", X)
np.save("processed/y.npy", y)
```

## Best Practices

- **Avoid Python loops over NumPy arrays or pandas columns.** Always look for a vectorized method first (`np.where`, boolean indexing, `.apply` only as a last resort). A loop that takes 2 seconds on 100k rows becomes 2 minutes on 6M rows.
- **Fit preprocessing only on training data.** When you compute means, medians, or scalers for imputation or normalization, compute them from the training split only, then apply the same values to the test/val split. Computing from the full dataset leaks test statistics into training.
- **Use explicit dtypes when reading CSVs.** `pd.read_csv("f.csv", dtype={"id": str, "price": float})` prevents pandas from silently misinterpreting an ID column of all-numeric strings as integers.
- **Prefer method chaining for readability.** Build a pipeline of `.dropna().fillna().merge()` steps in a single expression rather than reassigning `df` after each step — it is easier to comment and easier to audit the sequence.
- **Name intermediate frames descriptively.** `df_clean`, `df_with_features`, `df_train` make the pipeline stages self-documenting without verbose comments.
- **Use `Path` from `pathlib` instead of raw string paths.** `Path("data") / "raw" / "file.csv"` is OS-agnostic and supports convenient methods like `.mkdir(exist_ok=True)`.
- **Pin library versions in `requirements.txt`.** NumPy and pandas have breaking changes between major versions; a requirements file prevents silent environment mismatches when onboarding or deploying.

## Common Interview Questions

**Q: What is the difference between a NumPy array and a Python list?**
A: A NumPy array is a contiguous block of typed C memory (all elements the same dtype); a Python list is a sequence of pointers to arbitrary Python objects. NumPy arrays support vectorized operations (no Python loop), are ~100x faster for numeric computation, and have a fixed dtype. Lists are more flexible (heterogeneous types) but slow for bulk numeric work.

**Q: What does broadcasting mean in NumPy?**
A: Broadcasting is NumPy's rule for applying an operation between arrays of different shapes. When shapes are compatible (dimensions are equal or one of them is 1), NumPy stretches the smaller array conceptually to match the larger one without copying data. For example, `(3, 4) + (4,)` broadcasts the 1D array across all 3 rows.

**Q: What is the difference between `.loc` and `.iloc` in pandas?**
A: `.loc` uses label-based indexing (column names, index values); `.iloc` uses integer positional indexing (row/column number). `df.loc[0, "name"]` accesses the row with index label 0 and the column named "name"; `df.iloc[0, 0]` accesses the first row and first column by position.

**Q: What does `fit_transform` vs. `transform` mean, and why does it matter?**
A: `fit_transform` computes statistics (mean, std for a scaler) from the data and applies the transformation in one step. `transform` applies a previously fitted transformation without recomputing. For ML pipelines, always `fit_transform` on training data and `transform` only on validation/test data — computing statistics from test data leaks information and inflates evaluation metrics.

**Q: How do you handle missing values in a pandas DataFrame?**
A: Strategy depends on the column. For required fields (a row without them is unusable), drop with `dropna(subset=[...])`. For optional numeric fields, impute with median or mean using `fillna`. For categorical fields, impute with the mode or a constant "Unknown" category. Always impute using statistics computed from the training split, not the full dataset.

**Q: When would you use a list comprehension vs. a generator expression?**
A: A list comprehension (`[...]`) materializes all elements in memory at once. A generator expression (`(...)`) is lazy — it yields elements one at a time. Use generators when the sequence is very large and you only need to iterate over it once (e.g., reading lines from a large file), to avoid holding everything in RAM.

**Q: What is the difference between `merge` and `concat` in pandas?**
A: `concat` stacks DataFrames vertically (more rows, same columns) or horizontally (more columns, same rows). `merge` performs a relational join on one or more key columns — like SQL's JOIN — combining rows from two DataFrames that share a common key. Use `merge` when combining datasets with a shared ID; use `concat` when appending datasets with the same schema.

## Key Takeaways

- Python lists, tuples, sets, and dicts have distinct performance and semantic profiles — pick the right container for the job, not just the most familiar one.
- NumPy vectorization eliminates the need for explicit loops over numeric data and is the performance foundation all ML libraries are built on.
- A pandas DataFrame is a column-oriented table where each column is a typed NumPy array; operating on columns (not rows one-by-one) is the efficient, idiomatic approach.
- Always clean data before modeling: drop or impute nulls, remove duplicates, normalize string formats — garbage in, garbage out is not a cliche in ML, it is empirically verified.
- Compute preprocessing statistics (means, medians, encodings) only from the training split to avoid test data leakage.
- Prefer Parquet over CSV for intermediate ML datasets: smaller files, typed columns, faster read/write.
- List and dict comprehensions are idiomatic Python — learn to read and write them fluently, as they appear in virtually every data pipeline and ML codebase.
- The data preparation workflow (load → clean → feature-engineer → save) is not boilerplate to rush through — it often accounts for 70-80% of the total time in real ML projects.
