# LangChain Fundamentals

LangChain is a framework for the exact pipeline you already built by hand in Unit 8.3 — chunking, embedding, retrieval, prompting — plus composable building blocks for chaining these steps together and swapping providers without rewriting your logic.

## Theory & Fundamentals

### Why LangChain Exists

Every RAG pipeline and LLM application has the same structural pieces: load documents, split them into chunks, embed chunks, store in a vector database, retrieve relevant chunks, build a prompt, call the model, parse the output. Without a framework, you write custom glue code for every step and every provider combination.

LangChain provides:
1. **Standardized interfaces** — the same `retriever.invoke(query)` call works whether the retriever is Chroma, pgvector, Pinecone, or Elasticsearch.
2. **LCEL (LangChain Expression Language)** — a `|` syntax to compose steps into a pipeline without writing explicit data passing between them.
3. **Document loaders** — pre-built parsers for PDFs, web pages, CSVs, Notion, GitHub, and dozens of other sources.
4. **Provider abstractions** — swap between OpenAI, Anthropic, Ollama, and others by changing one import.

The value is real but bounded: LangChain reduces integration boilerplate. It doesn't reduce the need to understand what each step does. This is why Unit 8.3 (building RAG from scratch) comes before this one — once you've implemented chunking, embedding, and retrieval manually, you know exactly what LangChain is automating.

### LCEL: LangChain Expression Language

LCEL chains components with `|`, where each `|` passes the output of the left side as input to the right side. Every component is a "Runnable" — anything with `.invoke()`, `.batch()`, and `.stream()` methods.

## Core Patterns / Techniques

### Chains

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_template("Summarize this in one sentence: {text}")
model = ChatOpenAI(model="gpt-4o-mini")
parser = StrOutputParser()

chain = prompt | model | parser
result = chain.invoke({"text": "Long article text here..."})
```

Each `|` passes the output of one component as the input to the next — the same "retrieve → prompt → model → parse" pipeline from Unit 8.3, expressed as composable pieces.

### Document Loaders

```python
from langchain_community.document_loaders import PyPDFLoader, WebBaseLoader

# Load PDF — one Document object per page
loader = PyPDFLoader("handbook.pdf")
documents = loader.load()

# Load web page — extracts visible text
web_loader = WebBaseLoader("https://docs.example.com/getting-started")
web_docs = web_loader.load()

# Each Document has .page_content (str) and .metadata (dict)
print(documents[0].page_content[:200])
print(documents[0].metadata)  # {'source': 'handbook.pdf', 'page': 0}
```

### Text Splitters

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,     # max characters per chunk
    chunk_overlap=100,   # overlap between chunks to preserve context at boundaries
    separators=["\n\n", "\n", " ", ""]  # tries to split on paragraph, then line, then word
)

chunks = splitter.split_documents(documents)
# Returns list of Document objects with smaller page_content
```

### Retrievers

```python
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings

# Build a vector store from documents
vectorstore = Chroma.from_documents(documents, OpenAIEmbeddings())

# Expose as a retriever — consistent interface regardless of vector store backend
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

# Use it — returns list of Document objects
relevant_docs = retriever.invoke("What is Docker?")
```

### Full RAG Chain

```python
from langchain_core.runnables import RunnablePassthrough
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_template(
    "Answer the question based only on the following context:\n\n{context}\n\nQuestion: {question}"
)

def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)

answer = rag_chain.invoke("What is Docker?")
```

This is the identical four-step pipeline from Unit 8.3 — retrieve, build grounded prompt, call model, parse output — but expressed as a composable chain instead of a manual sequence of function calls.

## Best Practices

- **Understand the steps before using the abstractions** — LangChain hides complexity. If you don't know what it's doing, you can't debug it. Build the pipeline manually first (Unit 8.3), then use LangChain.
- **Use LCEL over legacy chains** — LangChain's older `LLMChain`, `ConversationalRetrievalChain`, etc. are being deprecated in favor of LCEL (`|` syntax). Start with LCEL.
- **Swap providers by changing one import** — switching from OpenAI to Anthropic means changing `from langchain_openai import ChatOpenAI` to `from langchain_anthropic import ChatAnthropic`. The rest of the chain is unchanged.
- **`.stream()` for responsive UIs** — instead of waiting for the full response, chain methods support streaming: `for chunk in chain.stream({"question": "..."})`.
- **Log intermediate steps for debugging** — use `verbose=True` or add `RunnableLambda(print)` in the chain to see what's being passed between steps.

## Common Interview Questions

**Q1: What problem does LangChain solve?**
A: Integration boilerplate. Every LLM application has the same structural pieces (load documents, chunk, embed, retrieve, prompt, generate, parse), and LangChain provides standardized interfaces so you can compose these steps with `|` and swap providers (OpenAI ↔ Anthropic ↔ local models) without rewriting the pipeline.

**Q2: What is LCEL and how does it work?**
A: LangChain Expression Language. It uses `|` to chain "Runnables" — any component with `.invoke()`, `.batch()`, `.stream()` methods. `prompt | model | parser` passes the output of the prompt component as input to the model, then the model's output to the parser. This replaces manually passing data between steps.

**Q3: What is the difference between a LangChain chain and a LangGraph agent?**
A: A chain is a fixed, linear sequence of steps (A → B → C). A LangGraph agent is a graph with conditional branching — the model decides which step to take next based on its output (e.g., call a tool, check a condition, or end). Chains work for deterministic pipelines; agents work for dynamic, multi-step reasoning.

**Q4: How do you stream output from a LangChain chain?**
A: Replace `.invoke()` with `.stream()` and iterate: `for chunk in chain.stream({"question": "..."})`. This works for the final model call in the chain, surfacing tokens as they're generated rather than waiting for the complete response.

**Q5: When would you NOT use LangChain?**
A: When you need precise control, are debugging a subtle issue, or the pipeline is simple (one prompt → one model call). LangChain adds an abstraction layer that can be opaque when something goes wrong. For production systems where you understand every step, writing explicit code is often more maintainable than adding a framework dependency.

## Key Takeaways

- LangChain standardizes the interface for document loaders, text splitters, embeddings, vector stores, and models — so the same chain logic works with any provider.
- LCEL (`|` syntax) chains Runnables: `prompt | model | parser` passes outputs left-to-right without manual data plumbing.
- The value: swap providers (OpenAI ↔ Anthropic ↔ local) and vector stores (Chroma ↔ pgvector) by changing one import.
- Use `.stream()` instead of `.invoke()` for streaming responses to a UI.
- Build from scratch first (Unit 8.3) — LangChain is most useful when you already understand what it's abstracting.
