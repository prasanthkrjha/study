# LangChain Fundamentals

LangChain is a framework for the exact pipeline you already built by hand in Unit 8.3 — chunking, embedding, retrieval, prompting — plus composable building blocks for chaining these steps together and swapping providers without rewriting your logic.

## Chains

A chain composes multiple steps (a prompt, a model call, output parsing) into one callable unit. LangChain's modern syntax uses LCEL (LangChain Expression Language), which pipes components together with `|`:

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_template("Summarize this in one sentence: {text}")
model = ChatOpenAI(model="gpt-4o-mini")
parser = StrOutputParser()

chain = prompt | model | parser
result = chain.invoke({"text": "Long article text here..."})
```

Each `|` passes the output of one component as the input to the next — the same "chunk → embed → retrieve → prompt" pipeline from Unit 8.3, expressed as composable pieces instead of manually-wired function calls.

## Document loaders

Utilities that load raw content from various sources (PDFs, web pages, CSVs, Notion, databases) into a standard `Document` object LangChain's other components expect:

```python
from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("handbook.pdf")
documents = loader.load()  # list of Document objects, one per page
```

This replaces writing your own file-parsing code for every source format you might need to ingest.

## Retrievers

An abstraction over "given a query, return relevant documents" — backed by a vector store (Chroma, pgvector, from Unit 8.4), but exposing a consistent interface regardless of which one you use underneath:

```python
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings

vectorstore = Chroma.from_documents(documents, OpenAIEmbeddings())
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

relevant_docs = retriever.invoke("What is Docker?")
```

Swapping `Chroma` for `PGVector` later requires changing this one line, not rewriting your retrieval logic — that's the actual value LangChain adds once you already understand what's happening underneath.

## Runnables

The unifying interface underneath LCEL — anything with `.invoke()`, `.batch()`, and `.stream()` methods is a "Runnable," which is why prompts, models, retrievers, and parsers can all be piped together with the same `|` syntax regardless of what they individually do.

## Prompt templates

Parameterized prompts with named placeholders, reusable across many inputs without manual string formatting:

```python
from langchain_core.prompts import ChatPromptTemplate

template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant for {domain} questions."),
    ("user", "{question}"),
])
```

## A full RAG chain in LangChain

```python
from langchain_core.runnables import RunnablePassthrough

rag_chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | prompt
    | model
    | parser
)
answer = rag_chain.invoke("What is Docker?")
```

This is the same four-step pipeline from Unit 8.3 — retrieve, build a grounded prompt, call the model, parse the output — expressed in LangChain's composable style.

## Practice tip

Rebuild your from-scratch RAG pipeline (Unit 8.3) using LangChain's document loaders, a Chroma retriever, and an LCEL chain. Because you already understand every step underneath, you'll be able to say precisely what LangChain is doing for you at each `|` — which is the difference between "I used LangChain" and "I understand what LangChain abstracts."
