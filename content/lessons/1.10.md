# Heap / Priority Queue

A heap gives you O(log n) insert and O(1) peek/remove of the min (or max) element — exactly what you need whenever a problem asks for "the k-th something" or "keep processing the smallest/largest remaining item."

## Min-heap vs. max-heap

A min-heap always keeps the smallest element at the top; a max-heap keeps the largest. JavaScript has no built-in heap, so in interviews you either implement a small binary heap or simulate one — but the concept transfers regardless of language:

```js
// Conceptual shape of a min-heap's core operations
class MinHeap {
  constructor() { this.data = []; }
  size() { return this.data.length; }
  peek() { return this.data[0]; }

  push(val) {
    this.data.push(val);
    this.#bubbleUp(this.data.length - 1);
  }

  pop() {
    const top = this.data[0];
    const last = this.data.pop();
    if (this.data.length) { this.data[0] = last; this.#bubbleDown(0); }
    return top;
  }

  #bubbleUp(i) {
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (this.data[parent] <= this.data[i]) break;
      [this.data[parent], this.data[i]] = [this.data[i], this.data[parent]];
      i = parent;
    }
  }

  #bubbleDown(i) {
    const n = this.data.length;
    while (true) {
      let smallest = i;
      const l = 2 * i + 1, r = 2 * i + 2;
      if (l < n && this.data[l] < this.data[smallest]) smallest = l;
      if (r < n && this.data[r] < this.data[smallest]) smallest = r;
      if (smallest === i) break;
      [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
      i = smallest;
    }
  }
}
```

You won't usually need to write this from scratch (most languages have a built-in priority queue), but understanding `bubbleUp`/`bubbleDown` is why insert/remove are O(log n): you only ever walk up or down one path in a balanced binary tree stored as an array.

## K-th largest / smallest

Keep a heap of size `k`: for k-th largest, use a **min-heap** of size k — push each new element, and pop whenever the heap exceeds size k. Whatever survives on top after processing everything is the k-th largest. This is O(n log k), much better than sorting the whole array (O(n log n)) when k is small.

## Merge k sorted lists

Put the head of each list into a min-heap keyed by value. Repeatedly pop the smallest, append it to the result, and push that node's successor (if any) back into the heap. This processes all `n` total elements with O(log k) work each, for O(n log k) overall — far better than merging lists two at a time.

## Recognizing the pattern

"Kth largest/smallest," "top k frequent," "merge k sorted structures," or "continuously retrieve the min/max while the data keeps changing" are the signal phrases for a heap. If sorting the whole input would work but feels wasteful because you only need a few extreme values, a heap is the fix.
