# Heap / Priority Queue

A heap is a specialized tree-based data structure that satisfies one invariant: every parent is smaller than (min-heap) or larger than (max-heap) both of its children. That single invariant means the global minimum (or maximum) is always sitting at the root, giving you O(1) access to that element and O(log n) insertion or removal. In most interview problems you never need to scan through all elements to find the best one — you just peek or pop the root.

Heaps are implemented as arrays, not pointer-based trees. The parent of index `i` lives at `Math.floor((i - 1) / 2)`, and the children of index `i` live at `2i + 1` (left) and `2i + 2` (right). This layout means a heap uses zero extra pointer memory and has excellent cache locality. Because the tree is always complete (every level is fully filled except possibly the last), the height is always exactly ⌊log₂ n⌋, which is why every sift-up or sift-down operation is O(log n).

JavaScript does not ship a built-in priority queue — a notable gap compared to Python (`heapq`) or Java (`PriorityQueue`). In interviews you either code a minimal heap from scratch (worthwhile since the code is small and reusable) or simulate one with an array and `sort`. Knowing the internals also prevents you from misusing it: pushing n elements into a heap one by one is O(n log n), but building a heap from an existing array via `heapify` (sift down every non-leaf from right to left) is O(n) — a fact that sometimes matters in the analysis of more complex algorithms.

## Theory & Fundamentals

### Heap invariant and the two flavors

- **Min-heap:** `parent ≤ children`. Root is always the global minimum.
- **Max-heap:** `parent ≥ children`. Root is always the global maximum.

The invariant is **local**: a parent only has to beat its own children, not every element in the tree. That is weaker than full sorting but sufficient to guarantee the root is extreme. When you pop the root, you fill the hole with the last element and then "sift it down" — repeatedly swapping with its smaller child (for min-heap) until the invariant is restored. When you push, you append to the end and "bubble up." Both operations follow one root-to-leaf or leaf-to-root path, so they are O(log n).

### Heap vs. sorted array vs. BST

| Operation | Heap | Sorted Array | BST (balanced) |
|---|---|---|---|
| Find min/max | O(1) | O(1) | O(log n) |
| Insert | O(log n) | O(n) | O(log n) |
| Remove min/max | O(log n) | O(n) | O(log n) |
| Search arbitrary | O(n) | O(log n) | O(log n) |

A heap wins when you only ever need the min or max — never arbitrary search. If you need both, or range queries, a BST or sorted structure is better.

### The k-th problem family

The most common heap interview pattern is maintaining a heap of fixed size k:
- **k-th largest element:** maintain a **min**-heap of size k. As you process each element, push it and then pop if size exceeds k. The root of the size-k min-heap is the k-th largest, because exactly k-1 larger elements sit above it.
- **k-th smallest element:** maintain a **max**-heap of size k. Same logic in reverse.
- **Top k frequent elements:** use a frequency map first, then a min-heap of size k keyed by frequency.

Time complexity: O(n log k). When k is much smaller than n, this beats sorting (O(n log n)) significantly.

### Merge k sorted lists / streams

Put the first element of each list into a min-heap alongside its list index and position. Pop the minimum, append it to output, and push the next element from the same list. Total work: O(N log k) where N is the total number of elements across all lists and k is the number of lists. The log k factor comes from heap operations on a heap of size at most k.

## Core Patterns / Techniques

### Pattern 1: Fixed-size heap for k-th extreme

```js
// K-th largest element in an array — O(n log k)
function findKthLargest(nums, k) {
  // Min-heap of size k: root is the k-th largest
  const heap = new MinHeap();
  for (const num of nums) {
    heap.push(num);
    if (heap.size() > k) heap.pop(); // evict the smallest when over capacity
  }
  return heap.peek(); // root = k-th largest
}
```

### Pattern 2: Top-k by frequency

```js
// Top k frequent elements — O(n log k)
function topKFrequent(nums, k) {
  // Build frequency map
  const freq = new Map();
  for (const n of nums) freq.set(n, (freq.get(n) ?? 0) + 1);

  // Min-heap keyed by frequency, keeping only top-k entries
  const heap = new MinHeap((a, b) => a[1] - b[1]); // compare by frequency
  for (const [val, count] of freq) {
    heap.push([val, count]);
    if (heap.size() > k) heap.pop();
  }

  return heap.data.map(([val]) => val);
}
```

### Pattern 3: Merge k sorted structures

```js
// Merge k sorted arrays into one sorted array
function mergeKSortedArrays(arrays) {
  const heap = new MinHeap((a, b) => a.val - b.val);
  const result = [];

  // Seed the heap with the first element of each array
  for (let i = 0; i < arrays.length; i++) {
    if (arrays[i].length > 0) {
      heap.push({ val: arrays[i][0], arrIdx: i, pos: 0 });
    }
  }

  while (heap.size() > 0) {
    const { val, arrIdx, pos } = heap.pop();
    result.push(val);
    // Push the next element from the same array
    if (pos + 1 < arrays[arrIdx].length) {
      heap.push({ val: arrays[arrIdx][pos + 1], arrIdx, pos: pos + 1 });
    }
  }
  return result;
}
```

### Pattern 4: Two-heap median maintenance

Maintain a max-heap for the lower half and a min-heap for the upper half. The median is always at one of the two roots. This gives O(log n) insert and O(1) median access.

## Code Examples

### Example 1: MinHeap implementation from scratch

```js
/**
 * A binary min-heap stored as an array.
 * Accepts an optional comparator for heaps of objects.
 */
class MinHeap {
  constructor(comparator = (a, b) => a - b) {
    this.data = [];
    this.cmp = comparator;
  }

  size() { return this.data.length; }
  peek() { return this.data[0]; }

  push(val) {
    this.data.push(val);
    this._bubbleUp(this.data.length - 1);
  }

  pop() {
    if (this.size() === 0) return undefined;
    const top = this.data[0];
    const last = this.data.pop();
    // Only sift down if there are remaining elements
    if (this.data.length > 0) {
      this.data[0] = last;
      this._siftDown(0);
    }
    return top;
  }

  _bubbleUp(i) {
    while (i > 0) {
      const parent = (i - 1) >> 1; // Math.floor((i - 1) / 2)
      if (this.cmp(this.data[parent], this.data[i]) <= 0) break; // parent is already smaller
      [this.data[parent], this.data[i]] = [this.data[i], this.data[parent]];
      i = parent;
    }
  }

  _siftDown(i) {
    const n = this.data.length;
    while (true) {
      let smallest = i;
      const left = 2 * i + 1;
      const right = 2 * i + 2;
      if (left < n && this.cmp(this.data[left], this.data[smallest]) < 0) smallest = left;
      if (right < n && this.cmp(this.data[right], this.data[smallest]) < 0) smallest = right;
      if (smallest === i) break; // already in correct position
      [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
      i = smallest;
    }
  }
}

// Verify: push 5 elements, pop in ascending order
const h = new MinHeap();
[5, 2, 8, 1, 9].forEach(n => h.push(n));
const sorted = [];
while (h.size()) sorted.push(h.pop());
console.log(sorted); // [1, 2, 5, 8, 9]
```

### Example 2: Merge k sorted linked lists

```js
/**
 * Merge k sorted linked lists into one sorted list.
 * Time: O(N log k), Space: O(k) for the heap
 * N = total nodes, k = number of lists
 */

// Simple ListNode for demonstration
class ListNode {
  constructor(val, next = null) { this.val = val; this.next = next; }
}

function mergeKLists(lists) {
  // Min-heap ordered by node value
  const heap = new MinHeap((a, b) => a.val - b.val);

  // Seed: push the head of every non-empty list
  for (const head of lists) {
    if (head !== null) heap.push(head);
  }

  const dummy = new ListNode(0); // sentinel head to simplify pointer manipulation
  let tail = dummy;

  while (heap.size() > 0) {
    const node = heap.pop();      // smallest remaining node across all lists
    tail.next = node;             // append to result
    tail = tail.next;
    if (node.next !== null) {
      heap.push(node.next);       // advance that list's pointer back into the heap
    }
  }

  return dummy.next;
}

// Build three sorted lists: [1->4->5], [1->3->4], [2->6]
const l1 = new ListNode(1, new ListNode(4, new ListNode(5)));
const l2 = new ListNode(1, new ListNode(3, new ListNode(4)));
const l3 = new ListNode(2, new ListNode(6));

let node = mergeKLists([l1, l2, l3]);
const output = [];
while (node) { output.push(node.val); node = node.next; }
console.log(output); // [1, 1, 2, 3, 4, 4, 5, 6]
```

## Best Practices

- **Simulate a max-heap in JS by negating values.** Since JS has no built-in heap, a common trick is to push `-value` into a min-heap; popping gives you `-maxValue`, which you negate back. This avoids writing a separate MaxHeap class.
- **Always remember the k-th largest uses a min-heap, not a max-heap.** It feels backwards but makes sense: a min-heap of size k keeps the k largest elements seen so far, and the smallest of those k is the k-th largest overall.
- **Never mutate heap elements after insertion.** The heap invariant only holds if values don't change. If you need a "decrease key" operation, use the lazy deletion pattern: push a new entry and mark the old one stale, then skip stale entries when you pop.
- **Heapify is O(n), not O(n log n).** If you already have all elements up front and just need to heapify once, build from the back half using siftDown. In practice, iterative insertion is fine for interview problems, but understanding heapify matters for algorithmic analysis.
- **Prefer a heap over sorting when k << n.** Sorting is O(n log n) always. A size-k heap solution is O(n log k), which is a huge win when finding, say, the 5th largest in a million elements.
- **For the two-heap median trick, balance carefully.** After each insertion, ensure the two heaps differ in size by at most 1. The median is either the root of the larger heap or the average of both roots when equal-sized.
- **When working with custom objects, provide an explicit comparator.** Comparing objects by a key (like node value or frequency) requires a comparator — default numeric comparison will not work.

## Common Interview Questions

**Q1: What is the time complexity of the k-th largest element algorithm using a heap, and why is it better than sorting?**

A: O(n log k). We process each of the n elements with a heap of size k, so each push/pop is O(log k). Sorting everything is O(n log n). When k is small (e.g., k=5 in a million-element array), O(n log k) ≈ O(n) vs O(n log n) — a meaningful speedup.

**Q2: Why use a min-heap (not max-heap) to find the k-th largest element?**

A: We maintain a min-heap of exactly k elements — the k largest seen so far. The root (minimum of those k) is the k-th largest. A max-heap would always give us the global maximum, not the k-th largest.

**Q3: What are the two invariants that a valid binary min-heap must satisfy?**

A: (1) The shape property: the tree must be a complete binary tree (all levels filled except the last, filled left to right). (2) The heap property: every parent must be ≤ both children. The shape property is what allows the compact array representation.

**Q4: How do you implement a "sliding window maximum" efficiently?**

A: Use a monotonic deque (double-ended queue), not a heap. The deque stores indices in decreasing order of their values. For each new element, pop from the back while the back element is smaller than the new element, then push the new index. The front of the deque is always the window maximum. This is O(n) total, while a heap approach would be O(n log k).

**Q5: How does the two-heap approach maintain the median of a streaming data set?**

A: Keep a max-heap for the lower half and a min-heap for the upper half. After each insertion, rebalance so sizes differ by at most 1. Median = root of the larger heap (odd total count) or average of both roots (even total count). Each operation is O(log n).

**Q6: What is the time complexity of building a heap from n elements?**

A: O(n) using heapify (sift-down from n/2 to 0). Inserting n elements one at a time is O(n log n). The difference: most sift-down operations in heapify work on short subtrees near the leaves.

**Q7: In the merge k sorted lists problem, why not just concatenate all lists and sort?**

A: Concatenation + sort is O(N log N) where N is total nodes. The heap approach is O(N log k). Since k ≤ N, log k ≤ log N, so the heap is always at least as good and often much better when k is small relative to N.

**Q8: Can you detect if an array is a valid min-heap without building one?**

A: Yes. For each non-leaf node at index i (i.e., i in range [0, Math.floor(n/2) - 1]), check that `arr[i] <= arr[2*i+1]` and (if it exists) `arr[i] <= arr[2*i+2]`. If all such checks pass, the array represents a valid min-heap. This is O(n).

## Practice Exercises

**Exercise 1 — K Closest Points to Origin (Easy)**
Given an array of points `[x, y]` in a 2D plane and an integer k, return the k closest points to the origin (0, 0). Distance is measured as √(x² + y²), but you do not need to compute the square root since you are only comparing distances.
Hint: Use a max-heap of size k keyed by squared distance. When the heap exceeds size k, pop the farthest. What remains is the k closest.

**Exercise 2 — Find Median from Data Stream (Medium)**
Design a data structure that supports two operations: `addNum(num)` inserts a number, and `findMedian()` returns the current median of all inserted numbers. Both operations should run in O(log n) and O(1) respectively.
Hint: Use two heaps. Keep all elements in the lower half in a max-heap and all in the upper half in a min-heap.

**Exercise 3 — Task Scheduler (Medium)**
Given a list of CPU tasks (each labeled A-Z) and a cooldown period n, find the minimum number of time units needed to finish all tasks, where the same task must wait at least n intervals between executions. You may insert idle slots.
Hint: Always execute the most frequent remaining task next. A max-heap of frequencies (not task identities) tracks this efficiently.

**Exercise 4 — Smallest Range Covering Elements from K Lists (Hard)**
Given k sorted lists of integers, find the smallest range `[a, b]` such that at least one number from each list lies within `[a, b]`.
Hint: Start with a min-heap containing the first element of every list. Track the current maximum. Pop the minimum, extend the range if needed, then push that element's successor. Stop when any list is exhausted.

**Exercise 5 — Rearrange String k Distance Apart (Hard)**
Given a string s and an integer k, rearrange the characters such that the same character appears at least k positions apart. Return an empty string if it is impossible.
Hint: Greedily place the most frequent remaining character at each position. Use a max-heap of (frequency, character) pairs and a cooldown queue of size k.

## Key Takeaways

- A heap guarantees O(1) access to the min (or max) and O(log n) insert/remove — the right tool whenever you repeatedly need the extreme element from a dynamic set.
- JavaScript has no built-in heap; you must implement one or simulate with sorted arrays. A generic MinHeap with a comparator covers most interview cases.
- The k-th largest element uses a **min-heap of size k** — counterintuitive but correct.
- The merge k sorted lists pattern generalizes to any problem where you're pulling from k sources simultaneously and need the globally smallest next element.
- The two-heap trick (max-heap lower half + min-heap upper half) is the canonical O(log n) insert / O(1) median solution.
- "Heapify from scratch" is O(n), but inserting n elements one at a time is O(n log n) — know the difference when analyzing algorithms.
- The lazy deletion pattern (push a new entry and skip stale ones on pop) lets you handle "decrease key" without modifying heap internals.
- When k is much smaller than n, heap-based solutions are substantially faster than sorting the entire array.
