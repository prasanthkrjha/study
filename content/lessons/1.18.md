# Bit Manipulation & Math

This unit is a grab-bag of tricks that show up as one-off "gotcha" problems, plus the number-theory basics you need to reason about arithmetic problems correctly. These topics are less systematic than the rest of the DSA curriculum — the interview value comes from recognizing the pattern, not from a deep theoretical foundation.

## Theory & Fundamentals

### Binary Representation

Every integer is stored as a sequence of bits. In a 32-bit integer, the rightmost bit has place value 1 (2⁰), the next has value 2 (2¹), and so on. Bit operations work directly on these binary digits:

| Operator | Name | Example | Result |
|----------|------|---------|--------|
| `&` | AND | `5 & 3` = `101 & 011` | `001` = 1 |
| `\|` | OR | `5 \| 3` = `101 \| 011` | `111` = 7 |
| `^` | XOR | `5 ^ 3` = `101 ^ 011` | `110` = 6 |
| `~` | NOT | `~5` = `~00101` | `11010` (−6 in 2s complement) |
| `<<` | Left shift | `1 << 3` | `1000` = 8 |
| `>>` | Right shift | `8 >> 2` | `10` = 2 |

### XOR Properties

XOR (`^`) has three properties that make it uniquely useful:
- `a ^ a = 0` (any value XOR itself is zero)
- `a ^ 0 = a` (identity element)
- Commutative and associative (order doesn't matter)

These three properties together mean: if you XOR a sequence of numbers where every value appears an even number of times except one, the result is that one unpaired value. All pairs cancel to zero.

### Two's Complement

Negative numbers in binary use two's complement representation: −n = ~n + 1. This is why `n & -n` isolates the lowest set bit — `-n` flips all bits and adds 1, which turns the trailing zeros into ones and the first 1 into a 0 with a carry, isolating the original lowest set bit.

## Core Patterns / Techniques

### XOR Tricks

```js
// Find the single number in an array where every other appears twice
// O(n) time, O(1) space — XOR cancels pairs
function singleNumber(nums) {
  return nums.reduce((acc, n) => acc ^ n, 0);
}
// [2, 1, 2] → 2^1^2 = 1

// Swap without temp variable (useful in C; in JS, prefer destructuring)
a ^= b; b ^= a; a ^= b;   // swaps a and b
// Explanation: after step 1, a = a^b; step 2, b = (a^b)^b = a; step 3, a = (a^b)^a = b
```

### Bit Inspection and Manipulation

```js
// Check if bit i is set
const isSet = (n, i) => (n >> i) & 1;

// Set bit i (turn it on)
const setBit = (n, i) => n | (1 << i);

// Clear bit i (turn it off)
const clearBit = (n, i) => n & ~(1 << i);

// Toggle bit i
const toggleBit = (n, i) => n ^ (1 << i);

// Check if n is a power of 2
const isPow2 = (n) => n > 0 && (n & (n - 1)) === 0;
// n = 8 = 1000, n-1 = 7 = 0111 → 1000 & 0111 = 0 → true

// Count set bits (Brian Kernighan's algorithm)
function countBits(n) {
  let count = 0;
  while (n) {
    n &= n - 1;   // clear lowest set bit
    count++;
  }
  return count;
}
// Each iteration removes one set bit → O(number of set bits)
```

### Bitmasking for Subsets

A bitmask of k bits can represent all subsets of a k-element set. Bit i = 1 means "element i is included."

```js
// Enumerate all subsets of nums
function allSubsets(nums) {
  const n = nums.length;
  const results = [];

  for (let mask = 0; mask < (1 << n); mask++) {
    const subset = [];
    for (let i = 0; i < n; i++) {
      if (mask & (1 << i)) subset.push(nums[i]);  // bit i is set → include nums[i]
    }
    results.push(subset);
  }
  return results;
}
// 2^n subsets total — O(n * 2^n) time
```

Bitmasking also underlies "DP over subsets" problems (traveling salesman, optimal assignment) where the bitmask IS the DP state.

### Number Theory Essentials

```js
// Euclidean GCD — O(log(min(a,b)))
function gcd(a, b) {
  return b === 0 ? a : gcd(b, a % b);
}

// LCM — uses GCD to avoid overflow: (a/gcd)*b instead of (a*b)/gcd
function lcm(a, b) {
  return (a / gcd(a, b)) * b;
}

// Check primality — O(sqrt(n))
function isPrime(n) {
  if (n < 2) return false;
  for (let i = 2; i * i <= n; i++) {
    if (n % i === 0) return false;
  }
  return true;
}

// Sieve of Eratosthenes — find all primes up to n, O(n log log n)
function sieve(n) {
  const isPrime = new Array(n + 1).fill(true);
  isPrime[0] = isPrime[1] = false;
  for (let i = 2; i * i <= n; i++) {
    if (isPrime[i]) {
      for (let j = i * i; j <= n; j += i) isPrime[j] = false;
    }
  }
  return isPrime.reduce((acc, v, i) => (v ? [...acc, i] : acc), []);
}
```

### Modular Arithmetic

When a problem says "return the answer modulo 10⁹+7," the true answer can be astronomically large. Key rules:

```js
const MOD = 1_000_000_007;

// Addition: (a + b) % m is correct
const add = (a, b) => (a + b) % MOD;

// Multiplication: (a * b) % m is correct
const mul = (a, b) => (a * b) % MOD;

// Subtraction: must add MOD to prevent negative result
const sub = (a, b) => ((a - b) % MOD + MOD) % MOD;

// Division: NOT (a / b) % m — requires modular inverse
// For prime modulus p: a^(p-2) mod p (Fermat's little theorem)
// In most interview problems, you apply mod after every add/multiply step
```

**Critical rule**: Apply mod after every multiplication and addition, not just at the end. JavaScript numbers lose precision for integers beyond 2^53 — if you multiply first and mod last, you may get wrong results.

## Code Examples

### Example 1: Number of 1 Bits (Hamming Weight)

```js
// Three approaches, each O(1) since integers are fixed 32-bit
function hammingWeight(n) {
  // Approach 1: Brian Kernighan — fastest for sparse bit patterns
  let count = 0;
  while (n !== 0) {
    n &= n - 1;    // clear lowest set bit
    count++;
  }
  return count;
}

// Approach 2: Check each bit position
function hammingWeightLinear(n) {
  let count = 0;
  for (let i = 0; i < 32; i++) {
    if ((n >> i) & 1) count++;
  }
  return count;
}

// Approach 3: Built-in (not always available in interviews)
// n.toString(2).split('').filter(b => b === '1').length
```

### Example 2: Sum of Two Integers Without + Operator

```js
// Use bit manipulation to implement addition
// a ^ b = sum without carry
// (a & b) << 1 = carry bits

function getSum(a, b) {
  while (b !== 0) {
    const carry = (a & b) << 1;  // carry propagates one position left
    a = a ^ b;                    // sum without carry
    b = carry;                    // next iteration processes the carry
  }
  return a;
}
// Terminates because each iteration reduces the number of set bits in b
```

### Example 3: Subsets via Bitmask

```js
// Find all subsets of nums that sum to a target
function subsetSum(nums, target) {
  const n = nums.length;
  const result = [];

  for (let mask = 0; mask < (1 << n); mask++) {
    let sum = 0;
    const subset = [];

    for (let i = 0; i < n; i++) {
      if (mask & (1 << i)) {
        sum += nums[i];
        subset.push(nums[i]);
      }
    }
    if (sum === target) result.push(subset);
  }
  return result;
}
// O(n * 2^n) — only feasible for small n (up to ~20)
```

## Best Practices

- **Recognize the XOR "cancelation" pattern quickly** — "find the unique element," "find missing number," or "two arrays where one has an extra element" are all XOR problems.
- **Use `n & (n-1)` to clear the lowest bit** — the building block for counting set bits and checking powers of 2.
- **Apply modular arithmetic after every multiply and add** — not just at the end. `(a * b) % MOD` before accumulating, every iteration.
- **Bitmask DP is feasible up to n ≈ 20** — 2²⁰ ≈ 1 million, which is tractable. 2³⁰ ≈ 1 billion is not.
- **Be careful with signed integer shifts** — `>>` in JavaScript is arithmetic (sign-extends), `>>>` is logical (zero-fills). For bit counting over all 32 bits, use `>>> 0` to treat the number as unsigned.
- **Primality check is O(√n)** — for a single number. For all primes up to N, use the Sieve of Eratosthenes: O(N log log N).

## Common Interview Questions

**Q1: How do you check if a number is a power of 2?**
A: `n > 0 && (n & (n - 1)) === 0`. Powers of 2 have exactly one set bit; subtracting 1 flips all lower bits to 1 and the set bit to 0, so the AND is zero.

**Q2: Given an array where every integer appears three times except one, which appears once — find the unique one.**
A: The simple XOR trick doesn't work (it cancels pairs, not triples). Use a bitwise approach: for each bit position, count how many numbers have that bit set. If the count % 3 ≠ 0, the unique number has that bit set. O(32n) = O(n) time.

**Q3: What does `n & -n` give you?**
A: The lowest set bit of n. `-n` in two's complement flips all bits of n and adds 1. The trailing zeros of n become ones in -n; the first set bit stays a 1 (with a carry clearing the higher bits). The AND isolates just that bit.

**Q4: Why does modular arithmetic work for addition and multiplication but not division?**
A: `(a + b) % m = (a%m + b%m) % m` holds because addition distributes over mod. For division: `(a/b) % m ≠ (a%m) / (b%m)` in general. To divide modulo m, you need the modular inverse of b: `a * b^(m-2) mod m` (using Fermat's little theorem, valid when m is prime). Most interview problems don't require this.

**Q5: How many subsets does an n-element set have?**
A: 2ⁿ. Each element can independently be included or excluded.

**Q6: What is the time complexity of Euclid's GCD algorithm?**
A: O(log(min(a, b))). Each step reduces the problem to gcd(b, a%b), and the pair (a, b) decreases at least by a factor of 2 every two steps (by the Fibonacci-worst-case analysis).

## Practice Exercises

**Exercise 1 — Single Number (Easy)**
Given an array where every element appears twice except one, find that single element in O(n) time and O(1) space. Hint: XOR all elements.

**Exercise 2 — Counting Bits (Easy)**
Given n, return an array where `ans[i]` = number of 1s in the binary representation of i, for all 0 ≤ i ≤ n. Can you do it in O(n) using previously computed values?
Hint: `countBits(i) = countBits(i >> 1) + (i & 1)`. The number of bits in i equals the number of bits in i/2, plus 1 if i is odd.

**Exercise 3 — Missing Number (Easy-Medium)**
Given an array containing n distinct numbers from 0 to n with one missing, find the missing number. Two approaches: XOR, or Gauss sum formula `n*(n+1)/2 - sum(nums)`.

**Exercise 4 — Reverse Bits (Medium)**
Reverse the bits of a 32-bit unsigned integer. Hint: process bit by bit from right to left, shifting the result left each iteration.

**Exercise 5 — Maximum XOR of Two Numbers in an Array (Hard)**
Find the maximum XOR of any two numbers in an array. Brute force is O(n²). Use a trie (bit trie) for O(32n) — insert all numbers bit by bit from MSB, then for each number greedily look for the complement bit at each level.

## Key Takeaways

- XOR's three properties (`a^a=0`, `a^0=a`, commutativity) explain the single-number trick: XOR everything and paired values cancel.
- `n & (n-1)` clears the lowest set bit — use it to count set bits (Brian Kernighan) or check powers of 2.
- `n & -n` isolates the lowest set bit — useful in Fenwick trees and some bit DP.
- Bitmasks represent subsets of small sets (n ≤ 20) as integers, enabling O(n·2ⁿ) enumeration and bitmask DP.
- Apply `% MOD` after every addition and multiplication — not just at the end — to prevent overflow.
- GCD via Euclid's algorithm is O(log min(a,b)); primality testing is O(√n); the Sieve finds all primes up to N in O(N log log N).
