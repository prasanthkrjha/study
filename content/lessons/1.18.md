# Bit Manipulation & Math

This unit is a grab-bag of tricks that show up as one-off "gotcha" problems, plus the number-theory basics you need to reason about arithmetic problems correctly.

## XOR tricks

XOR (`^`) has three properties that make it uniquely useful: `a ^ a = 0`, `a ^ 0 = a`, and it's commutative/associative (order doesn't matter). That's the entire explanation for the classic "find the single number in an array where every other number appears twice" — XOR everything together and every pair cancels out, leaving only the unpaired value:

```js
function singleNumber(nums) {
  return nums.reduce((acc, n) => acc ^ n, 0);
}
```

XOR is also how you swap two variables without a temp variable (`a ^= b; b ^= a; a ^= b;`), though in practice destructuring (`[a, b] = [b, a]`) is clearer in JS — the trick is worth recognizing when you see it in older code or C-style languages.

## Bitmasking

Represent a **set of up to ~30 boolean flags** as a single integer, where bit `i` being 1 means "item i is included." This turns subset enumeration into iterating integers from `0` to `2ⁿ - 1`:

```js
function allSubsets(nums) {
  const n = nums.length;
  const results = [];
  for (let mask = 0; mask < (1 << n); mask++) {
    const subset = [];
    for (let i = 0; i < n; i++) {
      if (mask & (1 << i)) subset.push(nums[i]);
    }
    results.push(subset);
  }
  return results;
}
```

Bitmasking also underlies "DP with state = which items have been used" problems (traveling salesman-style DP), where the mask **is** the DP state.

## Useful bit operations to have memorized

- `n & (n - 1)` clears the lowest set bit — used to count set bits (Brian Kernighan's algorithm) or check if `n` is a power of two (`n & (n-1) === 0`).
- `n & -n` isolates the lowest set bit.
- `n << k` / `n >> k` multiply/divide by `2^k`.

## GCD / LCM

Euclid's algorithm computes GCD in O(log(min(a,b))) — much faster than checking every number up to `min(a,b)`:

```js
function gcd(a, b) {
  return b === 0 ? a : gcd(b, a % b);
}
function lcm(a, b) {
  return (a * b) / gcd(a, b);
}
```

## Modular arithmetic

When a problem says "return the answer modulo 10⁹+7," it's a signal the true answer is enormous (common in combinatorics/DP counting problems) and would overflow fixed-size integers in other languages. Key rules: `(a + b) % m = ((a % m) + (b % m)) % m`, and similarly for multiplication — but **not** for division, which needs modular inverses (rarely required at this level; usually just apply mod after every addition/multiplication step to keep numbers small).

## Recognizing the pattern

"Find the one element that's different/unpaired" → XOR. "Track which of up to ~20-30 items are used" → bitmask. Any problem explicitly mentioning "modulo 10^9 + 7" → apply mod after every arithmetic operation, not just at the end.
