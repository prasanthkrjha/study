# Tries

A trie (prefix tree) is a tree where **each path from the root spells out a prefix**, and it exists to answer one question extremely fast: "does any word in my dictionary start with this prefix?"

## Structure

Each node holds a map of `character -> child node`, plus a flag for "a word ends here":

```js
class TrieNode {
  constructor() {
    this.children = new Map();
    this.isWord = false;
  }
}

class Trie {
  constructor() { this.root = new TrieNode(); }

  insert(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch);
    }
    node.isWord = true;
  }

  search(word) {
    const node = this.#walk(word);
    return !!node && node.isWord;
  }

  startsWith(prefix) {
    return !!this.#walk(prefix);
  }

  #walk(str) {
    let node = this.root;
    for (const ch of str) {
      if (!node.children.has(ch)) return null;
      node = node.children.get(ch);
    }
    return node;
  }
}
```

Both `insert` and `search`/`startsWith` are O(k) where `k` is the word/prefix length — completely independent of how many words are stored. That's the whole point: a hashset of strings can tell you "is this exact word present," but it can't answer "does any word start with this prefix" without scanning every entry.

## Prefix / autocomplete patterns

Autocomplete is: walk the trie to the end of the typed prefix, then DFS from that node collecting every complete word below it. Word search on a grid (finding trie-stored words embedded in a 2D board) combines a trie with DFS/backtracking — you walk the grid and the trie in lockstep, pruning as soon as the current path isn't a valid prefix in the trie.

## Recognizing the pattern

Any problem that repeatedly asks "does a prefix exist," "autocomplete," or "search a dictionary of words against a grid" wants a trie. If you find yourself scanning a whole word list per query, a trie is almost certainly the intended structure.
