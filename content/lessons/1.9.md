# Tries

A trie (prefix tree) is a tree where **each path from the root spells out a prefix**, and it exists to answer one question extremely fast: "does any word in my dictionary start with this prefix?" Unlike a hash set (which can only check exact membership), a trie exposes prefix structure — making it the right tool for autocomplete, spell checking, and word-search-in-a-grid problems.

## Theory & Fundamentals

### Structure and Complexity

Each trie node holds:
- A map from character → child node
- A boolean flag: "does a word end at this node?"

The root represents the empty string. Each edge represents one character. A complete word is spelled by following edges from root to a node where `isWord = true`.

**Complexity:**
- `insert(word)`: O(k) where k = word length
- `search(word)`: O(k)
- `startsWith(prefix)`: O(k)
- Space: O(ALPHABET_SIZE × total characters inserted) — up to O(26n) for lowercase English

All operations are O(k) regardless of how many words are stored. A hash set can check exact membership in O(k) (hashing the word), but cannot answer prefix queries without scanning all entries. That's the trie's specific advantage.

### When to Use a Trie

Use a trie when:
1. You need prefix lookup ("does any stored word start with X?")
2. You need autocomplete / next-character suggestions
3. You need to search a grid for words from a dictionary (word search II)
4. You need to find the longest word built from other words in a list

A hash set suffices when you only need exact membership. A trie is the upgrade when prefix structure matters.

## Core Patterns / Techniques

### Basic Trie Implementation

```js
class TrieNode {
  constructor() {
    this.children = new Map();
    this.isWord = false;
  }
}

class Trie {
  constructor() { this.root = new TrieNode(); }

  insert(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch);
    }
    node.isWord = true;
  }

  search(word) {
    const node = this._walk(word);
    return !!node && node.isWord;
  }

  startsWith(prefix) {
    return !!this._walk(prefix);
  }

  _walk(str) {
    let node = this.root;
    for (const ch of str) {
      if (!node.children.has(ch)) return null;
      node = node.children.get(ch);
    }
    return node;
  }
}
```

### Autocomplete: DFS from Prefix Node

Once you've walked to the end of a typed prefix, collect all words reachable from that node:

```js
function autocomplete(trie, prefix) {
  const prefixNode = trie._walk(prefix);
  if (!prefixNode) return [];

  const results = [];
  function dfs(node, current) {
    if (node.isWord) results.push(current);
    for (const [ch, child] of node.children) {
      dfs(child, current + ch);
    }
  }
  dfs(prefixNode, prefix);
  return results;
}
// Time: O(k + W) where k = prefix length, W = total chars of all matching words
```

### Word Search II Pattern (Trie + Backtracking)

The classic "find all words from a dictionary in a grid" problem combines trie with DFS backtracking:

```js
function findWords(board, words) {
  const trie = new Trie();
  for (const w of words) trie.insert(w);

  const found = new Set();
  const rows = board.length, cols = board[0].length;

  function dfs(node, r, c, path) {
    if (r < 0 || r >= rows || c < 0 || c >= cols || board[r][c] === '#') return;
    const ch = board[r][c];
    const child = node.children.get(ch);
    if (!child) return;          // prune: not a valid prefix

    path += ch;
    if (child.isWord) found.add(path);

    board[r][c] = '#';           // mark visited
    dfs(child, r+1, c, path);
    dfs(child, r-1, c, path);
    dfs(child, r, c+1, path);
    dfs(child, r, c-1, path);
    board[r][c] = ch;            // restore
  }

  for (let r = 0; r < rows; r++)
    for (let c = 0; c < cols; c++)
      dfs(trie.root, r, c, "");

  return [...found];
}
```

The trie enables pruning: as soon as the current grid path diverges from all dictionary words, the recursion stops. Without a trie, you'd check each word independently — O(W × 4^(grid size)) vs. O(4^(grid size)) total with trie-based pruning.

## Code Examples

### Example 1: Design Add and Search Words Data Structure

This problem requires supporting `.` as a wildcard matching any character:

```js
class WordDictionary {
  constructor() { this.root = new TrieNode(); }

  addWord(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch);
    }
    node.isWord = true;
  }

  search(word) {
    return this._dfs(this.root, word, 0);
  }

  _dfs(node, word, i) {
    if (i === word.length) return node.isWord;

    const ch = word[i];
    if (ch === '.') {
      // Wildcard: try all children
      for (const child of node.children.values()) {
        if (this._dfs(child, word, i + 1)) return true;
      }
      return false;
    } else {
      if (!node.children.has(ch)) return false;
      return this._dfs(node.children.get(ch), word, i + 1);
    }
  }
}
// addWord: O(k) — k = word length
// search: O(26^d) worst case for all-wildcard patterns of depth d
```

### Example 2: Replace Words (Prefix Replacement)

Given a list of root words and a sentence, replace each word in the sentence with its shortest root:

```js
function replaceWords(dictionary, sentence) {
  const trie = new Trie();
  for (const root of dictionary) trie.insert(root);

  return sentence.split(' ').map(word => {
    let node = trie.root;
    for (let i = 0; i < word.length; i++) {
      const ch = word[i];
      if (!node.children.has(ch)) break;   // no root matches: keep word
      node = node.children.get(ch);
      if (node.isWord) return word.slice(0, i + 1);  // found root
    }
    return word;
  }).join(' ');
}
// O(total chars in dictionary + total chars in sentence)
```

## Best Practices

- **Use an array of size 26 instead of Map for lowercase English** — `children = new Array(26).fill(null)` is faster and uses less memory than a Map for the common case of lowercase-only inputs.
- **Prune aggressively in word search** — once the trie path is dead (no child for current char), return immediately. This is what makes trie+DFS tractable for grid search.
- **Remove found words from the trie** to avoid duplicates in word search — set `node.isWord = false` when a word is found.
- **Store the word at the end node** to avoid reconstructing it from the path — for word search problems, storing `node.word = word` at the end node simplifies collection.
- **Recognize prefix problems quickly** — any problem mentioning "prefix," "autocomplete," "starts with," or "dictionary of words" is a trie candidate.

## Common Interview Questions

**Q1: What is the time complexity of inserting and searching in a trie?**
A: O(k) where k is the length of the word or prefix — independent of the number of words stored. A hash set is also O(k) for exact lookup (hashing the word), but can't answer prefix queries without scanning all entries.

**Q2: When would you use a trie vs. a hash set?**
A: Hash set for exact membership checks. Trie when you need prefix queries, autocomplete, or to search for multiple words simultaneously (word search grid). A trie also gives you sorted iteration over stored words (DFS in lexicographic order).

**Q3: What's the space complexity of a trie?**
A: O(ALPHABET_SIZE × total_characters). For 26 lowercase letters and n total characters, that's O(26n) in the worst case (no shared prefixes). In practice, shared prefixes reduce this significantly — that's the whole point of the trie.

**Q4: How would you delete a word from a trie?**
A: Walk to the end node and set `isWord = false`. If the node has no children and isn't a word endpoint, you can also remove the node and backtrack up, pruning unused nodes. In most interview problems, deletion isn't needed.

**Q5: What does the word search II problem look like without a trie?**
A: For each word in the dictionary, run a separate DFS over the grid — O(W × R × C × 4^min(word, grid)) total. With a trie, you run one DFS and all words are checked simultaneously — much more efficient when the dictionary is large.

## Practice Exercises

**Exercise 1 — Implement Trie (Beginner)**
Implement a Trie class with insert, search, and startsWith methods. Test it with: insert "apple," search "apple" → true, search "app" → false, startsWith "app" → true.

**Exercise 2 — Longest Common Prefix (Beginner-Intermediate)**
Given an array of strings, find the longest common prefix. Hint: insert all strings into a trie; walk down until you hit a fork (more than one child) or a word end.

**Exercise 3 — Word Search II (Intermediate)**
Given a 2D board and a word list, find all words from the list that can be formed in the board (horizontal/vertical adjacency, no cell reuse). Build a trie from the word list, then DFS the board using trie nodes for pruning.

**Exercise 4 — Palindrome Pairs (Advanced)**
Given a list of words, find all pairs of indices (i, j) such that words[i] + words[j] is a palindrome. A trie-based approach is one solution — insert reversed words, then for each word, walk the trie checking palindrome conditions at each node.

## Key Takeaways

- A trie stores strings character-by-character, with shared prefixes sharing nodes — enabling O(k) prefix lookup.
- The isWord flag distinguishes nodes that mark a complete word from intermediate prefix nodes.
- Autocomplete is: walk to the prefix node, then DFS to collect all complete words below.
- Word search grid problems combine trie (dictionary) with DFS+backtracking (grid traversal) — the trie enables pruning when the current path isn't a valid prefix.
- Trie vs. hash set: both give O(k) exact lookup, but only the trie answers "does any stored word start with this prefix?" efficiently.
