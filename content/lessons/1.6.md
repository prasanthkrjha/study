# Binary Search

Binary search isn't just "find a value in a sorted array" — it's a general technique for cutting a search space in half whenever you can answer "is the target to the left or right of here?" in O(1).

## The classic form

```js
function binarySearch(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2); // avoids overflow, and avoids re-checking mid
    if (nums[mid] === target) return mid;
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid - 1;
  }
  return -1;
}
```

Two things trip people up: using `mid = (lo + hi) / 2` (fine in JS, but the habit matters in languages with fixed-width integers), and getting the loop condition (`<=` vs `<`) wrong, which causes infinite loops or missed elements.

## "Search on the answer"

This is the pattern that turns binary search from a lookup trick into a genuine algorithm design tool. Instead of searching an array, you binary-search over the **space of possible answers** — useful whenever the problem has a monotonic "if X works, does X+1 also work?" property.

Example: "minimum days to make m bouquets" or "split array into k subarrays minimizing the largest sum" — you binary search over the candidate answer value, and for each candidate, run an O(n) feasibility check:

```js
function canSplit(nums, k, maxSum) {
  let pieces = 1, current = 0;
  for (const n of nums) {
    if (current + n > maxSum) { pieces++; current = n; }
    else current += n;
  }
  return pieces <= k;
}

function splitArray(nums, k) {
  let lo = Math.max(...nums), hi = nums.reduce((a, b) => a + b, 0);
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (canSplit(nums, k, mid)) hi = mid; else lo = mid + 1;
  }
  return lo;
}
```

## Rotated sorted arrays

A rotated sorted array (e.g. `[4,5,6,7,0,1,2]`) is still binary-searchable — at every midpoint, **one half is always properly sorted**. Check which half is sorted, then decide whether the target lies in that sorted half or the other one.

## Recognizing the pattern

- The array is sorted (or "sorted with a rotation").
- The problem asks for a minimum/maximum value satisfying a condition, and that condition is monotonic (once true, stays true as the candidate increases, or vice versa) — "search on the answer" applies even with no array in sight.
