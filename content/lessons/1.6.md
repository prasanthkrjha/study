# Binary Search

Binary search is the canonical example of divide-and-conquer: instead of scanning every element, you eliminate half the search space with each comparison. The result is O(log n) — for n = 10⁹, only about 30 comparisons are needed. That is not just a speed improvement; it is the difference between "runs in milliseconds" and "runs in hours."

The pattern's scope goes far beyond "find a value in a sorted array." Whenever you can express the problem as "find the smallest (or largest) value satisfying some monotonic condition," binary search on the answer space gives you an O(log(max - min) × O(feasibility check)) algorithm. This "search on the answer" technique transforms a class of optimization problems that look unsolvable in isolation into straightforward binary searches plus an O(n) feasibility check.

The single biggest source of bugs in binary search is the loop boundary and the update rules. There are two canonical forms — `lo <= hi` with `lo = mid + 1` / `hi = mid - 1`, and `lo < hi` with `lo = mid + 1` / `hi = mid` — and each has specific use cases. Mastering both eliminates the infinite-loop and off-by-one bugs that end interviews prematurely.

## Theory & Fundamentals

### Why O(log n)?

After k iterations of halving, the remaining search space is n / 2^k. The search ends when n / 2^k = 1, i.e., k = log₂(n). So binary search makes exactly ⌈log₂(n)⌉ comparisons in the worst case.

```
n=1000:   log₂(1000) ≈ 10 comparisons
n=10⁶:   log₂(10⁶) ≈ 20 comparisons
n=10⁹:   log₂(10⁹) ≈ 30 comparisons
```

This is why binary search is used on sorted data: the sorted order is what makes "is the target to the left or right?" an O(1) decision.

### The Two Canonical Forms

**Form 1: find exact target** — use `lo <= hi`, update with `lo = mid + 1` or `hi = mid - 1`. Loop exits when `lo > hi`.

**Form 2: find leftmost/rightmost value satisfying a condition** — use `lo < hi`, update with `lo = mid + 1` or `hi = mid`. Loop exits when `lo === hi`, which is the answer.

The key difference: Form 2 never excludes `mid` from the right side (`hi = mid`, not `hi = mid - 1`) because `mid` might itself be the answer.

### Overflow-Safe Midpoint

In languages with fixed-width integers, `(lo + hi) / 2` can overflow when `lo + hi > MAX_INT`. The safe version is `lo + Math.floor((hi - lo) / 2)`. In JavaScript numbers are 64-bit floats, so overflow is not a practical concern, but writing the safe form is a good habit for language-agnostic interviews.

### The Monotonic Property (Search on Answer)

"Search on the answer" requires a **monotonic predicate** P: a function from the answer space to {true, false} such that once P(x) is true, it's true for all values beyond x, and once false, it's false for all values before x.

```
Answer space:  [lo ........ boundary ........ hi]
P(x):          false false false TRUE TRUE TRUE TRUE
                                  ^
                                  find this boundary
```

Binary search finds the boundary in O(log(hi - lo)) by checking P(mid) and halving accordingly.

## Core Patterns / Techniques

### Pattern 1: Classic Binary Search (Exact Match)

```js
function binarySearch(nums, target) {
  let lo = 0;
  let hi = nums.length - 1;

  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (nums[mid] === target) return mid;
    if (nums[mid] < target) lo = mid + 1; // target is in right half
    else hi = mid - 1;                     // target is in left half
  }
  return -1; // not found
}
// Time: O(log n)  Space: O(1)
```

### Pattern 2: Leftmost Position (First Occurrence)

```js
// Find the leftmost index where nums[i] >= target (lower bound)
function lowerBound(nums, target) {
  let lo = 0;
  let hi = nums.length; // note: hi is nums.length, not nums.length - 1

  while (lo < hi) {    // note: strict <, not <=
    const mid = lo + Math.floor((hi - lo) / 2);
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid;     // mid might be the answer — don't exclude it
  }
  return lo; // lo === hi at termination
}
// Returns nums.length if no element >= target exists
```

### Pattern 3: Search on Answer — Minimize Maximum

```js
// Split array into k non-empty subarrays to minimize the maximum subarray sum.
// Binary search over the answer (possible max sums) from max(nums) to sum(nums).

function canSplit(nums, k, maxSum) {
  let pieces = 1;
  let current = 0;
  for (const n of nums) {
    if (current + n > maxSum) {
      pieces++;
      current = n;
      if (pieces > k) return false;
    } else {
      current += n;
    }
  }
  return true;
}

function splitArray(nums, k) {
  let lo = Math.max(...nums); // minimum possible max (at least the largest element)
  let hi = nums.reduce((a, b) => a + b, 0); // maximum possible (all in one piece)

  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (canSplit(nums, k, mid)) hi = mid; // mid works, try smaller
    else lo = mid + 1;                     // mid too small, need larger
  }
  return lo; // the smallest valid maximum sum
}
// Time: O(n log(sum))  Space: O(1)
```

### Pattern 4: Search in Rotated Sorted Array

```js
// Find target in a sorted array that has been rotated at an unknown pivot.
function searchRotated(nums, target) {
  let lo = 0;
  let hi = nums.length - 1;

  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (nums[mid] === target) return mid;

    // Determine which half is properly sorted
    if (nums[lo] <= nums[mid]) {
      // Left half [lo..mid] is sorted
      if (nums[lo] <= target && target < nums[mid]) {
        hi = mid - 1; // target in the sorted left half
      } else {
        lo = mid + 1; // target in the right half
      }
    } else {
      // Right half [mid..hi] is sorted
      if (nums[mid] < target && target <= nums[hi]) {
        lo = mid + 1; // target in the sorted right half
      } else {
        hi = mid - 1; // target in the left half
      }
    }
  }
  return -1;
}
// Time: O(log n)  Space: O(1)
```

### Pattern 5: Find Peak Element

```js
// A peak element is greater than its neighbors. Find any peak index.
// Works even on unsorted arrays due to the local monotonic property.
function findPeakElement(nums) {
  let lo = 0;
  let hi = nums.length - 1;

  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    // If mid's right neighbor is larger, there must be a peak to the right
    if (nums[mid] < nums[mid + 1]) lo = mid + 1;
    else hi = mid; // mid is larger, peak is here or to the left
  }
  return lo;
}
// Time: O(log n)  Space: O(1)
```

## Code Examples

### Example 1: Koko Eating Bananas (Search on Answer)

```js
/**
 * Koko has piles of bananas and h hours. She eats at speed k bananas/hour
 * (one pile per hour; leftover bananas in a pile don't carry over).
 * Find the minimum speed k to eat all bananas within h hours.
 *
 * Observation: if speed k works, speed k+1 also works → monotonic predicate.
 * Binary search over k in [1, max(piles)].
 *
 * Time: O(n log m) where m = max pile size   Space: O(1)
 */
function minEatingSpeed(piles, h) {
  // Can Koko finish all piles at speed k within h hours?
  const canFinish = (k) => {
    let hours = 0;
    for (const pile of piles) {
      hours += Math.ceil(pile / k);
    }
    return hours <= h;
  };

  let lo = 1;                         // minimum possible speed
  let hi = Math.max(...piles);        // eating fastest pile in 1 hour always works

  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (canFinish(mid)) hi = mid;     // speed mid works, try lower
    else lo = mid + 1;               // speed mid too slow
  }
  return lo;
}

console.log(minEatingSpeed([3,6,7,11], 8));  // 4
console.log(minEatingSpeed([30,11,23,4,20], 5)); // 30
```

### Example 2: Find Minimum in Rotated Sorted Array

```js
/**
 * Given a sorted array rotated at some unknown pivot, find the minimum.
 * Example: [3,4,5,1,2] → minimum is 1 (rotated from [1,2,3,4,5]).
 *
 * Key insight: the minimum is at the start of the "right portion."
 * Compare mid to hi: if nums[mid] > nums[hi], the pivot (minimum) is in
 * the right half. Otherwise it is in the left half (including mid).
 *
 * Time: O(log n)   Space: O(1)
 */
function findMin(nums) {
  let lo = 0;
  let hi = nums.length - 1;

  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (nums[mid] > nums[hi]) {
      // Minimum is in the right half (mid is in the larger left portion)
      lo = mid + 1;
    } else {
      // Minimum is in the left half including mid
      hi = mid;
    }
  }
  return nums[lo]; // lo === hi, pointing at the minimum
}

console.log(findMin([3,4,5,1,2]));   // 1
console.log(findMin([4,5,6,7,0,1,2])); // 0
console.log(findMin([11,13,15,17])); // 11 (not rotated)
```

## Best Practices

- **Choose the right loop form**: `lo <= hi` for exact-match search; `lo < hi` for "find first/last position satisfying a condition."
- **Always update with `lo = mid + 1` or `hi = mid - 1` (Form 1)** or `lo = mid + 1` / `hi = mid` (Form 2) — never assign `lo = mid` or `hi = mid - 1` in Form 2, which causes infinite loops or incorrect results.
- **Use `lo + Math.floor((hi - lo) / 2)` for the midpoint** — it is overflow-safe and shows intent clearly.
- **Verify the feasibility check is monotonic** before applying "search on the answer." The predicate must have the form: false...false...true...true with a single boundary.
- **For rotated arrays, identify the sorted half first** — always check which side is sorted before deciding which side contains the target. The condition `nums[lo] <= nums[mid]` (with `<=` to handle duplicates) reliably identifies the sorted left half.
- **Set search bounds carefully for "search on answer"**: `lo` should be the minimum valid answer, `hi` the maximum valid answer. Off-by-one bounds give wrong results even with a correct binary search body.
- **Return `lo` (not `mid`) after the loop in Form 2** — when `lo === hi`, they both point to the answer. Returning `mid` at any point during the loop is wrong since `mid` is recalculated each iteration.

## Common Interview Questions

**Q1: What is the time complexity of binary search and why?**
A: O(log n). Each iteration halves the search space. After k iterations, the remaining space is n/2^k. This equals 1 when k = log₂(n).

**Q2: What is the difference between `lo <= hi` and `lo < hi` as the loop condition?**
A: `lo <= hi` exits when the range is empty (lo > hi), and is used for exact-match search where you return mid when found. `lo < hi` exits when lo = hi, pointing to the answer, and is used for "find the boundary" problems where you never exclude `mid` from the right side (`hi = mid`).

**Q3: How do you search for a target in a rotated sorted array?**
A: At every midpoint, one of the two halves is always fully sorted. Determine which half is sorted by comparing `nums[lo]` and `nums[mid]`. Check if the target falls in the sorted half; if yes, search there, otherwise search the other half.

**Q4: Explain "binary search on the answer" with an example.**
A: Instead of searching an array, you binary-search over the range of possible answers. For "minimize the maximum subarray sum," the answer lies between `max(nums)` and `sum(nums)`. For each candidate answer, run an O(n) feasibility check. The condition is monotonic (if `x` works, `x+1` works), so binary search finds the smallest valid answer in O(log(sum) × O(n)).

**Q5: What makes a problem suitable for binary search on the answer?**
A: The problem asks for a minimum or maximum value satisfying a condition, and that condition is monotonic: once it becomes true (or false) as the candidate increases, it stays that way. "Minimum days to make m bouquets," "minimum eating speed," "maximum tasks achievable" — all have this shape.

**Q6: How do you find the first occurrence of a target in a sorted array with duplicates?**
A: Use Form 2 (lo < hi). When `nums[mid] === target`, set `hi = mid` (don't exclude mid — it might be the first occurrence). When `nums[mid] < target`, set `lo = mid + 1`. Loop exits at the first occurrence (or where it would be if absent).

**Q7: How do you handle a sorted array with duplicates in binary search?**
A: For exact match, duplicates don't affect correctness — you'll land on one occurrence, not necessarily the first or last. For "find first/last occurrence," use the lower/upper bound form (Form 2) with appropriate comparison.

**Q8: Can you apply binary search to a 2D matrix? How?**
A: Yes, if the matrix is sorted (each row sorted, and each row's first element > previous row's last). Treat the matrix as a virtual 1D array of size m×n, mapping index `i` → `matrix[i / n][i % n]`. Standard binary search on this virtual array finds the target in O(log(m×n)).

## Practice Exercises

**Exercise 1 — First and Last Position (Beginner)**
Given a sorted array with duplicates and a target, find the first and last index where target appears. Return `[-1, -1]` if absent. Implement both using binary search (not linear scan). What form of the loop do you use and why?
Hint: Find the lower bound (first occurrence ≥ target) and upper bound (first occurrence > target, so last occurrence = upper bound - 1) using two binary search calls.

**Exercise 2 — Search Insert Position (Beginner)**
Given a sorted array without duplicates and a target value, return the index if the target is found, or the index where it would be inserted in order. This is exactly the lower bound operation. Implement it in O(log n) without using any built-in search methods.
Hint: This is Form 2 binary search. The answer is `lo` when the loop terminates.

**Exercise 3 — Capacity to Ship Packages (Intermediate)**
Packages arrive at a port with given weights. A ship carries at most `capacity` weight per day and must ship packages in order (no reordering). Find the minimum capacity to ship all packages within `D` days.
Verify: what are the correct `lo` and `hi` bounds? What does the feasibility check look like? This is identical in structure to the "split array" problem.
Hint: `lo = max(weights)` (can always ship the heaviest in one day), `hi = sum(weights)` (all in one day). Feasibility: simulate loading greedily.

**Exercise 4 — Find K Closest Elements (Intermediate)**
Given a sorted array and integers `k` and `x`, return the `k` closest elements to `x` as a sorted array. Ties are broken by choosing the smaller element. Solve this in O(log(n-k) + k) time using binary search to find the optimal left boundary of the k-element window.
Hint: Binary search for the leftmost starting position `left` such that `x - arr[left] <= arr[left+k] - x`. Then return `arr[left..left+k-1]`.

**Exercise 5 — Median of Two Sorted Arrays (Advanced)**
Given two sorted arrays of size m and n, find the median of the combined array in O(log(min(m,n))). This is a classic hard problem. The approach: binary search on the partition index in the smaller array. For each partition, verify that the left halves of both arrays combined form the lower half of the merged array.
Hint: Partition array A at index `i` and array B at index `(m+n)/2 - i`. The partition is valid when `A[i-1] <= B[j]` and `B[j-1] <= A[i]`. Binary search for the correct `i`.

## Key Takeaways

- Binary search is O(log n) because it halves the search space each iteration — 30 iterations cover 10⁹ elements.
- Use `lo <= hi` for exact match; use `lo < hi` for boundary-finding (first/last occurrence).
- Always compute midpoint as `lo + Math.floor((hi - lo) / 2)` — overflow-safe and canonical.
- In Form 2 (boundary finding): `hi = mid` never excludes the potential answer; `lo = mid + 1` excludes mid when it is provably not the answer.
- "Search on the answer": binary-search over the range of possible answer values; use an O(n) feasibility check at each midpoint.
- Feasibility check must be monotonic — once the predicate flips, it never flips back.
- Rotated sorted arrays: one half is always fully sorted; identify which half and check if the target is there.
- The bounds (`lo`, `hi`) for "search on the answer" must be set to the minimum and maximum possible valid answer, not arbitrary values.
