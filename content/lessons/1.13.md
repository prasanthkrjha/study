# Graphs

A graph is just nodes and edges — but a huge share of real problems (grids, dependency chains, social networks, word ladders) are graphs wearing a disguise. Recognizing "this is secretly a graph" is half the battle.

## BFS vs. DFS traversal

Both visit every reachable node exactly once (with a `visited` set), but explore in different orders:

```js
function bfs(graph, start) {
  const visited = new Set([start]);
  const queue = [start];
  const order = [];
  while (queue.length) {
    const node = queue.shift();
    order.push(node);
    for (const neighbor of graph[node]) {
      if (!visited.has(neighbor)) {
        visited.add(neighbor);
        queue.push(neighbor);
      }
    }
  }
  return order;
}

function dfs(graph, node, visited = new Set()) {
  visited.add(node);
  const order = [node];
  for (const neighbor of graph[node]) {
    if (!visited.has(neighbor)) order.push(...dfs(graph, neighbor, visited));
  }
  return order;
}
```

**Use BFS** when you need the **shortest path in an unweighted graph** — BFS explores level by level, so the first time you reach a node is guaranteed via the fewest edges. **Use DFS** when you just need to visit everything, detect cycles, or explore as deep as possible before backtracking (connected components, topological ordering groundwork).

## Connected components

Run BFS or DFS from every unvisited node; each run discovers one full component. Count how many times you had to start a fresh traversal — that's the number of components. This is the base pattern behind "number of islands," "number of provinces," and friend-circle problems.

## Cycle detection

- **Undirected graph:** during DFS, if you reach a node that's visited and isn't the immediate parent you came from, there's a cycle.
- **Directed graph:** track nodes currently "in progress" (on the current DFS call stack) separately from "fully finished." Reaching a node that's still in-progress means a cycle; reaching one that's finished is fine.

## Matrix-as-graph problems

A 2D grid is a graph where each cell is a node connected to its (usually 4) neighbors. "Number of islands," "rotting oranges," and "shortest path in a grid with obstacles" are all standard BFS/DFS, just with neighbors computed as `(r±1, c)` and `(r, c±1)` instead of an adjacency list.

```js
function numIslands(grid) {
  const rows = grid.length, cols = grid[0].length;
  let count = 0;
  function sink(r, c) {
    if (r < 0 || c < 0 || r >= rows || c >= cols || grid[r][c] !== "1") return;
    grid[r][c] = "0"; // mark visited in place
    sink(r + 1, c); sink(r - 1, c); sink(r, c + 1); sink(r, c - 1);
  }
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === "1") { count++; sink(r, c); }
    }
  }
  return count;
}
```

## Recognizing the pattern

Anything with "connections," "paths between," "islands," "shortest hops," or a dependency-like relationship is a graph problem. Grids are graphs. Rooms with doors are graphs. Word ladders (one word transforms to another by changing one letter) are graphs where words are nodes and an edge exists between words one letter apart.
