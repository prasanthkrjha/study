# Two Pointers

The two-pointer technique uses two indices — often called `left` and `right`, or `slow` and `fast` — that move through an array or string in a coordinated way. The goal is to avoid a nested loop: instead of checking every pair (i, j) in O(n²), you move both pointers based on a condition so that each pointer traverses at most n steps, giving O(n) total.

What makes two pointers work is **monotonicity**: once a pointer moves in one direction, it never needs to go back. In opposite-direction pointers, the array being sorted means that moving `left` right increases the sum and moving `right` left decreases it — so you can determine which pointer to move without reconsidering earlier positions. In same-direction pointers, the condition governing whether to advance `slow` is only evaluated when `fast` moves forward.

Two pointers is not a single algorithm — it is a design principle that manifests in many forms: opposite-direction for pair-sum problems, same-direction for in-place partitioning, and fast-slow for cycle detection in linked lists. The common thread is using pointer movement constraints to encode information that would otherwise require re-scanning.

## Theory & Fundamentals

### Why Sorting Enables Two Pointers

When an array is sorted, it has a **monotonic** property: moving left makes values smaller, moving right makes values larger. This means that if `nums[left] + nums[right]` is too large, you know `right` must move left (any other `right` position would be even larger or the same); if the sum is too small, `left` must move right. There is no ambiguity about which pointer to move, and no need to revisit positions.

This is why many two-pointer solutions start with `arr.sort()`. Sorting costs O(n log n), but it unlocks an O(n) two-pointer pass — the total is O(n log n), which is still far better than O(n²).

### The Two Main Shapes

**Opposite-direction**: start at both ends, converge inward.
```
[1, 2, 3, 4, 5, 6]
 L                R   → compare or combine L and R
    L           R     → one moves based on result
```

**Same-direction (slow/fast)**: `fast` always advances; `slow` advances only when it finds a valid element.
```
[3, 3, 2, 1, 3, 3, 1]
 S                       → slow marks the "write" position
 F  →→→→→→→→→→→→→→→    → fast scans ahead
```

### Pointer Invariants

Every two-pointer solution has an invariant — a condition that is always true about what the pointers represent. For example, in "remove duplicates from sorted array": `nums[0..slow]` is always a valid deduplicated prefix. Maintaining this invariant is what makes the algorithm correct. When debugging, ask "what invariant should each pointer maintain?"

## Core Patterns / Techniques

### Pattern 1: Pair Sum in Sorted Array (Opposite Direction)

```js
// Two Sum II: input array is already sorted (1-indexed return)
function twoSumSorted(numbers, target) {
  let left = 0;
  let right = numbers.length - 1;

  while (left < right) {
    const sum = numbers[left] + numbers[right];
    if (sum === target) return [left + 1, right + 1]; // 1-indexed
    if (sum < target) left++;   // need larger sum → move left pointer right
    else right--;               // need smaller sum → move right pointer left
  }
  return [];
}
// Time: O(n)  Space: O(1)
```

### Pattern 2: Palindrome / Symmetry Check

```js
// Valid Palindrome: alphanumeric characters only, case-insensitive
function isPalindrome(s) {
  // Helper: is character alphanumeric
  const isAlphaNum = c => /[a-zA-Z0-9]/.test(c);

  let left = 0;
  let right = s.length - 1;

  while (left < right) {
    // Skip non-alphanumeric from both ends
    while (left < right && !isAlphaNum(s[left])) left++;
    while (left < right && !isAlphaNum(s[right])) right--;

    if (s[left].toLowerCase() !== s[right].toLowerCase()) return false;
    left++;
    right--;
  }
  return true;
}
// Time: O(n)  Space: O(1)
```

### Pattern 3: In-Place Compaction (Same Direction)

```js
// Remove duplicates from sorted array in-place
// slow: index of the last confirmed unique element
// fast: scanning ahead for the next new unique element
function removeDuplicates(nums) {
  if (!nums.length) return 0;
  let slow = 0; // invariant: nums[0..slow] is deduplicated

  for (let fast = 1; fast < nums.length; fast++) {
    if (nums[fast] !== nums[slow]) {
      slow++;
      nums[slow] = nums[fast]; // extend the valid prefix
    }
    // if nums[fast] === nums[slow], skip it (do not advance slow)
  }
  return slow + 1; // length of deduplicated array
}
// Time: O(n)  Space: O(1) — in place
```

### Pattern 4: Dutch National Flag / Three-Way Partition

```js
// Sort an array containing only 0s, 1s, and 2s (no extra space)
// Three pointers: low, mid, high
function sortColors(nums) {
  let low = 0;        // everything left of low is 0
  let mid = 0;        // mid scans forward
  let high = nums.length - 1; // everything right of high is 2

  while (mid <= high) {
    if (nums[mid] === 0) {
      [nums[low], nums[mid]] = [nums[mid], nums[low]]; // swap 0 to front
      low++;
      mid++;
    } else if (nums[mid] === 2) {
      [nums[mid], nums[high]] = [nums[high], nums[mid]]; // swap 2 to back
      high--;
      // do NOT advance mid — the swapped-in value is unexamined
    } else {
      mid++; // 1 is in the right place
    }
  }
}
// Time: O(n)  Space: O(1) — single pass
```

### Pattern 5: Three Sum (Sort + Two Pointer)

```js
// Find all unique triplets summing to zero
function threeSum(nums) {
  nums.sort((a, b) => a - b); // O(n log n)
  const result = [];

  for (let i = 0; i < nums.length - 2; i++) {
    if (nums[i] > 0) break;             // sorted: no triplet can sum to 0
    if (i > 0 && nums[i] === nums[i-1]) continue; // skip duplicate firsts

    let left = i + 1;
    let right = nums.length - 1;

    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];
      if (sum === 0) {
        result.push([nums[i], nums[left], nums[right]]);
        while (left < right && nums[left] === nums[left+1]) left++;  // skip dups
        while (left < right && nums[right] === nums[right-1]) right--; // skip dups
        left++;
        right--;
      } else if (sum < 0) {
        left++;
      } else {
        right--;
      }
    }
  }
  return result;
}
// Time: O(n²)  Space: O(1) excluding output
```

## Code Examples

### Example 1: Container With Most Water

```js
/**
 * Given n vertical lines at positions 0..n-1 with heights height[i],
 * find the pair of lines forming the container that holds the most water.
 *
 * Key insight: area = min(height[L], height[R]) * (R - L)
 * Moving the pointer with the SHORTER line is the only way to possibly
 * increase the area (moving the taller one can only decrease width and
 * cannot increase the height constraint).
 *
 * Time: O(n)   Space: O(1)
 */
function maxArea(height) {
  let left = 0;
  let right = height.length - 1;
  let maxWater = 0;

  while (left < right) {
    // Current area: width × min height
    const width = right - left;
    const water = Math.min(height[left], height[right]) * width;
    maxWater = Math.max(maxWater, water);

    // Move the shorter line inward — the only move with upside potential
    if (height[left] <= height[right]) {
      left++;
    } else {
      right--;
    }
  }
  return maxWater;
}

console.log(maxArea([1,8,6,2,5,4,8,3,7])); // 49
console.log(maxArea([1,1]));                // 1
```

### Example 2: Minimum Window to Include All Characters

```js
/**
 * Given a string s and string t, find the minimum window substring of s
 * containing all characters of t. Same-direction two pointers (sliding window
 * variant) with a frequency map.
 *
 * Time: O(|s| + |t|)   Space: O(|t|)
 */
function minWindow(s, t) {
  if (!t.length) return '';

  // Build frequency requirement from t
  const need = new Map();
  for (const ch of t) need.set(ch, (need.get(ch) ?? 0) + 1);

  let have = 0;           // distinct chars satisfied in current window
  const required = need.size; // distinct chars we must satisfy

  const window = new Map();
  let best = '';
  let left = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    window.set(ch, (window.get(ch) ?? 0) + 1);

    // Check if adding ch satisfied one more required character
    if (need.has(ch) && window.get(ch) === need.get(ch)) {
      have++;
    }

    // Contract window from left while all requirements are met
    while (have === required) {
      const windowStr = s.slice(left, right + 1);
      if (!best || windowStr.length < best.length) best = windowStr;

      const leftCh = s[left];
      window.set(leftCh, window.get(leftCh) - 1);
      if (need.has(leftCh) && window.get(leftCh) < need.get(leftCh)) {
        have--;
      }
      left++;
    }
  }
  return best;
}

console.log(minWindow('ADOBECODEBANC', 'ABC')); // 'BANC'
console.log(minWindow('a', 'a'));               // 'a'
console.log(minWindow('a', 'aa'));              // ''
```

## Best Practices

- **Sort first when working with unsorted arrays** — sorting enables two pointers for pair/triplet problems and costs O(n log n), still cheaper than O(n²) brute force.
- **Define pointer invariants before coding** — write in a comment what `slow` and `fast` (or `left` and `right`) represent at all times. This prevents subtle off-by-one errors.
- **Skip duplicates explicitly in three-sum style problems** — after finding a valid pair, advance both pointers past any repeated values before continuing, or the result set will contain duplicates.
- **Never move both pointers simultaneously unless you've proven it's correct** — move one, evaluate the condition, then decide whether to move the other.
- **Prefer `left < right` over `left !== right`** — the `<` condition naturally handles the case where pointers cross without entering an invalid state.
- **Use the slow/fast pattern for in-place modification** — it avoids creating a new array and works in O(1) space.
- **Recognize when sorting would break the problem** — two-sum with index return (LeetCode #1) cannot sort the array because you need original indices. Sort only when you can afford to lose original positions or only need values.

## Common Interview Questions

**Q1: What is the time complexity of Two Sum if the input array is already sorted?**
A: O(n) — use opposite-direction two pointers instead of a hashmap. One linear scan with two pointers is sufficient.

**Q2: How does two pointers reduce Three Sum from O(n³) to O(n²)?**
A: Fix one element with an outer loop O(n), then reduce the remaining two-element problem to a sorted two-pointer scan O(n). Total: O(n) × O(n) = O(n²).

**Q3: In the "remove duplicates from sorted array" problem, why does `slow` not advance when `fast` sees a duplicate?**
A: `slow` marks the boundary of the valid deduplicated prefix. It only advances when a new unique value is found and written. Advancing it on duplicates would leave gaps or lose the invariant.

**Q4: Can you use two pointers on an unsorted array?**
A: Yes, but typically only for same-direction patterns (slow/fast) where the condition is not about sorted order. Opposite-direction two pointers for pair sums require sorted input to make the move decision unambiguous.

**Q5: How do you handle duplicate triplets in Three Sum?**
A: Sort the array first. For the outer loop, skip `nums[i]` if it equals `nums[i-1]` (only when `i > 0`). After finding a valid triplet, advance both inner pointers past their duplicates before continuing.

**Q6: What is the invariant in the Container With Most Water problem that justifies always moving the shorter line?**
A: Moving the taller line inward can only decrease width (losing area) without any chance of increasing the height constraint (the shorter line still limits area). Moving the shorter line is the only move that could possibly find a taller minimum in a narrower window, making it a larger area overall.

**Q7: How would you find the three-element subarray whose product is closest to a target?**
A: Sort, then fix one element and use two pointers on the rest — analogous to Three Sum but tracking the minimum absolute difference from target.

**Q8: What's the difference between two pointers and sliding window?**
A: Both use two indices. Two pointers usually refers to opposite-direction (converging) pointers or same-direction with distinct roles. Sliding window is a same-direction pattern where the window between `left` and `right` defines a contiguous subarray and both boundaries advance forward. The line between them is blurry — many sliding window solutions are also called two-pointer solutions.

## Practice Exercises

**Exercise 1 — Pair Difference (Beginner)**
Given a sorted array and a target value `k`, find if there exist two elements whose absolute difference equals `k`. Return the pair. Try both the brute-force O(n²) approach and the two-pointer O(n) approach. Why does sorting help here?
Hint: If the difference is too small, advance the left pointer. If too large, advance the right pointer.

**Exercise 2 — Remove Element In-Place (Beginner)**
Given an array `nums` and a value `val`, remove all occurrences of `val` in place and return the new length. The relative order of non-`val` elements does not need to be preserved. Use the slow/fast pointer pattern. Can you do it in O(n) time and O(1) space?
Hint: `slow` tracks where to write the next valid element. `fast` scans for non-`val` elements.

**Exercise 3 — Trapping Rain Water (Intermediate)**
Given an array of heights representing an elevation map, compute how much water it can trap after raining. The water above position `i` is `min(maxLeft, maxRight) - height[i]` where `maxLeft` and `maxRight` are the highest bars to the left and right. Try the O(n) space approach using two prefix-max arrays first, then optimize to O(1) space using two pointers.
Hint: With two pointers converging from both ends, the side with the smaller max determines how much water the current position holds.

**Exercise 4 — Four Sum (Intermediate-Advanced)**
Generalize Three Sum to Four Sum: find all unique quadruplets summing to a target. The expected time complexity is O(n³). Think about how to reuse the Three Sum pattern with an additional outer loop, and how to skip duplicates at each level.
Hint: Two nested outer loops (fixing two elements) + two-pointer inner scan for the remaining two.

**Exercise 5 — Minimum Pair Absolute Difference in BST (Advanced)**
Given a Binary Search Tree (BST), find the minimum absolute difference between values of any two nodes. The in-order traversal of a BST gives sorted values — use that property plus two-pointer thinking (comparing adjacent elements in sorted order) without materializing the full traversal array.
Hint: Maintain a `prev` pointer during in-order traversal. The minimum difference is among adjacent values in sorted order.

## Key Takeaways

- Two pointers replaces O(n²) nested loops with two coordinated index moves, achieving O(n) with O(1) extra space.
- Opposite-direction pointers require sorted input — sorting first costs O(n log n) but the total is still better than O(n²).
- Same-direction (slow/fast) pointers are used for in-place compaction, deduplication, and partitioning.
- The move decision must be unambiguous: for sorted arrays, the sum comparison tells you exactly which pointer to move.
- Define and maintain invariants — what does `slow` represent? What is always true about `left` and `right`?
- Three Sum = outer O(n) loop + two-pointer O(n) inner scan → O(n²) total.
- Always skip duplicates explicitly in problems that require unique output.
- Recognize the pattern: if you're writing `for i { for j { ... } }` over a sorted array, you likely have a two-pointer problem.
