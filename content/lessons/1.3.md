# Two Pointers

Two pointers replaces a nested loop with two indices that move through the array in a coordinated way — usually dropping an O(n²) brute force to O(n).

## Opposite-direction pointers

Used when the array is **sorted** and you're looking for a pair or checking symmetry. Start one pointer at each end and move them toward each other based on a comparison.

```js
function twoSumSorted(nums, target) {
  let left = 0, right = nums.length - 1;
  while (left < right) {
    const sum = nums[left] + nums[right];
    if (sum === target) return [left, right];
    if (sum < target) left++;   // need a bigger sum
    else right--;                // need a smaller sum
  }
  return [];
}
```

The classic **container with most water** and **valid palindrome** problems use this exact shape.

## Same-direction pointers (fast/slow within an array)

One pointer marks "where the next valid element should go," the other scans ahead. Used for in-place removal/dedup:

```js
function removeDuplicates(nums) {
  let slow = 0;
  for (let fast = 1; fast < nums.length; fast++) {
    if (nums[fast] !== nums[slow]) {
      slow++;
      nums[slow] = nums[fast];
    }
  }
  return slow + 1; // new length
}
```

## Sorted-array techniques

Sorting first (O(n log n)) often unlocks a two-pointer O(n) pass afterward — this combo shows up constantly for "3Sum," "merge two sorted arrays," and "closest pair" problems. The mental model: sorting gives you *monotonic* behavior, which is exactly what lets a pointer move only in one direction and never need to backtrack.

## Recognizing when to use it

- The array is sorted, or you can sort it without breaking the problem.
- You're looking for a pair/triplet satisfying a sum or difference condition.
- You need to partition or compact an array in place without extra space.

If you catch yourself writing `for i { for j { ... } }` over a sorted array, stop — it's very likely a two-pointer problem in disguise.
