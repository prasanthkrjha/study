# Arrays & Hashing

Arrays and hash-based data structures form the foundation of a huge fraction of interview problems. The central idea is simple but powerful: a hashmap or hashset lets you answer "have I seen this value before?" or "does a complement exist?" in O(1) time, replacing the O(n) scan you would otherwise need. When applied inside a loop, this turns O(n²) brute-force solutions into O(n) — a transformation so common that recognizing when to apply it is one of the highest-leverage skills you can develop.

The techniques in this unit — frequency counting, prefix sums, two-sum lookups, and grouping by a computed key — appear not just in standalone "easy" and "medium" problems but as sub-routines inside harder problems. Understanding them deeply here means you will naturally reach for the right tool when you see them embedded in a graph, tree, or dynamic-programming problem later.

The cost of these optimizations is always O(n) extra space. That is almost always an acceptable trade in practice, and interviewers generally consider it correct to use it. When asked to solve something "in constant space," that constraint will be stated explicitly — otherwise, assume a hashmap is fair game.

## Theory & Fundamentals

### How Hash Tables Work

A hashmap (also called a hash table or dictionary) stores key-value pairs. Internally, it maintains an array of buckets. When you insert a key, a hash function maps the key to a bucket index in O(1) time. Retrieval works the same way: hash the key, go to that bucket, return the value.

**Hash collisions** occur when two keys hash to the same bucket. Most implementations resolve this through chaining (a linked list at each bucket) or open addressing. In the average case with a good hash function, each operation is O(1). In the pathological worst case (all keys collide), operations degrade to O(n). JavaScript's `Map` and object literal `{}` both use hash tables internally.

```
Key "alice" ──hash()──→ bucket 3 ──→ { "alice": 42 }
Key "bob"   ──hash()──→ bucket 7 ──→ { "bob":   19 }
Key "carol" ──hash()──→ bucket 3 ──→ { "carol":  5 }  ← collision, chained
```

### HashMap vs. HashSet vs. Plain Object

- **`Map`**: keys can be any value (including objects, numbers). Preserves insertion order. Use when keys are non-string or when order matters.
- **`Set`**: stores unique values only. Use when you only need membership testing, not associated values.
- **Plain object `{}`**: keys are always strings (or symbols). Simpler syntax for string keys; slightly faster in V8 for string-keyed lookups in tight loops.

### Prefix Sums

A prefix sum array `pre` where `pre[i]` = sum of `arr[0..i-1]` lets you compute any range sum in O(1):

```
arr = [3, 1, 4, 1, 5, 9]
pre = [0, 3, 4, 8, 9, 14, 23]

sum(arr[1..3]) = pre[4] - pre[1] = 9 - 3 = 6  ✓
```

Build the prefix array in O(n) once, then answer any range query in O(1).

## Core Patterns / Techniques

### Pattern 1: Complement Lookup (Two-Sum)

Whenever you need to find two elements that together satisfy some condition (sum, difference, product), store what you've seen so far in a map. For each new element, check if its "partner" already exists.

```js
// Two Sum: find indices i, j such that nums[i] + nums[j] === target
function twoSum(nums, target) {
  const seen = new Map(); // value → index
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) {
      return [seen.get(complement), i];
    }
    seen.set(nums[i], i);
  }
  return [];
}
// Time: O(n)  Space: O(n)
```

The key insight: build the map **as you iterate** (not upfront), so you naturally avoid pairing an element with itself.

### Pattern 2: Frequency Counting

Any problem involving "most common element," "anagram detection," or "character counts" uses a frequency map.

```js
// Detect if two strings are anagrams
function isAnagram(a, b) {
  if (a.length !== b.length) return false;
  const freq = {};
  // Increment for each char in a
  for (const ch of a) freq[ch] = (freq[ch] ?? 0) + 1;
  // Decrement for each char in b
  for (const ch of b) {
    if (!freq[ch]) return false; // missing or count already 0
    freq[ch]--;
  }
  return true;
}
// Time: O(n)  Space: O(k) where k = alphabet size (26 for lowercase letters)
```

### Pattern 3: Grouping by Computed Key

Group items by a canonical form. The canonical form must be the same for all items in a group and different across groups.

```js
// Group anagrams: all words that are rearrangements of each other
function groupAnagrams(strs) {
  const groups = new Map();
  for (const s of strs) {
    // Sorted characters = canonical form for anagram groups
    const key = [...s].sort().join('');
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(s);
  }
  return [...groups.values()];
}
// Time: O(n · k log k) where k = avg word length
// Space: O(n · k)
```

Alternative canonical key for anagram grouping without sorting: a 26-element count array serialized as a string like `"2#0#1#..."`. This reduces the per-word cost to O(k) instead of O(k log k).

### Pattern 4: Prefix Sum with Hashmap

For problems asking "count subarrays that sum to k," combine running prefix sums with a hashmap that counts how many times each prefix sum has appeared.

```js
function subarraySumEqualsK(nums, k) {
  // Seed with {0: 1} — the empty prefix has sum 0
  const prefixCount = new Map([[0, 1]]);
  let runningSum = 0;
  let count = 0;

  for (const n of nums) {
    runningSum += n;
    // If (runningSum - k) appeared before, subarrays ending here sum to k
    count += prefixCount.get(runningSum - k) ?? 0;
    prefixCount.set(runningSum, (prefixCount.get(runningSum) ?? 0) + 1);
  }
  return count;
}
// Time: O(n)  Space: O(n)
```

### Pattern 5: Existence / Deduplication with Set

When you only need to know *if* a value was seen (not when or how many times), a Set is cleaner than a Map.

```js
// Longest consecutive sequence
function longestConsecutive(nums) {
  const numSet = new Set(nums);
  let best = 0;

  for (const n of numSet) {
    // Only start counting from the beginning of a sequence
    if (!numSet.has(n - 1)) {
      let len = 1;
      while (numSet.has(n + len)) len++;
      best = Math.max(best, len);
    }
  }
  return best;
}
// Time: O(n) — each number is visited at most twice
// Space: O(n)
```

## Code Examples

### Example 1: Top K Frequent Elements

```js
/**
 * Given an integer array, return the k most frequent elements.
 * 
 * Approach: frequency map + bucket sort by frequency
 * Time:  O(n)
 * Space: O(n)
 */
function topKFrequent(nums, k) {
  // Step 1: Build frequency map — O(n)
  const freq = new Map();
  for (const n of nums) {
    freq.set(n, (freq.get(n) ?? 0) + 1);
  }

  // Step 2: Bucket sort — index = frequency, value = list of nums with that freq
  // Maximum possible frequency is nums.length
  const buckets = Array.from({ length: nums.length + 1 }, () => []);
  for (const [num, count] of freq) {
    buckets[count].push(num);
  }

  // Step 3: Collect top k from highest-frequency buckets
  const result = [];
  for (let i = buckets.length - 1; i >= 0 && result.length < k; i--) {
    for (const num of buckets[i]) {
      result.push(num);
      if (result.length === k) break;
    }
  }
  return result;
}

// Test
console.log(topKFrequent([1,1,1,2,2,3], 2)); // [1, 2]
console.log(topKFrequent([1], 1));            // [1]
```

### Example 2: Range Sum Queries with Prefix Array

```js
/**
 * Design a data structure that answers range sum queries in O(1)
 * after O(n) preprocessing.
 * 
 * sumRange(i, j) returns sum of nums[i..j] inclusive.
 */
class NumArray {
  constructor(nums) {
    // prefix[i] = sum of nums[0..i-1]
    // prefix[0] = 0 (empty prefix)
    this.prefix = new Array(nums.length + 1).fill(0);
    for (let i = 0; i < nums.length; i++) {
      this.prefix[i + 1] = this.prefix[i] + nums[i];
    }
  }

  // O(1) query: subtract prefix sums to isolate range
  sumRange(left, right) {
    return this.prefix[right + 1] - this.prefix[left];
  }
}

// Verification
const na = new NumArray([-2, 0, 3, -5, 2, -1]);
console.log(na.sumRange(0, 2));  // 1  (-2 + 0 + 3)
console.log(na.sumRange(2, 5));  // -1 (3 + -5 + 2 + -1)
console.log(na.sumRange(0, 5));  // -3

// 2D extension: same idea, two prefix sum subtractions + one addition
// for sumRegion(r1, c1, r2, c2) on a matrix
```

## Best Practices

- **Reach for a hashmap before a nested loop** — the single most common optimization in interview problems is replacing an O(n) scan inside a loop with an O(1) hashmap lookup.
- **Seed the prefix sum map with `{0: 1}`** — forgetting to seed with the empty prefix is the most common bug in prefix-sum problems. It handles subarrays starting at index 0.
- **Use `Map` over plain objects for non-string keys** — plain objects coerce all keys to strings. `Map` preserves key types (numbers stay numbers), which prevents subtle bugs like `{1: 'a'}` where key `1` and key `"1"` collide.
- **Choose canonical keys carefully for grouping** — the canonical form must be deterministic and collision-free across groups. Sorted characters work for anagrams; rounded values may not work for floating-point grouping.
- **Prefer `??` over `||` for default values in frequency maps** — `freq[ch] || 0` fails if the count is legitimately `0` and you're checking a falsy value. Use `freq[ch] ?? 0` to safely handle explicit zero.
- **Size matters for the problem constraints** — for string problems with only lowercase letters, an array of 26 is more efficient than a map and makes the space O(1) relative to input size.
- **Track what the hashmap stores** — common options are value→index (two-sum), value→count (frequency), value→boolean (seen/unseen). Always be clear on what you're storing and why.

## Common Interview Questions

**Q1: What is the time complexity of checking if two strings are anagrams?**
A: O(n) where n is the string length, using a frequency array or map. Sorting both strings and comparing is O(n log n) — correct but suboptimal.

**Q2: Why does seeding the prefix sum map with `{0: 1}` matter?**
A: It accounts for subarrays that start at index 0. Without it, a subarray `nums[0..j]` that sums to `k` would not be counted because `runningSum - k = 0` would not be found in the map.

**Q3: How would you find the longest consecutive sequence of integers in an unsorted array in O(n)?**
A: Insert all numbers into a Set. Then iterate: for each number that has no predecessor (n-1 not in Set), count how long the consecutive chain starting at n is. Each number is processed at most twice → O(n).

**Q4: What is the difference between a Map and a Set in JavaScript?**
A: A `Map` stores key-value pairs and supports O(1) get/set/has. A `Set` stores unique values with O(1) add/has/delete. Use `Map` when you need to associate data with a key; use `Set` when you only need membership testing.

**Q5: Given an array, find if any value appears more than n/2 times (majority element). What's the most space-efficient approach?**
A: Boyer-Moore Voting Algorithm: maintain a candidate and a count. Increment count when you see the candidate, decrement when you don't; reset candidate when count hits 0. This is O(n) time and O(1) space. A hashmap approach also works in O(n) time but uses O(n) space.

**Q6: How do you count the number of subarrays with sum equal to k?**
A: Use prefix sums with a hashmap. Maintain a running sum; for each element, check if `runningSum - k` exists in the map (meaning there's a prefix that, when removed, leaves a subarray summing to k). This is O(n) time and O(n) space.

**Q7: When would you use an array of size 26 instead of a Map for character frequency counting?**
A: When the input is guaranteed to contain only lowercase English letters. An array of 26 integers is O(1) space (constant, not dependent on input size), while a Map is O(k) where k is the number of distinct characters. The array also has better cache locality and simpler code.

**Q8: How would you design a data structure that supports both insert and findMedian in O(log n)?**
A: Use two heaps: a max-heap for the lower half and a min-heap for the upper half. Keep them balanced (sizes differ by at most 1). Insert into the appropriate heap and rebalance — O(log n). Median is the top of the larger heap or average of both tops — O(1).

## Practice Exercises

**Exercise 1 — Two Sum Variants (Beginner)**
Solve Three Sum: given an array `nums`, return all unique triplets `[a, b, c]` such that `a + b + c = 0`. No duplicate triplets in the output. Think about how to reduce this to repeated Two Sum calls. What is the time complexity of your solution?
Hint: Sort first, then for each element fix it as the first of the triplet and use two pointers (or a set) to find the remaining two.

**Exercise 2 — Frequency Map Application (Beginner-Intermediate)**
Given an array of strings, find the word that appears most often. If there is a tie, return any one of the most frequent words. Then extend your solution to return the top-3 most frequent words. What data structure do you use, and what is the complexity of each approach?
Hint: Build a frequency map first. For top-3, consider a min-heap of size 3 or a partial sort.

**Exercise 3 — Prefix Sum Range Query (Intermediate)**
Given a 2D matrix of integers, precompute a structure so that any rectangular sub-region sum can be answered in O(1). The region is defined by its top-left (r1, c1) and bottom-right (r2, c2) corners. Derive the formula using the 2D prefix sum table and explain why inclusion-exclusion prevents double-counting.
Hint: `prefix[r][c]` = sum of all elements in the rectangle from (0,0) to (r-1, c-1). The range query formula involves four prefix values.

**Exercise 4 — Grouping with Custom Keys (Intermediate)**
Given a list of log entries in the format `"timestamp:username:action"`, group all actions by user. Then, within each user's group, find the most common action. Return a map from username to their most frequent action. Think carefully about your canonical key and what the hashmap stores at each level.
Hint: Split each log entry on `:` to extract fields. Use nested maps or a single map with composite keys.

**Exercise 5 — Subarray Problems (Advanced)**
Given an array of integers and an integer k, find the maximum length subarray that sums to exactly k. Then generalize: find the number of subarrays with sum divisible by k. For the second problem, think about what property of prefix sums (specifically, their remainders modulo k) tells you that two prefix sums differ by a multiple of k.
Hint: For the second problem, if `pre[i] % k === pre[j] % k`, then `sum(arr[i+1..j])` is divisible by k. Store remainder → count in a map.

## Key Takeaways

- The core trade: use O(n) extra memory for a hashmap to reduce O(n²) brute-force time to O(n).
- `Map.get()`, `Map.set()`, `Map.has()`, `Set.has()`, `Set.add()` are all O(1) average — this is what makes the time reduction possible.
- Frequency maps count occurrences; complement maps store what you've seen for O(1) partner lookup; prefix sum maps count valid subarrays.
- Always seed prefix sum maps with `{0: 1}` to correctly handle subarrays starting at index 0.
- Grouping problems share a structure: compute a canonical key per item, then `map[key].push(item)`.
- Two-sum is a template that extends to three-sum, four-sum, and difference-based problems by reducing one variable at a time.
- `Map` preserves key types; plain objects coerce all keys to strings. Use `Map` for correctness with numeric or object keys.
- These patterns recur as sub-routines in nearly every subsequent topic — hashing inside graph problems, prefix sums inside DP, frequency maps inside sliding window.
