# Embeddings & Vector Search

Embeddings are the mathematical foundation on which semantic search, RAG systems, recommendation engines, and many other ML features are built. The key insight is deceptively simple: a neural network can be trained so that the distance between two vectors in high-dimensional space reflects the semantic similarity between the corresponding texts. Once text exists as a vector, the rich toolkit of linear algebra — dot products, cosine similarity, nearest-neighbor search — becomes applicable to questions about meaning.

Understanding embeddings at the level of how they are generated, what makes two vectors "close," and how vector databases make retrieval efficient at scale is what lets you make informed decisions in RAG system design, debug retrieval failures, and discuss trade-offs between dense and sparse retrieval with technical credibility.

This unit covers the concepts and practical tools: from cosine similarity computed from scratch to using FAISS for approximate nearest-neighbor search to the design trade-offs between different embedding models. Everything here feeds directly into the RAG pipeline in Unit 8.3.

## Theory & Fundamentals

**How embeddings encode meaning**: An embedding model is a neural network (typically a Transformer encoder like BERT, or a bi-encoder like E5/GTE) trained with a contrastive objective: pairs of semantically similar texts are pulled together in the vector space; dissimilar pairs are pushed apart. The resulting vectors encode semantic relationships: synonyms land nearby; antonyms are somewhat distant; words from the same domain cluster. This learned geometry is what makes the arithmetic analogy `king - man + woman ≈ queen` work — it is not magic, it is the spatial structure imposed by training on text co-occurrence patterns.

**Dense vs. sparse representations**: Dense embeddings are short, continuous vectors (e.g. 768 or 1536 floats) where every dimension carries distributed signal. Sparse representations (TF-IDF, BM25) are high-dimensional vectors where most values are zero — only terms present in the document have nonzero weights. Dense vectors capture semantic meaning (synonym matching); sparse vectors capture lexical presence (exact term matching). They are complementary, not competing.

**Cosine similarity vs. dot product**: Cosine similarity normalizes for vector magnitude — it measures the angle between two vectors, not their length. This makes it robust to differences in document length (a longer document's embedding has a larger magnitude but similarity should not increase just because it is longer). Dot product (unnormalized) is faster to compute and used internally by most vector databases; for unit-normalized vectors, cosine similarity and dot product are numerically equivalent.

**Approximate Nearest Neighbor (ANN) search**: Exact nearest-neighbor search requires comparing a query vector to every stored vector — O(n) per query, impractical at millions of vectors. ANN algorithms build an index that allows sub-linear retrieval by organizing vectors into a navigable structure. HNSW (Hierarchical Navigable Small World) graphs are the dominant algorithm — they trade a small accuracy loss (not guaranteed to find the absolute nearest neighbor) for orders-of-magnitude speed improvement. FAISS (Facebook AI Similarity Search) is the most widely used library implementing multiple ANN algorithms.

**Embedding model selection criteria**: Dimension count (more dimensions → more expressive but more storage and slower retrieval). Context window of the embedding model (constrains chunk size in RAG). Domain coverage (general-purpose models may underperform on specialized vocabulary). Speed and cost (API-based vs. self-hosted). MTEB (Massive Text Embedding Benchmark) is the standard leaderboard for comparing models across retrieval, classification, and clustering tasks.

## Core Concepts / Techniques

**Computing cosine similarity from scratch**:
```python
import numpy as np

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    """Cosine similarity between two 1-D vectors. Returns value in [-1, 1]."""
    norm_a = np.linalg.norm(a)
    norm_b = np.linalg.norm(b)
    if norm_a == 0 or norm_b == 0:
        return 0.0
    return float(np.dot(a, b) / (norm_a * norm_b))

def batch_cosine_similarity(query: np.ndarray,
                             corpus: np.ndarray) -> np.ndarray:
    """Cosine similarity of one query against N corpus vectors. O(N·D)."""
    # corpus shape: (N, D); query shape: (D,)
    query_norm  = query / (np.linalg.norm(query) + 1e-9)
    corpus_norm = corpus / (np.linalg.norm(corpus, axis=1, keepdims=True) + 1e-9)
    return corpus_norm @ query_norm   # shape: (N,)
```

**Generating embeddings with the OpenAI API**:
```python
from openai import OpenAI
import numpy as np

client = OpenAI()

def embed(texts: list[str], model: str = "text-embedding-3-small") -> np.ndarray:
    """Embed a list of texts. Returns (N, D) float32 array."""
    response = client.embeddings.create(model=model, input=texts)
    vectors  = [item.embedding for item in response.data]
    return np.array(vectors, dtype=np.float32)

# Single text
q_vec = embed(["What is the capital of France?"])[0]  # (1536,)

# Batch (more efficient — one API call for all texts)
docs = [
    "Paris is the capital of France.",
    "The Eiffel Tower is located in Paris.",
    "London is the capital of the United Kingdom.",
    "Python is a programming language.",
]
doc_vecs = embed(docs)   # (4, 1536)

# Rank documents by similarity to the query
sims = batch_cosine_similarity(q_vec, doc_vecs)
ranked = sorted(zip(sims, docs), reverse=True)
for score, doc in ranked:
    print(f"{score:.4f}  {doc}")
```

**FAISS for large-scale ANN search**:
```python
import faiss
import numpy as np

def build_faiss_index(vectors: np.ndarray, use_gpu: bool = False) -> faiss.Index:
    """
    Build a flat L2 index (exact search) for small datasets.
    For >100k vectors, switch to IndexIVFFlat or HNSW for speed.
    """
    dim = vectors.shape[1]
    index = faiss.IndexFlatIP(dim)    # Inner Product (= cosine for unit vectors)
    # Normalize for cosine similarity
    faiss.normalize_L2(vectors)
    index.add(vectors)
    return index

def search(index: faiss.Index, query: np.ndarray,
           k: int = 5) -> tuple[np.ndarray, np.ndarray]:
    """Return top-k (scores, indices) for a query vector."""
    query_copy = query.copy().reshape(1, -1).astype(np.float32)
    faiss.normalize_L2(query_copy)
    scores, indices = index.search(query_copy, k)
    return scores[0], indices[0]
```

## Code Examples

```python
"""
Complete semantic search system:
embed a document corpus, build a FAISS index,
run queries, and implement hybrid dense + sparse search.
"""
import numpy as np
import faiss
import json
from pathlib import Path
from openai import OpenAI
from sklearn.feature_extraction.text import TfidfVectorizer
from scipy.sparse import csr_matrix

client = OpenAI()

# ─── 1. Corpus ────────────────────────────────────────────────────────────────
DOCS = [
    "Python is a high-level programming language emphasizing readability.",
    "FAISS is a library for efficient similarity search over dense vectors.",
    "RAG combines document retrieval with language model generation.",
    "Cosine similarity measures the angle between two vectors in space.",
    "Transformers use self-attention to model sequence relationships.",
    "Docker containerizes applications with their dependencies.",
    "PostgreSQL is an open-source relational database management system.",
    "Embeddings map text to dense vectors encoding semantic meaning.",
    "LLMs are large neural networks trained on internet-scale text corpora.",
    "BM25 is a sparse keyword-based retrieval algorithm used in search engines.",
]

# ─── 2. Embed and Index ───────────────────────────────────────────────────────
cache_file = Path("embeddings_cache.json")

if cache_file.exists():
    # Load cached embeddings to avoid redundant API calls
    cached = json.loads(cache_file.read_text())
    doc_vecs = np.array(cached["vectors"], dtype=np.float32)
else:
    response = client.embeddings.create(
        model="text-embedding-3-small", input=DOCS
    )
    doc_vecs = np.array(
        [item.embedding for item in response.data], dtype=np.float32
    )
    cache_file.write_text(json.dumps({
        "model": "text-embedding-3-small",
        "vectors": doc_vecs.tolist(),
    }))
    print(f"Embedded {len(DOCS)} documents. Shape: {doc_vecs.shape}")

# Build FAISS index (L2 = cosine after L2 normalization)
dim   = doc_vecs.shape[1]
index = faiss.IndexFlatIP(dim)
normalized = doc_vecs.copy()
faiss.normalize_L2(normalized)
index.add(normalized)
print(f"FAISS index: {index.ntotal} vectors, dim={dim}")

# ─── 3. Dense (semantic) retrieval ────────────────────────────────────────────
def dense_search(query: str, k: int = 3) -> list[dict]:
    q_resp = client.embeddings.create(
        model="text-embedding-3-small", input=[query]
    )
    q_vec = np.array([q_resp.data[0].embedding], dtype=np.float32)
    faiss.normalize_L2(q_vec)
    scores, indices = index.search(q_vec, k)
    return [
        {"doc": DOCS[i], "score": float(s), "method": "dense"}
        for s, i in zip(scores[0], indices[0]) if i >= 0
    ]

# ─── 4. Sparse (BM25-style) retrieval via TF-IDF ─────────────────────────────
tfidf = TfidfVectorizer(stop_words="english", ngram_range=(1, 2))
doc_tfidf = tfidf.fit_transform(DOCS)  # sparse matrix (n_docs, vocab_size)

def sparse_search(query: str, k: int = 3) -> list[dict]:
    q_vec = tfidf.transform([query])        # sparse (1, vocab_size)
    scores = (doc_tfidf @ q_vec.T).toarray().flatten()
    top_k  = np.argsort(scores)[::-1][:k]
    return [
        {"doc": DOCS[i], "score": float(scores[i]), "method": "sparse"}
        for i in top_k if scores[i] > 0
    ]

# ─── 5. Hybrid retrieval (Reciprocal Rank Fusion) ────────────────────────────
def rrf_score(rank: int, k: int = 60) -> float:
    """Reciprocal rank fusion — rank 1 = best."""
    return 1.0 / (k + rank)

def hybrid_search(query: str, top_k: int = 3) -> list[dict]:
    dense_results  = dense_search(query,  k=5)
    sparse_results = sparse_search(query, k=5)

    # Build per-document RRF scores
    rrf: dict[str, float] = {}
    for rank, result in enumerate(dense_results):
        rrf[result["doc"]] = rrf.get(result["doc"], 0) + rrf_score(rank + 1)
    for rank, result in enumerate(sparse_results):
        rrf[result["doc"]] = rrf.get(result["doc"], 0) + rrf_score(rank + 1)

    ranked = sorted(rrf.items(), key=lambda x: x[1], reverse=True)
    return [{"doc": doc, "rrf_score": score, "method": "hybrid"}
            for doc, score in ranked[:top_k]]

# ─── 6. Compare retrieval strategies ─────────────────────────────────────────
queries = [
    "How do vectors capture semantic meaning?",  # semantic query
    "BM25 algorithm",                             # exact-term query
    "PostgreSQL database",                        # mixed
]

for q in queries:
    print(f"\nQuery: {q!r}")
    print("  Dense:", [r["doc"][:50] for r in dense_search(q, k=2)])
    print("  Sparse:", [r["doc"][:50] for r in sparse_search(q, k=2)])
    print("  Hybrid:", [r["doc"][:50] for r in hybrid_search(q, top_k=2)])
```

## Best Practices

- **Cache embeddings aggressively.** Embedding a corpus is expensive (API cost) and deterministic — the same text always produces the same embedding for a given model. Cache to disk or a KV store and recompute only when the corpus or model changes.
- **Normalize vectors before storing and before querying** if you are using dot product as your similarity metric. This makes dot product equivalent to cosine similarity, avoiding length-biased retrieval (longer documents embedding to larger-magnitude vectors).
- **Use hybrid search (dense + sparse) in production.** Dense-only search misses exact terminology; sparse-only misses paraphrases. Reciprocal Rank Fusion (RRF) is a simple, effective fusion method that requires no tuning of weighting parameters.
- **Match embedding model to chunk size.** Most embedding models have a context window (e.g. 512 tokens for many BERT-based models, 8192 for newer ones). A chunk longer than the model's context is silently truncated — the excess content is not encoded. Verify your chunk sizes against your embedding model's documented limit.
- **Do not embed raw HTML or markdown with metadata intact.** Strip markup before embedding — the embedding model should see clean semantic content, not structural syntax that dilutes the meaning signal.
- **Evaluate retrieval quality with labeled queries.** Create 20-50 test queries with known relevant documents. Measure Recall@k and MRR (Mean Reciprocal Rank) on your retrieval system, not just on end-to-end generation quality.
- **Choose embedding dimension based on dataset size.** A 1536-dimensional embedding for a 500-document corpus wastes compute and storage. Smaller models with lower dimensions are often sufficient for small corpora and measurably faster at query time.

## Common Interview Questions

**Q: What is a word embedding and how is it different from a sentence embedding?**
A: A word embedding (e.g. Word2Vec, GloVe) maps individual tokens to vectors based on co-occurrence statistics. A sentence embedding maps an entire sentence (or passage) to a single vector representing its overall meaning, typically produced by a Transformer encoder that aggregates token representations through pooling or a [CLS] token. Sentence embeddings are what you use in RAG; word embeddings are mostly superseded for retrieval tasks.

**Q: What is cosine similarity and why is it used instead of Euclidean distance?**
A: Cosine similarity measures the angle between two vectors, ignoring their magnitudes. Euclidean distance measures their absolute separation in space. For text embeddings, cosine similarity is preferred because it is length-invariant — a longer document embedding has a larger magnitude, which would make it appear "closer" to many queries under Euclidean distance even if the content is unrelated. Cosine normalizes this away.

**Q: What is the difference between dense and sparse retrieval?**
A: Dense retrieval uses continuous embedding vectors to find semantically similar documents — it can match synonyms and paraphrases even with no shared words. Sparse retrieval (BM25, TF-IDF) uses term frequency to find documents sharing exact or near-exact terms with the query — it is precise for specific terminology, product codes, and named entities. Dense misses exact terms; sparse misses semantic paraphrases. Hybrid search combines both.

**Q: What is FAISS and what problem does it solve?**
A: FAISS (Facebook AI Similarity Search) is a library for efficient similarity search over large collections of dense vectors. It solves the scalability problem: comparing a query vector to millions of stored vectors one-by-one (exact search) is O(n) per query. FAISS builds an index (HNSW, IVF) enabling approximate nearest-neighbor search in sub-linear time, trading a small accuracy loss for orders-of-magnitude speed improvement.

**Q: How do you evaluate embedding quality for a retrieval task?**
A: With labeled test queries. For each query, annotate which documents are relevant. Compute Recall@k (fraction of relevant documents in the top-k results) and MRR (mean reciprocal rank of the first relevant result). Run these metrics against your embedding model and retrieval configuration, and compare them when you change chunk size, embedding model, or retrieval strategy.

**Q: What is Reciprocal Rank Fusion (RRF)?**
A: RRF merges results from multiple ranked lists (e.g. dense and sparse retrieval) without needing to tune a weighting parameter. Each document gets a score of 1/(k + rank) for each list it appears in; scores are summed across lists. RRF is robust, parameter-free, and empirically performs well for hybrid search — it is the standard baseline for combining retrieval signals.

**Q: What does "embedding dimension" mean, and how do you choose it?**
A: Embedding dimension is the number of floats in each embedding vector. More dimensions can encode more nuanced relationships but cost more memory, more storage, and more computation per similarity comparison. Choose dimension based on: the complexity and diversity of the corpus (larger corpora benefit from higher dimensions), the model's available dimensions (some models offer matryoshka embeddings — truncatable at various dimensions), and latency/cost constraints.

## Key Takeaways

- Embeddings are dense vector representations where semantic similarity in text corresponds to geometric proximity in the vector space.
- Cosine similarity (angle between vectors) is the standard metric for text embeddings because it is magnitude-invariant and thus length-robust.
- Dense retrieval captures semantic meaning; sparse retrieval captures exact term matching. Production RAG systems typically use both — hybrid search with RRF is the standard default.
- Normalizing vectors before indexing makes dot product equivalent to cosine similarity — important when using FAISS's IndexFlatIP.
- FAISS and similar ANN libraries solve the scalability problem: exact search is O(n), ANN search is sub-linear at the cost of a small, tunable accuracy trade-off.
- Cache embeddings — they are expensive to generate and deterministic. Recompute only when the corpus or model changes.
- Evaluate retrieval with labeled queries and recall@k / MRR metrics — do not rely solely on generation quality to assess retrieval correctness.
- Chunk size must respect the embedding model's context window, or content will be silently truncated before encoding.
